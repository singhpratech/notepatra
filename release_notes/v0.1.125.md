# Notepatra v0.1.125

**A one-word MCP search could return the contents of your SSH private key. That is fixed, along with three other defects found by testing the MCP server on Windows — and the Windows binary finally reports its real version number after 124 releases claiming 0.1.0.**

This release is entirely about the MCP sidecar and the Windows build. There are no new editor features; every change below is a fix.

## The credential leak

`read_file` refused to open `~/.ssh/id_rsa`. `search_project` returned its matching lines.

Both consulted a deny-list of credential paths — but there were **two** copies of that list, maintained by hand in different files, and they had drifted in *both* directions:

| List | Had | Missing |
|---|---|---|
| `ai_tools.cpp` | `*.tfvars`, `*.tfstate`, `.pypirc`, `.env` family, `authorized_keys` | `*.jks`, unanchored `id_rsa` |
| `git_hunk_apply.cpp` | `*.jks`, unanchored `id_rsa` | everything in the row above |

Neither was a superset of the other, so each caller enforced a different policy — and `search_project`, the third caller, consulted **neither**. It walked the tree with no credential filter at all.

`src/path_denylist.h` is now the single list, built as the **union** of both, with all three callers routed through it. The regression test caught exactly `keystore.jks` — the extension only the `git_hunk_apply` copy had ever known about — which is the proof that taking the union mattered rather than picking a winner.

## `search_project` walked your entire home directory

`FileExplorer`'s constructor set `m_rootPath = QDir::homePath()` as a **display placeholder** — something to show in an empty sidebar. Four separate guards then read that value as "the workspace the user is working in", including the AI CSV sandbox and a security guard that had therefore never once closed.

The consequence: with no folder open, an MCP search recursed through `$HOME`. Display root and workspace root are now different questions, and `workspaceRoot()` stays **empty** until you actually open a folder. With no workspace, `search_project` searches open tabs only and says so — the response carries `workspace_searched` and `scope` so a client can never mistake a partial search for a complete one.

Fixing this properly meant `MainWindow` growing four accessors where it had one, because "what folder is the user working on" genuinely has four different right answers: scoping (empty means refuse), the first open file's directory, the folder a save dialog should suggest (may fall back broadly — you see and edit it), and the AI session root (sticky, so it does not change under a running conversation). An earlier attempt collapsed them back into "folder, else current file's directory", which resolves to `$HOME` the moment one file in `$HOME` is open, and made the AI root flap on every Ctrl+Tab — swapping chat history and cancelling pending write approvals mid-flight.

## `goto_line` past end-of-file lied

Scintilla rejects an out-of-range position and leaves the cursor at the **top** of the document. The response still read `{"line": 99999, "ok": true}`.

Because `insert_text` defaults to the cursor, an assistant aiming at the end of a file wrote at the **beginning** — behind an approval card that looked correct. `Editor::gotoLine` now clamps and returns where it actually landed; the verb reports `line`, `requested_line` and `clamped`.

## `insert_text` silently relocated writes

Passing `col` without `line` dropped `col` and wrote at the cursor. Silently moving a write is the one failure an approval gate cannot protect you from — you approve the text, not the destination. It is now an error.

## The sidecar hung on every bad argument

`notepatra-mcp` is a stdio server: with no arguments it blocks reading stdin, which is correct when a client launched it and looks exactly like a crash when a human runs it in a terminal. Every unrecognised argument fell into that loop.

- `--version` printed nothing and hung
- `--sokcet` silently started the **mock** server, so the client received fabricated tabs that looked like a real editor
- a mistyped subcommand like `sevre` hung the same way

All now exit 2 with a message naming what you typed.

## Windows: the version resource

Every Windows build ever shipped reported **0.1.0** to winget, SCCM, Intune and File Properties → Details, regardless of what it actually was — the `.rc` carried a hardcoded `0,1,0,0`. It is generated from `project(Notepatra VERSION …)` now, so there is exactly one place the version is written, and CI reads `VersionInfo.FileVersion` back off the shipped `.exe` and fails the build on a mismatch.

The gate is not advisory — it exits non-zero on a mismatch, so a Windows build
carrying the wrong version cannot be published. Its first run, on the commit
that introduced it, read back:

```
CMakeLists version  : 0.1.124
expected FileVersion: 0.1.124.0
actual   FileVersion: 0.1.124.0
OK: PE version resource matches the project version
```

## Testing

76 C++ suites and 91 Rust tests locally; 73 suites and 192 Rust assertions on Windows, including a real `QLocalServer` round-trip and the named-pipe integration test.

Every new test was **red-state verified by restoring the pre-fix code**, not by negating a condition. That distinction earned its keep: a hand-written sabotage of `search_project` still produced the correct answer, which made a sound test look weak until the real pre-fix control flow was put back. The failure signatures then matched the original Windows bug reports exactly — `{"line": 99999, "clamped": false}`, `workspace_searched: true` with no workspace open, and "leaked contents of keystore.jks".

## Upgrading

Drop-in. No configuration or data migration is required.

One note if you use the AI panel: chat history is keyed by workspace root, and this release stops `$HOME` from being treated as a workspace. Existing history is **copied** forward from the old key rather than moved, so nothing is lost either way.
