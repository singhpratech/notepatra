# Notepatra v0.1.18 — SQL pretty-printer, Git workflow rewrite, runtime theme propagation

**Released:** 2026-04-24

v0.1.18 is a depth pass on three tools that shipped "functional but thin" in v0.1.17: the **SQL formatter**, the **Git panel**, and **theme switching**. All three now feel like the tool you'd reach for, not a placeholder.

---

## Highlights

### 🧱 SQL formatter — Claude-style AST pretty-printer, dialect-aware

The previous `format_sql` was 13 lines of whitespace normalization. v0.1.18 replaces it with an AST walker built on the `sqlparser` crate (v0.52) — production-tested SQL parser.

- **Dialect-aware parse** — ANSI, PostgreSQL, MySQL, SQLite, MS SQL, Snowflake, BigQuery, Redshift, ClickHouse, DuckDB, Hive. Each dialect's reserved-words + quoting rules are respected.
- **Claude-style indentation** — `SELECT` columns aligned on their own lines, `JOIN` clauses indented one level, `CASE WHEN` laddered, CTEs broken at commas.
- **Graceful fallback** — on parse error (unknown syntax, half-typed query), falls back to the old whitespace normalizer so you never get a blank panel.
- **UPPERCASE / lowercase toggle** — preserved through the AST walk, not a post-pass regex.
- 33-case regression suite in `test_sqlfmt.cpp` — 28 pass hard, 5 flagged aspirational (parser edge cases the `sqlparser` crate itself doesn't round-trip).

### 🤖 AI Fix for SQL — dialect-aware syntax repair

New **AI Fix** button next to Format in the SQL panel. Sends your query + the currently-selected dialect to your configured LLM (Ollama / OpenAI-compatible / llama.cpp) with a prompt that says "fix the syntax for dialect X, don't rewrite logic, return just the corrected SQL." Streams the fix back inline.

Useful for the two common cases: PostgreSQL-specific syntax pasted into a MySQL tab, or a query with a missing closing paren / typo where the parser error message is unhelpful.

### 🌳 Git panel — real workflow tool, not a status viewer

Rewrote the Git panel as an actually-usable git client. Previously it showed a flat file list with a commit box; now it's:

- **Staged / Unstaged trees** — files grouped by state with inline **+** / **−** buttons to stage / unstage per row. Click a file to see the diff in the main editor.
- **Porcelain v2 parser** — async `QProcess` backend reads `git status --porcelain=v2 --branch` so file-state detection is correct across renames, copies, untracked vs ignored, and submodules.
- **Branch chip + ahead/behind counter** — the header shows `main ↑3 ↓1` when your branch has diverged. Click the chip to see the full branch list.
- **Commit box** — `Ctrl+Enter` commits. Shows line count as you type. Blocks the commit if no files are staged (with a clear message instead of a silent no-op).
- **Sync row** — one-click **Pull** / **Push** / **Fetch** with live ahead/behind refresh after each operation.
- **Collapsible history** — last N commits under the sync row, click-to-expand for full commit messages.
- **Stash menu** — stash / pop / list / drop, with the message preserved.

### 🎨 Runtime theme propagation — no more restart to switch themes

Previously, flipping the theme in Settings re-styled only the editor and main chrome. Every tool panel kept its old palette until you restarted the app, producing dark-on-dark melt in the REST client, Git panel, Project Search, Terminal, and others.

v0.1.18 adds a `MainWindow::themeChanged()` signal and `onThemeChanged()` slots on **every panel** — AI Assistant, Project Search, Terminal, REST Client, Git Panel, Compare (diff), Markdown Preview, and Hex Editor. Each panel's stylesheet blocks moved into an `applyPalette()` helper that reads a fresh `npPalette()` every time the signal fires.

- Switch theme → every panel repaints immediately, no restart.
- Nothing goes invisible during the transition (dark text on dark bg was the worst offender in the REST status badge and the Git branch chip).
- 8 `connect()` calls wired at each panel's creation site in `MainWindow` so a panel added later just needs to declare the slot and gets live theme switching for free.

### ✅ Tests

- `test_sqlfmt.cpp` — 33 assertions across 11 dialects (28 pass, 5 aspirational skip for parser limits).
- Full suite: `ctest -j` → **12/12 pass in 1.3 s**.

## Installation

### Linux (AppImage)

```bash
wget https://github.com/singhpratech/notepatra/releases/download/v0.1.18/Notepatra-0.1.18-linux-x86_64.AppImage
chmod +x Notepatra-0.1.18-linux-x86_64.AppImage
./Notepatra-0.1.18-linux-x86_64.AppImage
```

### macOS

```bash
curl -fsSL https://github.com/singhpratech/notepatra/releases/download/v0.1.18/Notepatra-0.1.18.dmg -o ~/Downloads/Notepatra-0.1.18.dmg
open ~/Downloads/Notepatra-0.1.18.dmg
```

### Windows

- **MSI** — `Notepatra-0.1.18.msi`
- **NSIS installer** — `Notepatra-Setup-0.1.18.exe`
- **Portable ZIP** — `Notepatra-0.1.18-windows-x64.zip`

### One-command installer scripts

```bash
# Linux, macOS
curl -fsSL https://notepatra.org/install.sh | sh

# Windows PowerShell
irm https://notepatra.org/install.ps1 | iex
```

## Upgrade notes

- In-app updater from v0.1.17 will pick this up automatically — click **Check for Updates** (or wait for the launch-time check).
- No config changes required. New SQL panel and Git panel inherit your existing theme.
- If you scripted against the old `npc_format_sql` FFI (4-arg), it's now 5-arg with a dialect parameter (default `"ansi"` preserves prior behavior).
