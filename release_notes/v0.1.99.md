# Notepatra v0.1.99 — Noter sidebar renders light on macOS

**Release date:** 2026-05-25

A macOS-only visual fix: the Noter sidebar tree (Notes / Reminders / Trash) rendered on a **dark background** while the rest of the panel — search box, "+ Noter" button, editor — stayed light. Noter worked fine; it just looked broken. v0.1.99 pins the sidebar tree to the intended light colour on every platform.

---

## What was wrong

On macOS, the Noter sidebar list sat on a black background with light text, clashing with the light "paper" panel around it. (Linux and Windows were unaffected — their default palette base is light, so the bug never showed there.)

## Root cause

The sidebar migrated from a `QListWidget` to a `QTreeWidget` a few releases back, but the panel stylesheet still carried the **old** `QListWidget#noterMeetingList` rules and never got a rule for the new `QTreeWidget#noterSidebarTree`. A Qt item-view paints its **viewport** from its own palette `Base` role — the parent panel's `background` does not reach it — so an unstyled tree falls through to the system base, which on macOS is dark.

## The fix

`src/notes.cpp`:

1. **Stylesheet** — replaced the dead `QListWidget#noterMeetingList` rules with `QTreeWidget#noterSidebarTree` rules: light `#f3f1ea` background, dark item text, hover highlight, amber selection.
2. **Palette fallback** — pinned the tree's `QPalette::Base` / `Text` in code as belt-and-braces, so the viewport stays light even on a style that bypasses the stylesheet selector.
3. The disclosure arrows are left to the native style (styling `::branch` would have removed them) — on the now-light background they render normally.

| Surface | Before v0.1.99 (macOS) | After v0.1.99 |
|---|---|---|
| Sidebar tree background | dark / system base | light `#f3f1ea` (matches the panel) |
| Notes / Reminders / Trash text | light-on-dark | dark-on-light, readable |
| Folder / clock / trash icons | washed out on black | clear on light |
