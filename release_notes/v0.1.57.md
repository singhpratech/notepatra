## 🪟 Windows mojibake — every emoji and special char fixed

Every emoji in the UI was rendering as garbage on Windows: 📊 → `ðŸ"š`, 🔒 → `ðŸ""`, 📌 → `ðŸ"Œ`, … → `â€¦`, ≈ → `â‰ˆ`, · → `Â·`. The Data Analyst card, the Share-file lock, the welcome icons, the model-recommendation banner — all affected.

**Root cause:** MSVC reads C++ source as the system code page (Windows-1252 on en-US) by default, so UTF-8 byte sequences get decoded as Latin-1 at compile time. Linux + macOS use UTF-8 so they were unaffected.

**Fix:** `add_compile_options(/utf-8)` for MSVC in CMakeLists. Single flag, fixes every emoji + accented character + Unicode arrow in the codebase. No source edits needed.

## 🧠 Coding mode revamp — Composer tab + multi-file Edit Plan + per-hunk apply

Slices A → F shipped together: a separate **Composer** tab joins *Chat* in the AI dock when Coding Mode is on. The Composer keeps its own scrollback, its own input, and surfaces the **Edit Plan** — a list of every file the model wants to change in this turn.

- Each Edit Plan entry shows the file path + a unified diff preview with **per-hunk Accept / Reject checkboxes**.
- Action bar at the bottom: *Apply All* / *Apply Selected* / *Reject All* — no more all-or-nothing diffs.
- Coding mode **auto-expands the AI dock to fullscreen** the moment you flip the switch (and restores the previous width when you switch back to Chat / Data Mode) so the diff preview has room to breathe.
- Composer talks to the model with a `dry_run:true` system layer — `write_file` and `apply_diff` come back as proposed-edit payloads that route to the Edit Plan instead of touching disk directly.

New widgets: `EditPlanList`, `DiffView` (side-by-side, line-tinted via the Rust `similar` crate).

## 📎 `@file` mention picker — workspace context, one keystroke

Type `@` in the chat input and a **workspace-files popup** appears with fuzzy-matched results from the project tree.

- Selected files are **prepended to the prompt as context** — the model sees real file content, not paths.
- Useful for *"@auth.py @user.py refactor the session helper"* without manually pasting.
- Backed by a `QCompleter` over the workspace file index.

## ⌨️ Ctrl+I inline edit — selection in, replacement out

Select code in the editor → **Ctrl+I** opens a small modal asking *"what should this become?"*.

- Type the change in plain English.
- The AI returns the replacement with a **side-by-side diff**.
- *Apply* replaces the selection in place; *Cancel* keeps the original.
- Works against whatever backend / model you have selected — local or cloud.

New `InlineEditDialog` (QDialog) wired into the editor's keymap; reuses the existing `OllamaClient` configured from `Config::instance()`.

## 🌿 Agentic git tools (read-only) — the AI can read your repo state

Five new tools wired into the agentic loop:

- `git_status` · `git_diff` · `git_log` · `git_branch_list` · `git_show`

**Read-only by design** — no writes, no resets, no force-push paths. The model can answer *"what's my git status?"* / *"what changed since yesterday?"* / *"show me the diff on branch foo"* by calling these autonomously, no shell-out and no copy-paste.

Implemented as a `GitTools` namespace with `QProcess` + 5 s timeout per call, hardcoded verb argv (no mutation), path-safety on cwd, and `git_show` commit-arg sanitization to refuse anything that isn't a `[A-Fa-f0-9]{4,40}` hex SHA.

## 🎯 Multi-cursor editing — Alt+drag, Ctrl+click, type once

- **Alt+drag** for column-select rectangles
- **Ctrl+click** to add a cursor at any caret position
- Type once and the same edit lands at every selection simultaneously
- Works with the existing find-all-occurrences and bracket-match flows
- Esc collapses to a single caret

Wired through QScintilla: `SCI_SETMULTIPLESELECTION`, `SCI_SETADDITIONALSELECTIONTYPING`, `SCI_SETMULTIPASTE = SC_MULTIPASTE_EACH`, `SCI_SETRECTANGULARSELECTIONMODIFIER = SCMOD_ALT`, `SCI_SETADDITIONALSELALPHA = 90`.

## 🎨 Mode-aware model dropdown coloring

The model dropdown now **colors entries by capability per active mode**:

- In **Coding mode**, models without tool-calling render in <span style="color:#E67E22">amber</span> with a hover tooltip explaining why.
- In **Data mode**, models that lack the recommended Data-Analyst capability surface render amber the same way.
- Tool-capable / Data-capable models stay accented in green.

The signal is purely visual — you can still pick any model; the color tells you what to expect.

## 💬 Chat input auto-grows for multi-line messages

Bottom message box now expands as you type multi-line content (40 px → 140 px max), driven by the document's actual rendered height — visually-wrapped long lines also trigger the grow, not just Enter-separated paragraphs (the previous bug used `blockCount()`). Auto-collapses to 40 px the moment the input is cleared after Send.
