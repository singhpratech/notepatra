# Notepatra v0.1.71 — AI Interaction Log

Released: 2026-05-11

This release lands the audit log the user asked for: every request and
response sent to a cloud or local LLM is recorded into a small SQLite
database so you can inspect exactly what went where.

## What's new

### AI Interaction Log (`Tools → AI Interaction Log…`)

Every cloud (OpenRouter, OpenAI, Azure OpenAI, Ollama Cloud) and local
(Ollama, llama.cpp, LM Studio / Jan / vLLM via OpenAI-compat) call is
recorded into `~/.config/notepatra/ai-logs/interactions.db`. The
schema captures:

- timestamp, session id (one per app launch)
- backend tag, model name, mode (`chat` / `coding` / `data`)
- role (`user`, `system`, `assistant`, `tool_call`, `tool_result`)
- full content, tool name / args / result, prompt + eval tokens,
  elapsed ms, error string on failure

Storage is SQLite in WAL mode so writes never block the GUI; total
file size capped at 50 MB and rows older than 7 days are pruned on
every app start.

### Viewer dialog

`Tools → AI Interaction Log…` opens a read-only audit dialog:

- Backend / mode / model filters
- Table view (timestamp, backend, model, mode, role, preview,
  tokens/elapsed) — click a row for full content in the bottom panel
- **Export JSON** — pulls up to 10,000 events into a single
  pretty-printed JSON file you can keep offline or pipe into other
  audit tooling.
- **Prune now** — runs the 7-day cleanup on demand.
- **Toggle "Log AI interactions"** — flips
  `Config::aiInteractionLogging` directly from the dialog so you
  don't have to dig into Settings.

### Privacy + safety

- **Default ON.** Privacy-as-transparency: by default Notepatra
  records what it sends so you can see for yourself. Toggle off
  anywhere (Tools dialog or `Config::aiInteractionLogging = false`)
  and the recorder becomes a no-op — the database file isn't even
  opened.
- **Credential scrubbing.** Every value written to the DB is run
  through a regex pass that masks Bearer tokens, OpenAI `sk-`,
  Anthropic `sk-ant-`, GitHub PATs (`ghp_/ghs_/gho_/ghu_/ghr_`),
  AWS access keys (`AKIA…`), Google API keys (`AIza…`), and
  `-----BEGIN ... PRIVATE KEY-----` blocks. The log can NEVER
  become a new credential-exfil path.
- **No network egress.** The log is purely local SQLite — Notepatra
  never uploads, mirrors, or syncs it.

## How it's wired

- New module: `src/ai_interaction_log.{h,cpp}` (~280 LoC). Public
  API: `record(Event)`, `recordUser`, `recordAssistant`,
  `recordToolCall`, `recordToolResult`, `recordError`, `query(Filter)`,
  `pruneOld`, `setEnabled`, `isEnabled`, `databasePath`.
- New viewer: `src/ai_log_dialog.{h,cpp}` (~250 LoC). Plain Qt
  widgets — `QTableWidget`, `QPlainTextEdit`, `QSplitter`. No new
  dependencies.
- `OllamaClient::generate()` records:
  1. The outgoing user message (and system prompt when first emitted).
  2. The assistant completion at every `responseStats` emit site —
     Ollama `/api/generate` + `/api/chat` done frame, OpenAI-compat
     `[DONE]` frame, OpenAI-compat `finish_reason` frame. Each path
     resolves the backend tag from the base URL
     (`openai.azure.com` → `azure-openai`, `api.openai.com` →
     `openai`, etc.).
- `OllamaClient::setMode("chat"|"coding"|"data")` lets AIPanel tag
  each turn with the mode for filter purposes; cheap setter, no
  protocol impact.
- `MainWindow::checkCrashRecovery()` → ahead of `restoreSession()`
  the constructor now calls `AiInteractionLog::pruneOld()`.

## Tests + verification

- `cmake --build . --target notepatra` builds clean on the lite
  configuration (no new compile warnings).
- Live-tested by sending a Data-mode question to local Ollama; the
  row appeared in the dialog immediately with token + elapsed
  fields populated.
- Disabled the toggle, sent another turn, confirmed no row
  appeared; re-enabled and the next turn recorded again.

## Notes for upgraders

- First launch on v0.1.71 creates the SQLite db and indexes; ~50 ms
  one-time cost.
- The `aiInteractionLogging` Config field is missing from older
  config.json files and defaults to true — existing installs opt
  in by default. Flip off in the dialog if you'd rather not.
