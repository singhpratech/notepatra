# Notepatra v0.1.64 — Lite mode by default (bare binary + on-demand Charts Pack)

**Date:** 2026-05-10
**Tag:** `v0.1.64`
**Build:** Linux x64 / Linux ARM64 / macOS Apple Silicon / Windows x64 — plus new `linux-x64-full` / `linux-arm64-full` flavors with QtWebEngine bundled

The big architectural shift: Notepatra is now **lite by default**. Every install starts at ~9 MB. Heavy features — first up the Vega-Lite chart renderer — become optional packs you grab when you actually need them. Same philosophy as DuckDB extensions: tiny core, expand on demand.

---

## Why

v0.1.63 bundled QtWebEngine into every release (~95 MB extra on macOS/Windows). That was the wrong shape: most users will never trigger a chart, but every install paid the price. We flipped the default and built the upgrade path users actually need.

---

## What changed

### Lite-mode default

`CMakeLists.txt` flips `NOTEPATRA_WITH_WEBENGINE` from `ON` to `OFF`. The default binary:

- **No QtWebEngine link** — `ldd` shows zero WebEngine deps
- **9.2 MB on Linux x64** (down from ~95 MB with WebEngine bundled)
- Same speed, same features, minus the inline chart renderer

To get charts back: download the new `-full` artifact (Linux today, macOS / Windows in v0.1.65) or build from source with `-DNOTEPATRA_WITH_WEBENGINE=ON`.

### New "Charts Pack required" card

When a Data Analyst prompt triggers `generate_chart` and the user is on a lite binary, instead of the old confusing "rebuild with `-DNOTEPATRA_WITH_WEBENGINE=ON`" stub label they now see:

```
┌──────────────────────────────────────────────────────────────┐
│  📊  Chart rendering requires the Charts Pack                │
│                                                              │
│  Renders Vega-Lite charts (bar / line / scatter / area /     │
│  composite) inline in the chat transcript. Powered by        │
│  QtWebEngine + vega-embed.                                   │
│                                                              │
│  ≈ 95 MB · One-time download · Auto-installs on first use    │
│                                                              │
│  [ Install charts pack ]   [ View JSON instead ]             │
└──────────────────────────────────────────────────────────────┘
```

- **[Install charts pack]** opens a modal explaining the two flavors, then routes the user's default browser to the GitHub Releases page for the current tag with platform-specific download instructions.
- **[View JSON instead]** appends the Vega-Lite spec as a fenced code block under the card — users can copy it into a standalone Vega-Lite editor without installing anything.

Theme-aware: pulls colors from `QPalette` so it respects Light / Dark / Monokai / custom themes without hard-coded greys.

### New `src/plugin_loader` scaffolding

`NotepatraPlugins::isInstalled(name)`, `installPath(name)`, `pluginDir()`, `packDescription(name)`, `approximateDownloadSize(name)`, `manualInstallDocUrl(name)`. v0.1.64 returns build-time-static answers (charts pack "installed" iff `NOTEPATRA_WITH_WEBENGINE=1`); v0.1.65 layers in real on-disk detection + SHA-256-verified manifests.

Currently registered packs:

| ID | Description | Approx size | Status |
|---|---|---|---|
| `charts` | Vega-Lite renderer (QtWebEngine + vega-embed) | 95 MB | bundled in `-full` build |
| `pdf` | Poppler-Qt5 PDF→PNG for vision models | 12 MB | v0.1.66 candidate |

### CI now publishes both flavors for Linux

`.github/workflows/build.yml` runs a second build pass in each Linux job:

- `notepatra-linux-x64.tar.gz` — lite (default download)
- `notepatra-linux-x64-full.tar.gz` — bundles QtWebEngine
- `notepatra-linux-arm64.tar.gz` — lite
- `notepatra-linux-arm64-full.tar.gz` — bundles QtWebEngine

Both flavors get SHA-256, cosign signatures, and SLSA build provenance.

### Test coverage

`test_vega_chart.cpp` extended with two new subcases:

1. **Lite-mode button → signal wiring** — finds the two `QPushButton`s in the card, clicks each programmatically, asserts `installRequested()` and `viewJsonRequested(spec)` fire exactly once with the round-tripped spec.
2. **plugin_loader sanity** — verifies `isInstalled("charts")` reflects the build-time flag, unknown pack names return false (no throw), `approximateDownloadSize` returns > 0, doc URLs are non-empty.

Plus updated assertion in the existing setSpec subcase: lite-mode `setSpec()` must NOT emit `renderError` anymore (missing Charts Pack is a feature-gap, not an error condition).

All 25 tests pass on the lite build.

## What ships in v0.1.65 (next)

- **macOS full flavor** in CI (the existing `macdeployqt` + `install_name_tool` + signing pipeline needs a second pass with WebEngine frameworks)
- **Windows full flavor** in CI (`windeployqt` second pass for WebEngine DLLs)
- **In-app HTTP-download install** — the [Install charts pack] button currently routes through the browser; v0.1.65 streams the pack into `~/.local/share/notepatra/plugins/charts/` directly, with SHA-256 verification and a Qt plugin shim so the main binary can dlopen the WebEngine wrapper at runtime without re-linking

---

## Upgrading from v0.1.63

Same as always — replace the binary. Your config, chat history, and connections live outside the binary.

If you were using charts in v0.1.63, you now have two options:

- **Wait for v0.1.65** — full flavor for your platform ships soon
- **Build from source today** — `cmake .. -DNOTEPATRA_WITH_WEBENGINE=ON && make` works exactly like v0.1.63
