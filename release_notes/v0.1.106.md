# Notepatra v0.1.106

**A reliability + security hardening release: a session-restore fix that could clobber the wrong file, credential-scrubbing on the AI tool-result channel, a stored-XSS fix in chart HTML export, a wider secret-file deny-list, a memory-safety fix in the Rust core, and a large-file memory guard.** Every change in this release hardens a code path that already shipped — there are no new features behind it.

## Why this release

These are the battle-readiness ship-blockers found during a robustness + security pass, several of which were surfaced or sharpened by an adversarial audit. They are independent of (and shipped ahead of) the in-progress Data-Analyst work, which stays deferred.

## The fixes

### Reliability

1. **Session restore could write unsaved content to the wrong file** (`mainwindow.cpp`). `restoreSession()` assumed `openFile()` always appended a tab. When a restored tab pointed at a file that *exists but is unreadable* (permissions, replaced by a directory) or was already open in an earlier-restored tab, `openFile()` early-returned without adding a tab — so `editorAt(count()-1)` aliased the **previous** restored editor. The modified branch then overwrote that prior tab's buffer and marked it modified, and a later Save clobbered the wrong file on disk. Fixed by capturing the tab count before the call and only reusing the appended editor if the count grew; otherwise the unsaved content lands in a fresh untitled tab so nothing is destroyed.

2. **Large-file memory guard** (`config.h`, `editor.cpp`, `preferences.cpp`). Opening a file pulls it fully into RAM. There's now a soft memory budget (**Preferences → Editing → Large files**, default 2 GB): opening a larger file asks for confirmation first instead of risking an out-of-memory stall on a low-RAM machine. It's a soft ceiling — you can always proceed, or raise the limit.

### Security

3. **Credential-scrubbing on the AI tool-result channel** (`aipanel.cpp`). The v0.1.55 CredScrub redacted credentials on the prompt-build path, but the tool-result channel bypassed it: `read_file(".env")`, `search`, `git_diff`, and `git_show` bodies were forwarded **verbatim** to the (possibly cloud) backend on the next round. The same `CredScrub::redact()` now runs over those content-bearing tool results before they are queued. Structured write-tool results are left untouched so the next round can still parse them.

4. **Wider secret-file deny-list** (`ai_tools.cpp`). `isHardDenied()` — which blocks the agent's `read_file` before it reads — now also covers the dotenv family (`.env`, `.env.local`, `.env.production`, and the `<name>.env` / `*.env.*` convention such as `app.env` / `database.env`), `secrets.json`, and Terraform `*.tfvars` / `*.tfstate` (which routinely hold provider credentials and plaintext resource secrets).

5. **Stored-XSS in chart HTML export** (`charts/vega_chart_renderer.cpp`). Exporting a chart to standalone HTML embedded the serialized Vega-Lite spec inside a `<script>` block. A model-emitted value containing `</script><script>…` would break out and execute when the file was opened via `file://`. The serialized spec is now escaped (`<`, `>`, `&`, U+2028, U+2029 → `\uXXXX`) before embedding — still valid JSON, no live `</script>` — on **both** the WebEngine and the default (lite) export paths. The in-app render path was never affected.

6. **Edit-apply path could write outside the workspace** (`aipanel.cpp`). The dry-run `write_file` / `apply_diff` preview queued the workspace-*relative* path, which resolved against the process CWD (`$HOME` on a normal launch) at Apply time — misplacing edits and potentially clobbering `$HOME` files. It now queues the absolute target path, and `applyComposerEdits()` refuses any non-absolute path outright (re-anchoring it under the workspace with the same deny-list safety as the write tools).

### Memory safety

7. **Interior-NUL heap over-read in the Rust core** (`rust-core/src/lib.rs`). `text_to_result` returned a `CString`, which truncates at the first interior NUL while still reporting the original length — so a text op whose output legitimately contains a NUL (e.g. **Tools → Base64 Decode** of `QUJDAEVGRw==` → `b"ABC\0EFG"`) made the C++ side read past the allocation. It now hands back the raw UTF-8 bytes as a `Box<[u8]>` + explicit length, freed by the matching `npc_free_text_result`. Same fix pattern as the v0.1.87 file-load path.

## Out of scope

- **Read-only SQL gate hardening** — a token-aware rewrite of the `query_sql` read-only gate was prepared but **held**. An adversarial audit found that a string/token-based gate is structurally unable to catch side-effecting functions (`SELECT setval(...)`, `read_csv('/etc/passwd')`, `OPENROWSET`/`dblink`), MySQL executable comments (`/*! … */`), and `EXPLAIN ANALYZE`, and that an over-broad mutation-keyword scan wrongly rejected legitimate reads (`SELECT REPLACE(...)`, a `comment` column, T-SQL `[set]`). The correct fix is connection/transaction-level read-only enforcement (e.g. `SET TRANSACTION READ ONLY`, `PRAGMA query_only`, a read-only DB role) with the string gate as defense-in-depth — that's a dedicated follow-up. The currently-shipped prefix check is unchanged by this release.
- **Data-Analyst feature** — the compact-DDL schema context and the Data-mode prompt learnings stay deferred to a later version, gated on the model-evaluation pass.
