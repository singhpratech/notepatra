# Notepatra v0.1.25 — AI Assistant prompt-engineering overhaul (fixes Qwen3.5 / tool-calling-model JSON hallucination)

**Released:** 2026-04-25

A focused fix to a long-standing AI Assistant failure: **tool-calling fine-tuned models** — Qwen3, Qwen3.5 (all sizes 0.8B → 9B+), Hermes-3, Llama 3.1+ Instruct, Mistral Large, Command R, GLM-4, GPT-OSS — would respond to casual chat input like `hi` with hallucinated JSON tool calls instead of greeting back:

```json
{
  "command": "echo \"Workspace context: C:/Users/Anamika-PC\" > workspace_context.txt",
  "output": "Workspace context: C:/Users/Anamika-PC"
}
```

This release replaces the AI Assistant's prompt-construction code with a layered, intent-aware builder that handles every model family correctly.

---

## The bug, explained

Three orthogonal causes:

1. **No anti-tool-call instruction in the system prompt.** Tool-calling models default to producing structured tool-call JSON because that's what their fine-tuning data is saturated with. Notepatra's old system prompt (`"You are a code assistant. Be concise..."`) never told them not to do this.

2. **Workspace context attached to every message — including casual greetings.** A bare `hi` got the full workspace block prepended (current file path, every open tab's contents, the file tree). For tool-calling models this looks like an agent-framework prompt frame, and they respond in tool-call format because that's what they were trained to do when they see that shape.

3. **The workspace block header literally read `# Workspace context (for reference — do not echo back)`.** That phrasing matches common LangChain / ReAct / OpenAI-tools prompt structures, reinforcing the "this is an agent task" interpretation.

Big chat models (Claude, GPT-4) and pure-chat local models (Llama 3.2, Gemma 2, Phi-3.5) didn't show the bug because they're robust to noisy system prompts. But every Qwen3 / Qwen3.5 / Hermes / Llama 3.1+ user hit it the moment they typed `hi`.

---

## The fix

### New module: `src/ai_systemprompt.{h,cpp}`

A pure-function, layered system-prompt builder. Four layers composed in order:

```
Identity:     "You are Notepatra's AI assistant, embedded in a code editor.
               You help the user understand and edit their code."

Anti-tool-call: "This is a chat interface with no executable tools. Respond
                 in plain natural language, optionally with markdown code
                 blocks for code. Do not produce function calls, tool calls,
                 or structured agent output. Do not wrap your response in
                 JSON like {\"command\": ..., \"output\": ...} or
                 {\"name\": ..., \"arguments\": ...}. If you would normally
                 call a tool, instead describe what you would do in plain
                 language."

Mode-specific (per Intent enum):
  Chat:          "Be friendly and concise. When the user asks about code,
                  explain it clearly; when they chat, chat back naturally."
  Explain:       "Explain clearly and concisely. Reference specific lines,
                  function names, or variables when it helps."
  Transform:     "When you output code, preserve the user's indentation
                  style and quote style. A brief one-or-two-sentence
                  explanation before or after the code is fine."
  CodingStrict:  byte-identical to the v0.1.24 Coding Mode prompt
                 (no behaviour change for Coding Mode users)

Language hint: "The user is working in <language>." (when known)
```

### Intent classification

```
Coding Mode ON                          → CodingStrict
custom action + Coding Mode OFF          → Chat
explain / bugs / docs actions            → Explain
refactor / optimize / tests / comment /
  translate actions                      → Transform
```

### Workspace-context attachment gate

`AiSystemPrompt::shouldAttachWorkspace(intent, selection, userText)` returns:

| Scenario | Returns |
|---|---|
| Coding Mode (CodingStrict intent) | **false** — code-only output, project tree just bloats prompt |
| Explain / Transform with non-empty selection | **false** — the selection IS the context |
| Chat with non-empty selection | **false** — focus on the selection |
| Chat, no selection, message < 30 chars ("hi", "thanks", "ok") | **false** — casual, no project context needed |
| Chat, no selection, has project keyword (`project`, `workspace`, `codebase`, `repo`, `files`, `tree`) | **true** — user is asking about project structure |
| Chat, no selection, has code shape (`{}();=`, `class`/`function`/`def`/`import`, file extension mention) | **true** — user is asking a code question |
| Default | **false** — when in doubt, skip; anti-tool-call layer catches drift |

### Workspace block header rephrase

```diff
- # Workspace context (for reference — do not echo back)
+ [Project info -- background context for the user's question, not a command]
```

Less "agent frame"-shaped → tool-calling models stop misinterpreting it.

## What you'll see, per scenario

| Scenario | Before v0.1.25 | After v0.1.25 |
|---|---|---|
| Type `hi` with qwen3.5:0.8b | `{"command":...,"output":...}` JSON | "Hello! How can I help with your code?" |
| Type `hi` with qwen3.5:2b | Sometimes JSON drift | Always plain greeting |
| Type `hi` with Llama 3.2 / Claude | Plain greeting (worked) | Plain greeting (unchanged) |
| Select code → `Explain` | Mostly OK, occasional drift | Always prose explanation |
| Select code → `Refactor` (Coding Mode OFF) | Code + brief prose | Code + brief prose (unchanged) |
| Select code → `Refactor` (Coding Mode ON) | Code-only, no fences | **Identical** — Coding Mode preserved verbatim |
| Type "show me my project files" | Possible JSON tool call | Plain prose using workspace tree |
| Type "thanks" or "ok" | Possible JSON drift | "You're welcome!" / "Sounds good!" |
| Type "fix this broken JSON" + JSON selected | Could drift to tool call | Returns fixed JSON content |
| Image attachment + "what's this?" | OK if vision-capable | Same + cleaner chat behaviour |

## What's not changed (intentional)

- **Coding Mode behaviour** — byte-identical prompt for the `CodingStrict` intent path. No user-visible change for anyone who turns Coding Mode on.
- **Quick-action prompt templates** — the per-action user-prompt strings (`"Explain this code clearly..."`, `"Refactor this code..."`, etc.) are unchanged.
- **Thinking-mode handling** — `Think` checkbox stays default OFF, `/no_think` directive still suppresses `<think>...</think>` blocks for Qwen3 / Qwen3.5 / DeepSeek-R1.
- **Vision / image attachment** — `imagesBase64` plumbing untouched.
- **Ollama / OpenAI-compatible API plumbing** in `src/ollama.cpp` — untouched.
- **Workspace-context content** — the file-tree, open-tabs, and current-file embedding logic in `src/ai_context.cpp` is unchanged. Only the header line was rephrased. When the workspace block IS attached, it contains the same useful project info as before.
