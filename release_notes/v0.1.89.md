# Notepatra v0.1.89

**Save As detail view now shows a "Date Created" column — last piece of the v0.1.88 dialog UX request.**

## What changed

v0.1.88 shipped the Save As dialog UX baseline (960×640 geometry, Detail view default, sort by Date Modified descending) but the user-requested **Date Created** column was deferred — the proxy-model approach I first tried crashed Qt's tree view on Ctrl+S. v0.1.89 ships the column via the supported pattern: a `QIdentityProxyModel` subclass that adds one extra column on top of `QFileDialog`'s internal `QFileSystemModel`.

## The fix

`src/savedialogfsmodel.h/cpp` (NEW) — `SaveDialogDateCreatedProxy`, an identity proxy that:

1. **Reports `columnCount() = source + 1`** so the tree view paints 5 columns instead of 4.
2. **Overrides `index(row, extraCol, parent)`** to return a `createIndex()` whose `internalPointer()` is borrowed from source column 0 — so when the view dereferences the extra-column index, it lands on a real `QFileInfo`. This is the bit my v0.1.88 attempt got wrong: a hand-rolled `QSortFilterProxyModel` returned an index with no source mapping, and the next paint cycle dereferenced garbage → SIGSEGV on Ctrl+S.
3. **Overrides `mapToSource()`** to map the extra column to source column 0 (same row, same `internalPointer()`), so Qt's model APIs that traverse from the proxy index back to the file system can succeed.
4. **Overrides `data(extraCol, DisplayRole)`** to return `QFileInfo::birthTime()`, with `metadataChangeTime()` (ctime) fallback for filesystems that don't store birth time, and a final em-dash so the cell never crashes.
5. **Overrides `headerData(extraCol, Horizontal, DisplayRole)`** to return `"Date Created"`.

`src/mainwindow.cpp` — `configureSaveDialogUx()` now calls `dialog.setProxyModel(new SaveDialogDateCreatedProxy(&dialog))` before sizing the tree view. Same wiring applied to both `saveFileAs()` AND the close-tab "Save before close?" prompt — UX is consistent everywhere we use Save As.

## Linux ext4 gotcha

`QFileInfo::birthTime()` uses `statx()` under the hood and needs ext4 with kernel ≥ 4.11. On ext3 / FAT / older kernels it returns an invalid `QDateTime`. The fallback chain:

```
birthTime() → if invalid → metadataChangeTime() (ctime)
            → if still invalid → "—" (em-dash, never crash)
```

On a modern ext4 system the column shows real dates; on a USB-mounted FAT volume it shows ctime; on truly clueless filesystems it shows the em-dash.

## Why a proxy and not a QFileSystemModel subclass

`QFileDialog` builds its OWN `QFileSystemModel` internally — you can't swap it out via any public API. The supported extension point is `setProxyModel()` which wraps that internal model. Subclassing `QFileSystemModel` and trying to `tv->setModel()` would break the dialog's path-bar, file-name editing, and selection wiring that's hard-coded to the d-pointer's model. Identity-proxy + extra-column overrides is the canonical Qt pattern for this.
