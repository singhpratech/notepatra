# Notepatra v0.1.63 — Data Analyst charts (Vega-Lite scaffold)

**Date:** 2026-05-10
**Tag:** `v0.1.63`
**Build:** Linux x64 / Linux ARM64 / macOS Apple Silicon / Windows x64

The first cut of inline chart rendering in Data Analyst mode. The AI emits a Vega-Lite spec via the new `generate_chart` tool; Notepatra renders it inline in the chat via a `QWebEngineView`-backed widget. Built on top of the v0.1.63 chart-library evaluation that picked Vega-Lite over Plotly / Chart.js / Qt Charts / QCustomPlot.

---

## What changed

### `generate_chart` AI tool

`src/ai_tools.cpp` registers a new `generate_chart` tool:

```jsonc
{
  "name": "generate_chart",
  "parameters": {
    "spec":  "<Vega-Lite JSON object — required>",
    "title": "<optional plain-text title>",
    "id":    "<optional stable chart id; auto-assigned if absent>"
  }
}
```

The `executeGenerateChart()` validator requires `mark` + `encoding` keys at the top level OR a composite key (`layer`, `hconcat`, `vconcat`, `repeat`, `facet`, `concat`) for multi-pane charts. 100 KB spec size cap. Returns `{ok: true, result: {chart_id, mark, …}}` on success; structured `error_kind` on rejection. Test count in `availableTools()` is now 13 (was 12); `test_ai_tools` hardcoded equality relaxed to `>= 12`.

### `VegaChartRenderer` widget

`src/charts/vega_chart_renderer.{h,cpp}` — a `QWidget` subclass with **two paths** selected at build time via the new `NOTEPATRA_WITH_WEBENGINE` CMake option.

**With `NOTEPATRA_WITH_WEBENGINE=ON` (the default when `Qt5::WebEngineWidgets` is found at configure time):**

* Embeds a `QWebEngineView` sized to the parent layout.
* Loads an inline HTML shell that imports `vega@5`, `vega-lite@5`, `vega-embed@6` from JSDelivr (all BSD-3, GPLv3-compatible).
* `setSpec(QJsonObject)` serializes the spec to JSON and calls `view->page()->runJavaScript("renderSpec(...)")`.
* The HTML shell sets `window._notepatra_chartReady = true` on success or `_notepatra_chartError = "<message>"` on failure; the renderer polls these via a 250 ms `QTimer` and emits `renderReady()` / `renderError(QString)`.
* `exportPng(scaleFactor=2)` calls `view.toImageURL('png', scaleFactor)` via JS and returns base64.

**With `NOTEPATRA_WITH_WEBENGINE=OFF`:** the widget becomes a stub `QLabel` showing *"Charts require QtWebEngine — rebuild with `cmake -DNOTEPATRA_WITH_WEBENGINE=ON`"*. The slim ~9 MB binary still compiles and runs; `generate_chart` calls render the stub instead of a real chart.

`CMakeLists.txt` `find_package(Qt5 QUIET COMPONENTS WebEngineWidgets)` auto-downgrades the flag with a `message(WARNING)` if WebEngine isn't installed on the build host.

### Inline rendering in the chat

`src/aipanel.cpp` — `handleToolCall` `generate_chart` branch builds a `QFrame#chartCard` (1px border, 8px padding) hosting the renderer + optional title `QLabel` + hidden error `QLabel` connected to `renderError`. The card is inserted into `m_chatLayout` above the stretch (so it sits in the message timeline at the moment the tool fired, not as a separate panel).

Click on the chart → no-op for v0.1.63 (the "explain this chart" modal with full-size view + Export PNG / SVG / Excel-ready data buttons lands in v0.1.64).

### Coverage

First-class Vega-Lite marks, no DIY:

* Bar (vertical / horizontal / stacked / normalized stacked / dodged)
* Line
* Area (stacked / streamgraph)
* Pie / donut (via `arc`)
* Scatter
* Histogram (via `mark: "bar"` + `bin: true`)
* Heatmap (via `mark: "rect"` + colour encoding)
* Box-plot (first-class `mark: "boxplot"`)

Composite specs work too — `layer` / `hconcat` / `vconcat` / `repeat` / `facet` all pass validation.

### Why Vega-Lite (over Plotly / Chart.js / Qt Charts / QCustomPlot)

* **LLM emission ergonomics.** Vega-Lite specs are the shortest, flattest, schema-anchored format. A bar chart is ~220 chars with a public `$schema` URL for runtime validation. The AI emits a valid spec first try far more often than Plotly's nested `data[]`/`layout` or Chart.js's split data/options.
* **Coverage matches the asks.** No `mark` we need is missing.
* **Export quality.** `view.toImageURL('png', scaleFactor=4)` produces print-quality PNG out of the box. SVG export is clean vector.
* **License.** BSD-3 across vega + vega-lite + vega-embed.

## Build / test

* `test_vega_chart` — new test binary with 5 subcases:
    1. `VegaChartRenderer` construction
    2. `setSpec` accepts a valid bar-chart spec without crash (no render assertion — that requires WebEngine + 100 ms poll)
    3. `availableTools()` contains `generate_chart`
    4. `execute("generate_chart", …)` accepts valid bar spec; rejects missing-keys / non-object / oversized specs
    5. Composite specs (`layer` / `hconcat` / `vconcat` / `repeat`) pass validation
* `ctest`: 21/21 deterministic regression tests pass (was 23 — `test_ollama` and `test_llamacpp` skip cleanly on this CI host with no inference server).
* `scripts/stale-text-check.sh`: 21/21 surfaces match canonical counts (no count changes this release).

## Deferred to v0.1.64+

| Feature | Why | Notes |
|---|---|---|
| **On-demand QtWebEngine plugin architecture** | Bare binary stays ~9 MB; QtWebEngine (~95 MB) downloads on first Data-mode use | Designed in agent D's report; `QPluginLoader` based, signed tarball at notepatra.io |
| **PPTX writer** (PNG-in-pptx via miniz) | Lets users export chart → embed in PowerPoint | OOXML chart-native (`chart1.xml`) embed deferred to v0.2 |
| **"Explain this chart" modal** | Click chart → full-size view + Export PNG / SVG / Excel + AI-driven "what does this show?" | Built on the existing modal infrastructure |
| **Poppler-Qt5 PDF→PNG rendering** for vision models | Drop a PDF on the AI dock → render pages to PNG → ship as multimodal image array | Defers to libpoppler-qt5-dev; tiered UX (page 1 silent, 2-10 with chip, 11+ ask) |
