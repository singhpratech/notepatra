# Notepatra v0.1.108

**Data Analyst mode writes sharper SQL.** Three filter-correctness idioms added to the built-in analyst system prompt — no new dependencies, the same bare Lite binary, download sizes unchanged from v0.1.107.

## What changed

The Data Analyst's system prompt now teaches three patterns that quietly bite text-to-SQL on real datasets:

- **Case-insensitive text search.** When you ask the analyst to find rows whose description / name *contains* a word, it now lower-cases both sides — `WHERE LOWER(description) LIKE '%term%'`. A bare `LIKE '%term%'` is case-sensitive in SQLite / PostgreSQL / DuckDB and silently skips Capitalized rows like `'Diabetes mellitus type 2'`, undercounting the answer.
- **Exact-code matching without over-filtering.** When a question names a coded value with a system prefix ("LOINC 8480-6", "ICD-10 E11.9", "CVX 140"), the column usually stores only the bare value — so the analyst now filters `WHERE code = '8480-6'` and *stops there*. Once the exact code matches, the rows are pinned; it no longer bolts on a guessed `AND system = …`, `AND category = …`, or a redundant `LIKE`. Each extra "to be safe" predicate can only subtract rows, and a guessed literal often removes all of them (for example, a plausible-looking `AND system = 'SNOMED'` returns zero rows when the column actually stores `'SNOMED-CT'`).
- **Fewer wrong-column guesses.** The analyst no longer invents a category / type literal from the question's English label — words like "obese", "active", "BMI" describe the data, they are not guaranteed column values. It verifies the distinct values (or filters on the code) first.

## How it was validated

The three idioms were measured against a multi-domain text-to-SQL evaluation (five datasets, hundreds of ground-truth-checkable questions) before shipping. The change is a net improvement with no regressions — including fixing the production model's lone remaining defect on the synthetic-EHR dataset, where it had been adding a spurious category filter that returned zero rows.
