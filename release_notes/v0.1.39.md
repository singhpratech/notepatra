# Notepatra v0.1.39 — Coding Mode levels up: write_file, search, apply_diff + persistent chat

**Released:** 2026-04-27

User asked, reasonably: *"if I say 'create me a Python file' it should create the .py file, right?"* — and it didn't. Coding Mode shipped agentic tool-calling in v0.1.35, but only the **read** side (`read_file`, `list_dir`); the write-side tools were noted as "deferred to v0.1.36+" in those release notes and then never landed. v0.1.39 closes that gap.

Also bundled: **persistent chat history** per workspace (so the conversation survives app restarts), and a small UI fix — the AI dock's close button is now **clearly red** instead of tone-on-tone-invisible against the chrome.

---

## What's new

### 1. `write_file` — the agent can finally create files

```jsonc
// JSON-Schema definition (sent to tool-aware models in the chat request)
{
  "type": "function",
  "function": {
    "name": "write_file",
    "parameters": {
      "type": "object",
      "properties": {
        "path":    { "type": "string",  "description": "Workspace-relative." },
        "content": { "type": "string",  "description": "Full file content (UTF-8)." },
        "mode":    { "type": "string",  "enum": ["create", "overwrite", "append"] }
      },
      "required": ["path", "content"]
    }
  }
}
```

**Modes:**

| Mode | If file exists | If file missing |
|---|---|---|
| `overwrite` (default) | Truncate + write new content | Create |
| `create` | **Refuse** (`error_kind: exists`) | Create |
| `append` | Append to end | Create |

**Auto-create subdirectories:** asking the agent to `write_file("docs/v0.1.39/notes.md", ...)` works even if `docs/v0.1.39/` doesn't exist yet — the parent path is `mkpath`'d, but only after verifying the lowest existing ancestor canonicalizes **inside** the workspace. Asking it to `write_file("../escape.txt", ...)` is refused.

**Limits:** 5 MB max content per call (typical AI-generated files are kilobytes; the cap exists to keep token-context blowups out of the picture).

**Auto-open in editor:** when the agent writes a brand-new file, it opens in a tab automatically. When it overwrites a file you already have open, the editor reloads the buffer **silently** (skips the "modified by another program" dialog — the user just told the AI to do this).

### 2. `search` — pattern hunt across the workspace

```jsonc
{
  "type": "function",
  "function": {
    "name": "search",
    "parameters": {
      "type": "object",
      "properties": {
        "pattern":        { "type": "string"  },
        "path":           { "type": "string",  "description": "Workspace-relative dir. Default: workspace root." },
        "case_sensitive": { "type": "boolean", "description": "Default false." },
        "regex":          { "type": "boolean", "description": "Default false (literal)." },
        "glob":           { "type": "string",  "description": "Filename glob, e.g. '*.py'." },
        "max_matches":    { "type": "integer", "description": "Default 50, max 200." }
      },
      "required": ["pattern"]
    }
  }
}
```

**Result shape:**

```json
{
  "ok": true,
  "result": {
    "pattern": "import os",
    "path": ".",
    "files_scanned": 142,
    "total_matches": 7,
    "truncated": false,
    "matches": [
      {"path": "src/foo.py",    "line": 3,  "col": 1, "snippet": "import os"},
      {"path": "tests/bar.py",  "line": 12, "col": 1, "snippet": "import os, sys"}
    ]
  }
}
```

Walks via `QDirIterator` with the same heavy-dir filter as the rest of Notepatra (skips `.git`, `node_modules`, `target`, `build`, `dist`, `.venv`, etc.). Files are sniffed for NUL bytes and skipped if binary. Snippets capped at 200 chars per match so the agent can keep many results in context without blowing its window.

### 3. `apply_diff` — surgical line edits, atomically

```jsonc
{
  "type": "function",
  "function": {
    "name": "apply_diff",
    "parameters": {
      "type": "object",
      "properties": {
        "path":  { "type": "string" },
        "hunks": {
          "type": "array",
          "items": {
            "type": "object",
            "properties": {
              "old_start_line": { "type": "integer" },
              "old_lines":      { "type": "string" },
              "new_lines":      { "type": "string" }
            },
            "required": ["old_start_line", "old_lines", "new_lines"]
          }
        }
      },
      "required": ["path", "hunks"]
    }
  }
}
```

**Two-phase atomic apply:**

1. **Validate ALL hunks.** For each hunk, read lines `[old_start_line .. old_start_line + count(old_lines))` from the live file. If any hunk's `old_lines` doesn't match what's actually in the file, return `error_kind: conflict` immediately. **Nothing is written.** This catches the case where the file drifted between the model reading it and asking for an edit.
2. **Apply in REVERSE order.** Hunks are sorted by start line then applied highest-to-lowest, so earlier hunks' line numbers don't shift when later hunks insert/delete content. The agent doesn't need to reason about line-shift bookkeeping — submit them in any order.

The write itself goes through a `.notepatra.tmp` + atomic `rename` so a kill-9 in the middle of writing leaves either the old file or the new file, never a half-baked corruption.

If the file is currently open in an editor tab, the buffer reloads silently after the apply.

### 4. Persistent chat history

Chats now survive app restart. Stored at:

```
~/.config/notepatra/chat-history/<sha1-of-workspace-path>.json
```

One file per workspace. Switching workspaces swaps in the right history. The schema is intentionally simple — just an array of `{role, text, model?, promptTokens?, evalTokens?, elapsedMs?}` records.

**Hygiene:**
- 1 MB cap per workspace; oldest messages roll off the front when over.
- Saves are debounced 2 s — typing into a streaming response doesn't cause a write per token.
- "Reset" deletes the on-disk file too — start fresh on next launch.
- Atomic write via `.tmp` + `rename`, just like `apply_diff`.

**Privacy note:** chats may contain pasted code. The file lives in `~/.config/notepatra/`, owned by your user. It's not shared, not synced, not uploaded.

### 5. Red close button on the AI dock

The `×` close button on the AI Assistant header was tone-on-tone against the chrome on every theme — effectively invisible at rest, only showing on hover. Replaced with a **theme-independent red** treatment:

```cpp
"QPushButton { background: transparent; border: none; "
"color: #E81123; font-weight: 700; padding: 0 0 2px 0; } "
"QPushButton:hover { background: #E81123; color: white; } "
"QPushButton:pressed { background: #C41019; color: white; }"
```

`#E81123` is the Windows-canonical close-button red (UWP / Fluent). The `×` glyph is U+00D7 MULTIPLICATION SIGN — present in every font shipped on every desktop OS for the last 30+ years (the previous attempt with U+2715 ✕ rendered as tofu on some Windows installs).

## Path safety, extended for writes

The three-layer safety from v0.1.35 (workspace anchor + canonicalize + hardcoded deny-list) still holds. New helper for write-side:

```cpp
// resolveSafeWritePath — same anchoring as resolveSafePath, but the
// TARGET file is allowed to not exist yet.
//   - parentDir: walk up to the lowest existing ancestor; that
//     ancestor's canonical path must be inside the workspace.
//   - mkpath the rest of the parent chain ONLY then.
//   - hardcoded deny-list applied to the final candidate path
//     (so creating ~/.ssh/foo via a mkpath chain is still refused).
```

Tested:
- `write_file("../escape.txt", ...)` → `outside_workspace`
- `write_file("creds.pem", ...)` → `denied` (hardcoded `*.pem` rule)
- `apply_diff("secret.pem", ...)` → `denied` (same rule, applies on existing files too)
- `write_file("new/sub/dir/file.py", ...)` where `new/` doesn't exist → mkpath, then write
- `write_file("/etc/passwd", ...)` → `outside_workspace`

## What the agent sees (system prompt)

```
You have agentic workspace tools available.

READ side:
  read_file(path, offset?, limit?)
  list_dir(path)
  search(pattern, path?, regex?, glob?, case_sensitive?, max_matches?)

WRITE side:
  write_file(path, content, mode?)
  apply_diff(path, hunks)

Use the tool_calls structured field — never type JSON in your text response.
Paths are workspace-relative; secret/credential paths refused.

Prefer write_file for new files or full rewrites; prefer apply_diff for
surgical edits to large existing files. After writing, the user's editor
auto-opens or reloads the file — no need to ask them to refresh.
```

## Try it

In a workspace, with Coding Mode ON and a tool-aware model selected (qwen3, llama3.1+, hermes3, mistral-nemo, granite3, claude-*, gpt-4*, openai/*, anthropic/*):

```
> create a Python script hello.py that prints "Hi from Notepatra!"
```

The agent will:
1. Call `list_dir(".")` to see what's already there.
2. Call `write_file("hello.py", "print(\"Hi from Notepatra!\")\n")`.
3. Notepatra opens hello.py in a new tab.

```
> in hello.py change the message to include today's date
```

The agent will:
1. Call `read_file("hello.py")` to see the current content.
2. Call `apply_diff("hello.py", [{old_start_line: 1, old_lines: "print(...)\n", new_lines: "...new line..."}])`.
3. Editor silently reloads the buffer.

```
> find every TODO in this codebase
```

→ `search("TODO", regex=false)` → list of matches the agent summarises.

Close + reopen Notepatra. Open the same workspace. The chat is still there.
