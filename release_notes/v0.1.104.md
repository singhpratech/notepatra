# Notepatra v0.1.104

**Diagrams gain optional per-symbol colours and chained arrows — `node x [Process] #1565c0` and `a -> b -> c` — while staying monochrome by default.** The native `.npd` renderer that landed in v0.1.103 now lets you give individual nodes their own colour for a splash of meaning (green starts, amber decisions, red errors), and connect a sequence of nodes on one line. Nothing changes if you don't ask for it: an uncoloured diagram looks exactly as before.

## What changed

The v0.1.103 diagram canvas drew every node in one uniform palette, and every connection had to be written as a separate `a -> b` line. Two small additions make real flow charts easier to read and faster to write — both opt-in, both fully native (no WebEngine), both flowing through the same `QPainter` export path so they appear in PNG/JPEG/PDF/SVG/HTML/WebP alike.

## The additions

1. **Per-symbol colour (opt-in).** Add a colour token *after the shape* on any `node` (or `icon`) line:

   ```
   node start (Start) green
   node proc  [Process data] #1565c0
   node check {Valid?} orange
   node err   [Show error] red
   ```

   Use a `#hex` value or a common colour name. The renderer derives a readable **border** and **auto-contrast label text** (dark text on light fills, light text on dark) so a coloured node stays legible on any of the five palettes and in light/dark themes. A node with **no** colour keeps the diagram palette — so leaving them all uncoloured gives the clean monochrome look that is still the default.

2. **Chained arrows.** Connect a run of nodes on one line:

   ```
   a -> b -> c -> d        # expands to a→b, b→c, c→d
   m -> n <-> o            # each hop keeps its own direction
   a -> b -> c : ok        # a trailing label rides the LAST hop
   ```

   `a -> b -> c` previously produced a single broken node literally named `"b -> c"`; it now expands into the individual edges, with per-hop direction (`->` vs `<->`) preserved.

## Parser hardening

The chained-arrow change was put through an adversarial parse audit, which surfaced — and this release fixes — a set of edge cases, several of them latent before v0.1.104:

| Input | Before | After |
|-------|--------|-------|
| `http://x -> y`, `a:start -> b` | edge silently dropped (colon mis-read as a label) | clean edge; **node ids may contain colons** (URLs, namespaces) |
| `a -> b:state -> c` | chain collapsed, node `c` lost | full chain `a → b:state → c` |
| `node x [Maps A -> B]` | hijacked into the edge branch → garbage nodes | a normal node whose **label may contain `->`** |
| `a -> b :: detail` | label became the literal `": detail"` | clean label `detail` |

The label separator is now the first `:` written **after the first arrow and with a leading space** (` : label`), which is exactly how every template and the AI prompt already teach it. A leading keyword (`node`/`icon`/`diagram`/`title`/`palette`/`textbox`) always wins, so labels are free to contain arrows.

A standalone diagram **export** hardening also ships: an untrusted `.npd` `title` containing `</title><script>…` is now HTML-escaped at the write site, so it can never inject a live tag into exported HTML or SVG.

## Out of scope

- Colours on **connection** lines — colour is a `node`-line feature; on an edge line a trailing word stays part of the (admittedly unusual) node id. Documented in Help.
- Per-hop labels inside one chain line — write each labelled hop on its own line; a chain's single trailing label rides the last hop.
