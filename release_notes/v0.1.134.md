# Notepatra v0.1.134

**macOS fixes for the REST Client and the menu bar, and a status bar that describes the tab you are on.**

A small release. Everything below was reported from a macOS screenshot of the REST Client; the status bar and Encoding fixes apply on every platform.

## Fixed: REST Client

- **The Headers and Body tab labels were clipped on both sides on macOS** ("eader", "ody"), in both the request and the response tabs. Qt sized each tab with the tab bar's own font, the app's 10 pt UI font, which is 10 px on macOS, while the stylesheet painted the label at 12 px, and the label was cut to fit. Linux and Windows draw that font at about 13 px, so it never showed there. The 12 px label size is now set on the tab bars themselves, so the same font measures and paints the label.
- **Send Request hints show the keys you actually press:** `⌥⌘R` on macOS, `Ctrl+Alt+R` on Linux and Windows. The shortcut now comes from one place, and the Body pane hint, the Feature Guide, the Keyboard Shortcuts list and "How REST Client Works" all print it the way the platform writes it.
- **No "Set a method and URL" hint over a response.** After a binary response the Body pane is empty (the size and type are in the note above it), and it still showed the before-any-request hint. It now says "Binary response: not shown as text. Use Save… to keep it.", and an empty response says "The response has no body."
- **Open in tab is text-only.** Its icon was the system's generic-document picture, a white page on macOS, which disappeared when the button was disabled. The Copy button beside it already had no icon.

## Changed: macOS menu bar

macOS truncated the titles of 14 top-level menus. On macOS the menu bar is now:

File · Edit · Search · View · Tools · Format · Settings · Window · Help

- **Format** (new, macOS only) holds the Encoding and Language menus.
- **Tools** ends with Utilities, Plugins, Macro and Run, after a separator.
- Every menu item, shortcut and checkmark is the same as before; only where the six menus sit changed. Linux and Windows keep the 14 menus in the same order.

## Fixed: status bar on tool tabs

On a tab that is not an editor (Welcome, REST Client, Noter, Terminal, a diagram, Compare, the formatter panels and the other tool tabs) the status bar kept showing the last editor's length, line count, position, line endings, encoding and INS. It now shows only the tab's name, and clicking it does nothing. The empty slots keep their space, so the bar does not shift when you switch between an editor and a tool tab. Going back to an editor shows its fields again.

Also fixed: **clicking the encoding in the status bar now opens the Encoding menu.** It looked for a menu titled "Encoding", but the title is written `E&ncoding`, so the click did nothing on every platform.

## Visible on Linux and Windows

- The REST Client's tabs are a few pixels narrower (about 5 px for "Headers"): they were sized with the larger app font. The text, padding and orange underline are unchanged.
- Open in tab has no icon.
- Tool tabs show only their name in the status bar.
- The Feature and Tool Guide no longer mentions a "Features" menu or a "?" menu, neither of which exists, and says the built-in formatter panels are in the Tools menu.

## Not verified

The macOS fixes are covered by tests that reproduce the Mac conditions on Linux (a 10 px app font for the tab labels, the compact menu bar built on purpose) and by Linux screenshots. As of writing they have not been run on a real Mac. In particular, the macOS app menu (About, Preferences, Quit) and the system items macOS adds to Window and Help have not been seen with the new menu bar.

## Tests

- `test_rest_client`: tab labels painted with the tab bar's own font and wide enough for it under a Mac-sized font; the Send Request hint matches the action's keys; the binary and empty-response hints; Open in tab has no icon.
- `test_menubar_layout` (new): both menu-bar layouts, the 9 and 14 titles in order, identical items and shortcuts in both, the status-bar Language and Encoding clicks, and no item that macOS would move into the app menu.
- `test_changehistory_statusbar`: switching to the REST Client tab hides the editor fields, shows the tab name and stops clicks; switching back restores them.
