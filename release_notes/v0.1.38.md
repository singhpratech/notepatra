# Notepatra v0.1.38 — AI Assistant crash + file-leak hotfixes

**Released:** 2026-04-26

Two bugs reported by user, both root-caused and fixed.

---

## Bug 1: Coding Mode toggle crashed the app mid-stream

### Symptom

Clicking the Coding Mode checkbox while a model was actively streaming a response caused the app to crash.

### Root cause

Use-after-free on the `m_streamingStats` QLabel.

```
1. User hits Send → AI starts streaming
2. beginAssistantBubble() creates the streaming card with a child
   QLabel (m_streamingStats) and starts a 250 ms QTimer that
   updates the label's text from the live token count.
3. User clicks Coding Mode mid-stream
4. Toggle handler calls renderTranscript()
5. renderTranscript() → aiClearChat() → deleteLater() on every
   widget in m_chatLayout, including m_streamingCard.
   m_streamingCard's destruction also schedules its child
   m_streamingStats for deletion.
6. m_streamingCard / m_streamingBody pointers nullified
   ←  but m_streamingStats was NOT nullified  ←
7. 250 ms timer ticks
8. Lambda checks `if (!m_streamingStats) return;`  ← passes,
   pointer is non-null but DANGLING (memory freed)
9. Lambda calls m_streamingStats->setText(...) → CRASH
```

### Fix

In `renderTranscript()`, stop the timer AND nullify `m_streamingStats` (plus `m_streamingTokenCount` + `m_streamingStartMs`) **before** calling `aiClearChat()`. Same defensive cleanup added to `endAssistantBubble()` for symmetry.

```cpp
void AIPanel::renderTranscript() {
    if (!m_chatLayout) return;
    if (m_streamingStatsTimer) m_streamingStatsTimer->stop();
    m_streamingStats = nullptr;
    m_streamingTokenCount = 0;
    m_streamingStartMs = 0;
    aiClearChat(m_chatLayout);
    m_streamingCard = nullptr;
    m_streamingBody = nullptr;
    ...
}
```

## Bug 2: Custom chat appended the entire open file to every prompt

### Symptom

User typed a casual message ("hi") in the AI chat box with **Coding Mode OFF** and no text selected. The AI saw their whole open file appended to the prompt — wasting tokens, leaking unrelated code, and producing weird responses.

### Root cause

```cpp
// setWorkspaceContext()  (aipanel.cpp:1162 pre-v0.1.38)
m_context = selectedText.isEmpty() ? currentFileText : selectedText;
```

When the user had no selection, `m_context` fell back to the **entire current file**. That's correct for quick-action templates (Explain / Refactor / Write Tests) which need code to operate on. But the "custom" chat action also unconditionally appended `m_context`:

```cpp
// sendPrompt() "custom" branch  (aipanel.cpp:1565 pre-v0.1.38)
prompt = userText + "\n\n```\n" + m_context + "\n```";
```

So a 2-byte "hi" became the entire file plus 2 bytes.

### Fix

New `m_contextIsSelection` flag tracks whether `m_context` is a real user selection or a whole-file fallback:

```cpp
// AIPanel::m_contextIsSelection  (NEW in aipanel.h)
bool m_contextIsSelection = false;

// setWorkspaceContext() now sets the flag:
m_contextIsSelection = !selectedText.isEmpty();
m_context = m_contextIsSelection ? selectedText : currentFileText;

// sendPrompt() "custom" branch is now conditional:
if (m_contextIsSelection && !m_context.isEmpty()) {
    prompt = userText + "\n\n```\n" + m_context + "\n```";
    userBubbleText = userText + "\n\n" + m_context;
} else {
    prompt = userText;
    userBubbleText = userText;
}
```

**Behaviour after the fix:**

| State | Before fix | After fix |
|---|---|---|
| File open, no selection, "hi" | Whole file appended to "hi" | Just "hi" |
| File open, text selected, "explain this" | Selection appended | Selection appended (correct) |
| Quick-action button (Explain/Refactor/etc.) with no selection | Whole file appended | Whole file appended (correct — these actions NEED code) |
| Quick-action button with selection | Selection appended | Selection appended (correct) |
| Project-level question ("show me my files") | Workspace context block attached via `shouldAttachWorkspace` | Same (unchanged) |
| Coding Mode + question about a file | Workspace + agentic `read_file` tool | Same (unchanged) |

The "custom" chat now behaves like a regular chat box. Quick actions still get the file context they need. Coding Mode's agentic tools still let the AI explicitly read files via `read_file()` calls.

## Try it

1. Open any file. Type "hi" in the AI chat. Coding Mode OFF. The AI now sees just "hi" — not the whole file.
2. Select a line of code. Type "what does this do". The AI sees the selection inlined as a fenced code block.
3. Click any quick-action button (Explain / Refactor / etc.). The whole-file fallback kicks in — those actions need code to operate on.
4. Click Coding Mode toggle while a stream is in progress. No crash.
