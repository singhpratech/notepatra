# Notepatra v0.1.40 — the "stop screwing up my JSON" release

**Released:** 2026-04-29

---

## What happened

After v0.1.39 shipped (Coding Mode could finally `write_file` / `search` / `apply_diff`), the user tried to fix a broken JSON file via the AI dock and reported: *"it added unnecessary content all it had to do is fix it and it screwed JSON bigtime."*

Two real product issues plus four agent-loop robustness gaps fell out of the diagnosis:

1. **The chat panel didn't use the strict patcher prompt.** Tools → JSON Tools → AI Fix has a "minimal-change JSON patcher" prompt with explicit *"do NOT reorder keys, do NOT reformat, do NOT add fields"* rules. The AI dock chat (Ctrl+Shift+A) used the generic chat prompt — small models gladly "improved" the user's JSON by adding fields and restructuring.

2. **No quick way to invoke the strict path from the dock.** Even users who knew about the JSON Tools panel had to leave the chat to use it.

3. **`apply_diff` byte-exact match.** The model gets file content via `read_file` with `      N\t` line-number prefixes; small models often echoed those right back into `apply_diff old_lines`, hitting `error_kind: conflict` on every hunk.

4. **Whitespace-fragile match.** Trailing spaces / slightly different leading indent in the model's `old_lines` would conflict against bytewise-identical content modulo whitespace.

5. **Silent JSON parse failures.** When the model emitted malformed JSON in tool-call `arguments` (very common when the tool args contain unescaped quotes from the broken JSON the user is asking it to fix), both the Ollama path and the OpenAI-compat path silently produced empty args. The downstream tool then fired with confusing errors like *"hunks array is empty"* and the agent gave up.

6. **`read_file` couldn't be told to skip the line-number prefix.** Even when the model wanted to feed read_file output into apply_diff cleanly, the prefix was always there.

v0.1.40 fixes all six.

## Headline fixes

### 1. Fix-intent detection in the AI chat

Type `fix my json` (or `fix my html`, `fix my sql`, `repair this json`, `the json is broken`, etc.) into the AI dock chat input and the system prompt automatically swaps to a strict minimal-change patcher — same rules as Tools → JSON Tools → AI Fix:

```
You are a minimal-change JSON patcher. Your job is to take broken JSON
and return the SAME JSON with ONLY the broken parts fixed. Preserve
everything else exactly — line order, key order, indentation, whitespace.

Rules — apply ONLY these, do NOT improve content:
1. Add missing closing braces/brackets — match what's open.
2. Remove trailing commas (JSON spec forbids them).
...
8. Do NOT reorder keys. Do NOT reformat. Do NOT add fields.
9. Output ONLY the corrected JSON. No prose, no markdown ``` fences,
   no comments, no <think> blocks, no preamble.
10. If the input is already valid JSON, output it UNCHANGED.
```

What does NOT trigger:
- `explain my json` / `describe this json` / `what is json`
- `show me my json files` / `list all json files` / `find json`
- `teach me json`
- `fix my code` (too generic — chat handles it)

Implementation lives in `src/ai_intent.{h,cpp}` so the regex + prompt-builder is testable independently of the AI panel UI. Tests: `test_ai_intent` covers 49 assertions.

### 2. Three new quick-action buttons

Open the AI dock → **▸ Quick actions** → see a third row:

> [ Fix JSON ] [ Fix HTML ] [ Fix SQL ]

Each routes the current selection (or current file if no selection) to the strict-patcher prompt, no need to type the trigger phrase. Tooltip on hover: *"Strict minimal-change fix for the selection (or current file). Won't add fields, won't reformat, won't restructure."*

A tip line under the buttons points users at the dedicated panel for repeated / large fixes:

> 💡 For larger or repeated fixes, open Tools → JSON Tools (or HTML / SQL) — dedicated panel with side-by-side diff, regex-first repair, AI fallback.

### 3. `apply_diff` three-tier match

Per-hunk fallback chain:

| Tier | Match strategy | On match |
|---|---|---|
| 0 | Strict bytewise equality | Apply, no warnings |
| 1 | Strip `^\s*\d+\t` line-number prefix from `old_lines` | Apply, append `"hunk@N: matched after stripping read_file line-number prefix from old_lines"` to `result.warnings` |
| 2 | `.trimmed()` comparison per line | Apply, append `"hunk@N: matched only after whitespace normalization — verify indentation in new_lines"` |
| (none) | All three failed | Return `error_kind: conflict` (existing behaviour) — file untouched |

The relaxed tiers let the agent make forward progress while the warning lets it self-correct on the next read — this is the same pattern established AI assistants use. True conflicts (genuinely different content) are still refused, verified by a regression test.

### 4. `read_file with_line_numbers` parameter

New optional bool, default `true` (back-compat with every v0.1.39 caller). Pass `false` to receive raw file content with no `      N\t` prefix:

```jsonc
// Default — line-number prefix included (back-compat)
read_file({ "path": "main.cpp" })
// →   "     1\t#include <iostream>\n     2\tint main() {\n..."

// New — raw bytes, suitable for apply_diff old_lines
read_file({ "path": "main.cpp", "with_line_numbers": false })
// → "#include <iostream>\nint main() {\n..."
```

The `read_file` schema in `availableTools()` advertises the new param so any tool-using model can find it.

### 5. Tool-mode system prompt teaches the model

The agentic-mode preamble (`src/ai_systemprompt.cpp::toolModeLayer`) now includes:

> `read_file(path, offset?, limit?, with_line_numbers?)` to read a file (default output prefixes each line with `      N\t` — use `with_line_numbers=false` when you plan to feed lines into `apply_diff old_lines` so you do NOT have to strip the prefix yourself)
>
> `apply_diff(path, hunks)` for line-level edits where each hunk has `old_start_line` + `old_lines` (expected current text — must match the file BYTE-FOR-BYTE; do NOT include the `      N\t` prefix from read_file's default output) + `new_lines` (replacement). Atomic; if any hunk's old_lines doesn't match the file the call returns `error_kind: conflict` and nothing is written. The tool will fall back to a prefix-strip / whitespace-normalised match and report it in `result.warnings` — if you see those warnings, re-read the file with `with_line_numbers=false` to avoid them.

### 6. Tool-call JSON parse-error surfacing

In `src/ollama.cpp`, both the Ollama `/api/chat` path and the OpenAI-compat SSE path now use `QJsonParseError` to detect malformed tool-call arguments. When parsing fails on a non-empty payload, the args object gets two markers:

```jsonc
{
  "_notepatra_parse_error": "expected value at offset 42",
  "_notepatra_raw_args": "{ \"path\": \"foo.json\", \"hunks\": [ ..."
}
```

`AIPanel::handleToolCall` detects the markers and synthesises a structured error tool result back to the model:

```
Tool-call arguments JSON failed to parse: <error>. Re-emit the call with
valid JSON. Make sure quotes inside string values are escaped (\") and
that nested objects are well-formed. Raw args preview: <240 chars>...
```

A red `(malformed args) ✗ malformed_args` card appears in the chat so the user can see what happened. The hard 25-call budget still ticks, so a model stuck in a loop of malformed calls eventually halts.

## Tests — 17/17 suites green

Was 16 on v0.1.39 (`test_ai_intent` is new). 

| Suite | Coverage |
|---|---|
| `test_ai_intent` (NEW) | 49 assertions — positive JSON/HTML/SQL intents (case-insensitive, mixed phrasing), negatives (`explain`, `describe`, `teach`, `show`, `list`, `find`, `grep`), edge cases (multi-line, `@file` mention, generic "fix my code"), strict-prompt sanity (mentions PRESERVE, mentions reorder warning, no markdown fences instruction). |
| `test_ai_tools` (extended) | +20 new assertions: apply_diff strict tier (no warnings on clean match), tier-1 prefix-stripped match emits warning, tier-2 whitespace-trimmed match emits separate warning, true conflict still refused, read_file default vs `with_line_numbers=true` vs `with_line_numbers=false`, schema advertises new param. 157 total assertions in this suite. |

All 17 suites pass on Linux. CI will validate macOS + Windows on tag push.
