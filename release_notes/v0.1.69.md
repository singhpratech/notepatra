# Notepatra v0.1.69 — Critical fix: AI Coding / Data mode no longer locks tool buttons

**Date:** 2026-05-10
**Tag:** `v0.1.69`
**Build:** Linux x64 / Linux ARM64 / macOS Apple Silicon / Windows x64 — both lite and Linux-full flavors

A critical follow-up to v0.1.68 closing the **Coding / Data mode auto-fullscreen lock-up**, plus the integration test that proves it stays fixed.

---

## The bug

When the AI Assistant is in **Coding Mode** or **Data Mode**, the dock auto-fullscreens — the user gets the full window for the chat / data-analyst session and the editor + sidebars are hidden by Qt's splitter machinery. Pre-v0.1.69, clicking **any tool button** while in those modes — Project Search, Terminal, REST Client, JSON / HTML / Bracket Tools, SQL Formatter, Compare, Welcome — appeared to do nothing. The button click was real, the tool tab was added to the tab widget, but `m_tabs` itself stayed hidden behind the splitter squashed to 100% AI dock. App looked frozen / locked up. Only Ctrl+Shift+A (toggle dock off) would partially recover, and even then the editor area came back empty until tab visibility was manually restored.

## Root cause

Coding Mode and Data Mode enter fullscreen via a code path **different** from the user clicking the `⛶` expand button:

```cpp
// src/aipanel.cpp ~line 1200 (coding mode toggle)
connect(m_codingMode, &QAbstractButton::toggled, this,
        [this, applyModeWithCancel](bool on) {
            if (on) { applyModeWithCancel(); emit fullscreenToggled(true); }
        });
```

The mode toggle **emits `fullscreenToggled(true)` directly** — it never calls `m_aiExpandBtn->setChecked(true)`. (The expand button is also hidden in Coding / Data mode — see `applyMode` line ~1031 — so the user has no way to un-fullscreen via the button.)

v0.1.67's `MainWindow::exitAiFullscreenIfActive()` helper drove the off-path through `AIPanel::forceExitFullscreen()`, which was:

```cpp
void AIPanel::forceExitFullscreen() {
    if (m_aiExpandBtn && m_aiExpandBtn->isChecked()) {
        m_aiExpandBtn->setChecked(false);
    }
}
```

When fullscreen was entered via the Coding / Data mode toggle, the button was never checked, so `forceExitFullscreen` short-circuited and **did nothing**. The tool tab opened in a hidden `m_tabs`.

## The fix

`src/aipanel.cpp` — `forceExitFullscreen()` now emits `fullscreenToggled(false)` directly when the button isn't checked, so `MainWindow`'s existing fullscreen-restore handler always runs. The handler is idempotent — if there's no saved sibling state (`m_aiSavedSiblingVisibility` is empty), the off-branch is a no-op.

```cpp
void AIPanel::forceExitFullscreen() {
    if (!m_aiExpandBtn) return;
    if (m_aiExpandBtn->isChecked()) {
        m_aiExpandBtn->setChecked(false);  // user-toggled fullscreen path
    } else {
        emit fullscreenToggled(false);     // Coding / Data mode path
    }
}
```

## The test that catches it

`test_ai_fullscreen_exit.cpp` grows from 14 sub-checks (v0.1.68) to **23 sub-checks across 6 scenarios**. The two new scenarios drive exactly the buggy code path:

| # | Scenario | Pre-v0.1.69 | v0.1.69 |
|---|---|---|---|
| S1 | fullscreen (via expand btn) + `openFile(new)` | PASS | PASS |
| S2 | fullscreen + `setCurrentIndex(other)` (Ctrl+Tab equiv) | PASS | PASS |
| S3 | fullscreen + Ctrl+N (v0.1.61 background-tab UX) | PASS | PASS |
| S4 | fullscreen + `openFile(already-open)` | PASS | PASS |
| **S5** | **Coding mode + Project Search click** | **FAIL** | **PASS** |
| **S6** | **Data mode + Terminal (Ctrl+`) click** | **FAIL** | **PASS** |

The S5 / S6 assertions are `m_tabs->isVisible()` after the tool action triggers — proving the tab widget is actually visible to the user, not just present in the QObject tree.

This test runs in CI on every commit, so this class of regression cannot ship undetected again.

## Why three releases for one feature

v0.1.67, v0.1.68, and v0.1.69 all touched the same AI-dock-fullscreen-exit code path. The reason it took three cuts:

* **v0.1.67** wired auto-exit on 14 tool-tab open sites but missed editor tab switching (Ctrl+Tab, tab-bar click, `File > Open`).
* **v0.1.68** added `currentChanged` instrumentation to catch every tab-focus change, but never tested the Coding / Data mode path because the v0.1.68 integration test only exercised fullscreen entered via the expand button.
* **v0.1.69** introduces the **first real integration test of the auto-fullscreen path** (S5 + S6 above), which caught a third bug that had been invisible since Coding / Data modes were introduced — the user reported it visually as "app locks up when I click Project Search in Coding mode".

The deeper lesson is wired into the build now: any new auto-fullscreen entry path must extend `test_ai_fullscreen_exit` or it doesn't ship.
