# Notepatra v0.1.93 — Project Search: intelligent flood protection, relevance ranking, smarter defaults

**Release date:** 2026-05-19

Project Search reliability + ergonomics release. Replaces the v0.1.92 "drop everything in a tree and hope" model with an *informed* search experience: smart defaults, soft amber warning at 10k matches, hard checkpoint popup at 50k with user choice (Continue / Show me these / Cancel), live descending phrase-relevance ranking, a `match=N%` badge on every result row, and desktop notifications for long searches.

No new file types / lexers / backends / installer changes. Same install commands, same artifact names, same flavor split.

---

## What was broken before

Project Search v0.1.92 had no flood protection. A casual 2-word query against a large folder (e.g. `import os` against `$HOME`) could match tens of thousands of files in caches/venvs/cargo-deps and:

1. Flood the UI thread with millions of queued `matchesFound` events
2. Push memory to 1 GB+
3. Eventually OOM-kill the app, losing the user's session

The first attempted fix in this release cycle was a silent hard cap at 50,000 matches — but capping mid-search loses results the user can't see. Replaced with the **B-with-tweaks** design after a design discussion: warn, don't truncate.

## What changed

### 1. Match all words — **default OFF**

Default OFF means a 2-word query like `import os` runs as an *exact-phrase search* (matches the literal substring `"import os"`) — safe and predictable.

Power users tick it explicitly when they want any-order any-line AND semantics. Tooltip explicitly labels **Default OFF** and explains the trade-off.

### 2. Soft amber warning at 10,000 matches

When the running match count crosses 10,000, the progress bar turns amber and the status line shows:

> ⚠ Found 10,000+ matches — scan is wide. Hit Cancel anytime or narrow your query.

Informational only, no interruption. One-shot per search.

### 3. Hard checkpoint popup at 50,000 matches

When the count crosses 50,000, all worker threads pause at file boundaries. A modal dialog shows:

```
Found 50,000 matches across 847 file(s).
Scanned 12,000 of 38,400 files (31%). 26,400 file(s) still to go.
Continuing may use 500 MB+ of RAM and take longer. What do you want to do?

[ Continue (find more) ]  [ Show me these ]  [ Cancel ]
```

- **Continue** — workers resume, no more popups for this search (sticky opt-in)
- **Show me these** — workers stop cleanly, partial results are kept and rendered. UI phase flips to Idle *immediately* (status line says "⏸ Stopping at your request…") so the elapsed timer doesn't keep ticking while threads wind down.
- **Cancel** — same path as the Cancel button; discards in-flight stream

### 4. `match=N%` relevance badge on every result row

Every result line now starts with a self-describing badge:

```
match=100%  90:1   │  import os
match=100%  90:8   │  import os
match= 99%  91:1   │  import posixpath
match= 50%  120:8  │  os.path.exists("/tmp")
```

Meaning:

| `match=N%` | What it means |
|---|---|
| **100%** | Your full phrase appears on that line (exact-phrase search → every row is 100%) |
| **99%** | Match-all-words mode, every query word is on this line but not as a contiguous phrase |
| **50%, 67%…** | Match-all-words mode, only some query words are on this line (the rest matched elsewhere in the file) |

Badge is shown in **every mode** (exact phrase, regex, single-word, match-all-words) — exact-phrase searches naturally land at 100% on every row, so the badge is visually consistent. The hint under the title also updates dynamically when Match-all-words is ticked to explain the badge inline.

### 5. Live phrase-relevance ranking (descending, both axes)

When Match-all-words is ON and the query has 2+ tokens, results are ranked descending by relevance — *as the scan progresses*, not only at the end:

- **Within a file**: lines with `match=100%` (phrase hits) sort above `match= 99%` (all-words scattered) above lower percentages, via stable_sort on the `Qt::UserRole+5` per-line score.
- **Across files in the session**: each file's best-line score (UserRole+4) drives a session-level order. When a new batch improves a file's best score, the file is *live-repositioned* in the tree (take + insert at the correct sorted slot) so 100%-containing files surface to the top during the scan.

Score model:
- Per-line: 100 for phrase, 99 for all-tokens-scattered, `round(found/total * 99)` for partial, 0 if no tokens hit.
- Per-file: `bestPct × 1,000,000 + matchCount` — bestPct always beats match volume, ties broken by total match count.

### 6. Desktop notification when a long search finishes unfocused

When a search takes ≥ 3 seconds AND the Notepatra window is **not** the active window AND the OS exposes a notification daemon, an OS-native notification fires:

> **Notepatra — Project Search done**
> Found 50,247 matches across 1,443 files in 1m 23s.

Cross-platform via `QSystemTrayIcon::showMessage` — Qt routes to libnotify/D-Bus on Linux, Toast on Windows, NSUserNotificationCenter on macOS. No visible tray icon is added; we only need the instance to deliver the notification.

Won't fire for:
- Searches < 3 seconds (status line already tells you)
- Window currently focused (you're already watching)
- Hosts with no notification daemon (rare on Linux — KDE / GNOME both expose it)

### 7. Search button re-enables immediately on stop

Pre-fix, clicking Cancel or "Show me these" left the Search button greyed out for several seconds while worker threads unwound from `QtConcurrent::blockingMap`. Now the button re-enables instantly — a fresh `startSearch()` resets every worker atomic from scratch, and the new search slot queues behind via `Qt::QueuedConnection`, so a new query can start the moment the user wants.

### 8. Hover tooltips on every checkbox

Every checkbox in the search panel now has a tooltip that explains what it does (Match case, Whole word, Regex, Match all words, Also match file names, Include binary files). Previously only Include-binary had one.

## Bug fixes

| Bug | Cause | Fix |
|---|---|---|
| Modal dialog showed *"Scanned X of Y files (4%%)"* | Literal `%%` in the QString template; Qt's `arg()` doesn't process `%%` like printf | Changed template to `(%3%)` |
| Status line showed *"⏳ stalled on: <path>"* even when the scan was making progress (just slow on a big file) | Wording from the 20-tick stall-detection branch was alarming | Renamed to *"· current: <path>"* — neutral, matches the header-file comment |
| Project Search title 🔍 rendered as a bare mono glyph (or tofu) on Linux while looking correct on Windows / macOS | The title `QLabel` font didn't carry the same color-emoji font fallback that the results tree uses | Applied the same `#ifdef Q_OS_LINUX` font-families fallback (Noto Color Emoji → Twemoji → Symbola → Joypixels) to `m_title`'s font |
| "Show me these" left the status line saying *"Searching…"* for ~47 seconds while threads wound down | UI phase wasn't reset until the worker fully returned | UI phase flips to Idle and the 10 Hz live refresher stops the instant the button is clicked, with status updated to *"⏸ Stopping at your request…"* |
| Phrase-matching files weren't surfacing to the top of results during the scan (only after finish) | Original implementation only re-sorted in `onFinished` | Live re-position in `onMatches` via `take + insert at correct sorted slot` whenever a file's best-line % improves |

## How the threshold pipeline works

```
                  ┌──────────────────────────────────────┐
   match found ──►│ totalMatchesAtomic++                 │
                  │ totalFilesWithMatchesAtomic++ on emit│
                  └────────────┬─────────────────────────┘
                               │
                               ▼
                  ┌──────────────────────────────────────┐
                  │ checkThresholds() — runs after every │
                  │ matchesFound emit, in worker thread  │
                  └────────────┬─────────────────────────┘
                               │
                ┌──────────────┴──────────────┐
                ▼                              ▼
        matches >= 10,000                matches >= 50,000
        (one-shot)                       (one-shot &
                │                         m_skipCheckpoints==false)
                ▼                              │
        emit softWarningHit ──► UI: amber bar  ▼
                                       m_paused.store(true)
                                       emit pauseAtCheckpoint
                                              │
                                              ▼
                                       UI: modal dialog
                                              │
                              ┌───────────────┼───────────────┐
                              ▼               ▼               ▼
                         Continue       Show me these     Cancel
                         m_skip=true    m_cancel=true     m_cancel=true
                         m_paused=false m_paused=false    m_paused=false
                              │              │                │
                              ▼              ▼                ▼
                         workers       workers stop      workers stop
                         resume       (keep results)    (discard)
```

All atomic. `compare_exchange_strong` ensures the signals fire exactly once per search even when multiple worker threads cross the threshold simultaneously.

## Known limitations carried forward

- The 50k checkpoint popup is per-search only — if you click Continue and the same search hits 500k, no further popup (we trust your first Continue).
- "Don't ask again this session" is **not** in this release — deferred to v0.1.94 to keep the diff narrow.
- Smart folder default (defaulting to current file's dir / workspace instead of the previously-used folder) is also deferred to v0.1.94.
