# Notepatra v0.1.95 — Windows crash hardening + Noter full redesign

**Release date:** 2026-05-24

Two big shipping items in one release: (1) three critical Windows crash classes fixed (Save / Save As / right-click Save crash on every invocation; double-click launcher spawning multiple PIDs; window invisible at unreachable coordinates after a monitor change) and (2) the meeting-notes feature **Noter** rewritten from scratch into a two-pane sidebar+editor shape after the v0.1.94 placeholder UX proved unusable.

Same install commands, same artifact names, same flavor split (lite + full).

---

## Note on version numbering — what happened to v0.1.94?

The version line jumps from `v0.1.93` straight to `v0.1.95`. **v0.1.94 was never tagged or published as a release.** Here's the sequence:

1. After v0.1.93 shipped on 2026-05-19, a user reported three Windows-only failures: Save / Save As reliably crashing, multi-PID on double-click launcher, and an invisible-window state after a monitor change.
2. The fixes for all three were built locally during a deliberate release pause (no commits to `main`, no CI burn). Internally those fixes were tagged as the *next* version — `v0.1.94` — in source-file comments to mark when the changes were made.
3. Before that work was tagged, the same session continued into the full Noter redesign — the meeting-notes feature being rewritten from scratch after its v0.1.94-era placeholder UX proved unusable. That work was conceptually `v0.1.95`.
4. When the release pause was lifted, **both bodies of work were bundled into a single v0.1.95 release** to avoid the churn of two tags in 24 hours (each tag costs a multi-platform CI run, a GitHub Pages rebuild, and a canary install probe — none of which is free).

So v0.1.95 is *substantively* two minor releases stapled together. The "Windows crash hardening" section below IS the v0.1.94 work; the "Noter full redesign" section is the v0.1.95 work. There is no separate release artifact for v0.1.94 and never will be — the v0.1.94 tag was never created on the remote, and the binary released as `v0.1.95` includes the v0.1.94 work in full.

You may still see `// v0.1.94 — …` comments in the source code (`src/mainwindow.cpp::clampWindowToScreens`, `src/main.cpp` single-instance bridge block, the `configureSaveDialogUx` rewrite). Those are **forensic breadcrumbs**, marking when the change was made conceptually — not a claim about which release shipped it. The CHANGELOG and this release notes file are the authoritative record of which version shipped which work.

This is the same pattern as prior gaps in Notepatra's version line (v0.1.4, v0.1.6, v0.1.11 — all noted in the CHANGELOG preamble), where tagged-but-unpublished work rolled forward into the next published release. The mental model: **a version number gap means "rolled into the next version", never "shipped but you missed it".**

## 1. Windows crash hardening

Three independent crash / hang classes resolved.

### 1.1 Save / Save As crash on every invocation

**What was broken:** every Save / Save As / right-click-Save / closeTab-Save-prompt invocation reliably crashed Notepatra on Windows. Multiple users reported the same stack.

**Root cause:** `QFileDialog::setProxyModel(...)` plus a `QIdentityProxyModel` subclass (`SaveDialogDateCreatedProxy`) that fabricated a synthetic "Date Created" column via direct `createIndex()`. On Windows, `QFileSystemModel`'s async `QFileInfoGatherer` races the proxy's `mapToSource` walk, and `setProxyModel` called AFTER `setNameFilter`/`selectNameFilter` (the natural ordering) leaks dangling `QPersistentModelIndex` into the dialog's internal `QCompleter`. The completer fires on a SUBSEQUENT Save (not even the same Save As that opened the dialog), so the crash often surfaced one Save later than the action that produced it.

**The fix:** removed the proxy entirely. Deleted `src/savedialogfsmodel.{cpp,h}` and the `setProxyModel` call in `configureSaveDialogUx`. The Save As dialog keeps its 960×640 default geometry, Detail view, and Date-Modified-descending sort — just without the broken column. Lost feature: Date Created column in Save As. Reasoning: saving the user's file is the contract; a column is a nicety. The v0.1.89 comment in mainwindow.cpp had been claiming "subclass NOT a proxy" for 4 releases while the code still called `setProxyModel` — comment-vs-code drift hid the regression. New memory rule `feedback_comment_vs_code_drift` codifies the lesson.

**Bonus correctness fix:** `Editor::saveFile()` returns `bool` but three call sites (File→Save, right-click Save, closeTab unsaved-prompt) ignored the return. A read-only / AV-locked / permission-denied file silently dropped the user's edits while `updateGitGutter` + the file-watcher ran on stale data. Now wrapped with `QMessageBox::warning` on failure — user is told and the close is cancelled.

### 1.2 Multi-PID on double-click

**What was broken:** double-clicking the Notepatra launcher on Windows spawned multiple PIDs in Task Manager. End-task didn't bring them all down — an invisible orphan remained, requiring identification by tooling outside the app.

**Three root causes stacked:**
1. `QLocalServer::listen()` ran AFTER `MainWindow` construction. The constructor restores tabs / lexers / AI dock / file watcher (multi-second on a large session). Concurrent launches during that window failed the connect-probe and spawned fresh PIDs.
2. The connect-probe timeout was 300 ms — too short for cold-start Windows where Defender SmartScreen scan can stall pipe-open past that.
3. Probe-miss called `QLocalServer::removeServer(serverName)` unconditionally before `listen()` — wiping the running instance's named-pipe registration whenever any probe missed for any reason, orphaning it forever.

**The fix (main.cpp:269-378):**
1. `QLocalServer::listen()` now runs BEFORE `MainWindow` construction. The pipe is bound before slow tab restore starts.
2. Two-stage probe: 500 ms initial + 1500 ms retry. Three-quarters of a second of wait is invisible to the user; spurious "no server" is the real cost (multi-PID accumulation).
3. `removeServer()` only called if `listen()` actually fails — that's the only situation where a stale socket file is genuinely the cause. A still-alive previous instance is never orphaned.
4. Drain pending connections after wiring the `newConnection` lambda — connections accepted between `listen()` and the slot wire-up are buffered but the signal won't re-fire; we call the drain lambda once manually.

### 1.3 Invisible window after monitor change

**What was broken:** persisted window coordinates from a previous session on a now-disconnected secondary monitor (e.g. `windowX=2500, windowY=200`) restored the main window to coordinates that exist on no screen. User saw "Notepatra invisible" and double-clicked the launcher repeatedly — feeding the multi-PID bug above. The two bugs reinforced each other.

**The fix:** added `clampWindowToScreens(QRect)` in mainwindow.cpp. Every restore site (constructor's `cfg.windowX/Y/W/H` block AND `restoreSession()`'s `session.json` block) intersect-tests against `QGuiApplication::screens()`'s availableGeometry. If the requested rect doesn't overlap ANY connected monitor by at least 100 px in each axis, recenter on primary at a capped size (90% of primary's available area, with 400×300 minimum). Pre-fix guard of `cfg.windowX >= 0` was insufficient — large positive coords pass the check and still land off-screen.

## 2. Noter — full redesign

The v0.1.94 Noter feature shipped as 23 files / ~10.9k LOC with a 5-button header row, 6-button insert bar, slash menu, edge-strip icons, slide-over Notebooks + Reminders panels, and a force-disabled WebEngine path. User feedback was direct: *"unusable and cluttered, getting lost using this particular tool, no clarity on UX."*

The v0.1.95 redesign was researched against Apple Notes, Bear, Obsidian, Notion, Linear, Things 3, Granola, Mem.ai, Reflect, and Heptabase. All ten apps converged on the same pattern: **two-pane sidebar+editor, AI as one explicit button (post-meeting, not during), no slash menu, no toolbar clutter**.

### What was added

- **Date-grouped meeting sidebar** — Today / Yesterday / This week / This month / Older + Trash, all collapsible
- **Inline ✕ button on every meeting row and every todo row** — one-click move to Trash, no right-click required
- **Trash + restore for meetings** — delete moves file to `~/Documents/Notepatra/Noter/Trash/.trashed-<timestamp>-<name>.html`; restore moves it back; permanent delete sweeps the backup ring too
- **Trash + restore for todos** — `status='trashed'` (not SQL DELETE); restore brings it back; permanent delete from Trash group SQL-deletes the row
- **Markdown shortcuts in editor** — type `- [ ]` + Space → ☐; click ☐ → toggle ✓; Enter on ☐ line → new ☐; empty ☐ + Enter → break out of list; F4 toggles checkbox on current line
- **Inline @date chips planned for v0.1.96** — for now use the calendar pickers in Add-todo + right-click Set due / Set reminder
- **Calendar dropdowns everywhere** — Add-todo dialog has Text + Due (with today/tomorrow/clear quick-picks) + Remind (with in 1h / tomorrow / 1h-before-due / clear quick-picks). Right-click → Set due / Set reminder opens a `QDateTimeEdit` with `setCalendarPopup(true)` plus Clear button.
- **Inline-editable todo titles** — double-click any todo's title → `QLineEdit` → Enter commits, Esc cancels. Edit propagates back into the meeting body via text find-and-replace so the next `reindexNote()` doesn't clobber the change. `NoterTodosPanel::todoTextEdited` signal + `NotesTodos::setText()` API.
- **AI model selector** in the editor footer — auto-populates from `OllamaClient::listModels()`, persists choice to `Config::aiNoterModel`. Falls back gracefully when no backend is reachable.
- **Single ✨ Extract button** bottom-right of editor — runs `NoterSweepPrompt::build()` through OllamaClient against the whole note, shows `NoterSweepDialog` preview, on Apply inserts an "Action Items" section at the bottom.
- **Light QMenu styling forced per-instance** — Qt's QSS cascade doesn't carry QMenu rules through widgets that set their own stylesheet, so we apply `setStyleSheet` directly to each context-menu instance. Fixes the dark-on-dark right-click menu the user reported.

## 3. Tool brand-color palette unified

Previously every Notepatra tool had three color sources that drifted: tab strip (tabmanager.cpp), feature-toolbar icon (mainwindow.cpp addFeatureShortcut), and Welcome card (welcome.cpp). A typo or a forgotten edit would diverge the surfaces.

New `src/tool_colors.{h,cpp}` is the single source of truth. `notepatraToolAccent(toolKey)` returns the canonical brand color; tabmanager + addFeatureShortcut + Welcome cards all call into it. Edit one file to retint a tool everywhere.

The palette was also overhauled to 12 visibly-distinct hues spread ~30° apart across the wheel — resolving five prior collisions (AI / JSON both medium blue; HTML / Project Search both warm orange; HTML / Noter both red-orange; Noter / Git both red; Brackets / Project Search same hue):

## Out of scope

- **`@date` inline chips in the editor body** — deferred to v0.1.96. The Add-todo dialog + right-click → Set due / Set reminder cover the date-setting use case; inline chips are a polish item.
- **Trashed-meeting auto-expiry** — files in `Noter/Trash/` stay forever until user permanently deletes. A 30-day auto-purge is a sensible follow-up.
- **Per-meeting export to Markdown / PDF from sidebar context menu** — exists via Notes Export module but isn't wired to the new sidebar yet.
- **Inline AI suggestions in the editor body** — deliberately out. All 10 reference apps converged on "AI is a button, not a presence." Granola's stance: *stay present, AI helps after.*

## Memory rules established this cycle

- `feedback_qfiledialog_proxy_windows_crash` — never use `setProxyModel` to add a synthetic column to `QFileSystemModel`
- `feedback_window_geometry_must_clamp_to_screens` — always intersect-test persisted coords against connected monitors
- `feedback_single_instance_bind_before_mainwindow` — `QLocalServer::listen()` MUST precede the slow window constructor; never `removeServer()` unconditionally
- `feedback_comment_vs_code_drift` — when a comment claims a fix while the code still does the broken thing, trust the code
- `feedback_inline_editable_label_pattern` — `QStackedWidget [QLabel, QLineEdit]` for inline edit; emit signal through parent for anonymous-namespace rows
- `feedback_qt_widget_integration_test_pattern` — heavy-link sources + `QTest::keyClicks` + `$HOME` redirect for end-to-end widget testing
- `project_noter_v95_redesign` — the redesign decisions + research summary
