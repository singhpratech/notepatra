# Notepatra v0.1.28 — Dark-theme palette readability hotfix

**Released:** 2026-04-26

Four-language hotfix for v0.1.27's per-language palette. The user asked: *"palettes should be both dark and light theme compatible."* Audit revealed four languages where the dark-theme keyword colour was a navy / dark-red value that disappeared against `#1E1E1E` background.

---

## What was wrong

| Language | Old dark colour | Why it was broken |
|---|---|---|
| **Lua** | `#000080` (navy) | Pure navy on `#1E1E1E` is unreadable — text and background are both dark with similar luminance |
| **Perl** | `#39457E` (camel-blue) | Dark blue on dark grey — same problem, low contrast |
| **D** | `#B03A2E` (brick red) | Dark red on dark grey — readable but eye-strain |
| **Ruby** | `#CC342D` (brand red) | Works on light, harsh on dark |

These were copied from the language's official site / brand palette without adjusting for dark backgrounds. Brand colours optimised for light websites don't always work on `#1E1E1E` editor chrome.

---

## What was fixed

Every per-language branch in `src/npp_palette.cpp` now has proper 3-way `monokai ? ... : (dark ? ... : ...)` differentiation so the keyword + type colours are tuned independently for each theme.

| Language | Light keyword | Dark keyword | Source |
|---|---|---|---|
| **Lua** | `#000080` navy (lua.org classic) | `#4FC1FF` Lua-bright-blue | lua.org dark-mode code blocks |
| **Perl** | `#39457E` camel-blue (perl.org) | `#569CD6` VS Code blue | VS Code Perl grammar |
| **D** | `#B03A2E` brick-red (dlang.org) | `#FF6E6E` coral | brightened for dark contrast |
| **Ruby** | `#CC342D` brand-red (ruby-lang.org) | `#FF7B72` salmon | VS Code Ruby grammar default |

All four languages now also get a tuned secondary-keyword (type) colour for dark themes:
- D / Ruby: `#4EC9B0` teal types on dark, `#267F99` darker teal on light
- Perl: `#9CDCFE` light blue on dark, `#0451A5` JSON-key blue on light
- Lua: `#4EC9B0` teal types on dark, `#267F99` on light

## What's NOT changed

- **All keyword sets unchanged** — same comprehensive sets shipped in v0.1.27 for the 6 new lexers (PowerShell / Rust / Go / Swift / TypeScript / Kotlin).
- **All other 19 language accents unchanged** — only the 4 buggy ones touched.
- **Generic palette fallback unchanged** — every QScintilla built-in lexer still gets the same blue + purple defaults if not in the per-language switch.
- **No new dependencies, no schema changes, no installer changes.** Pure colour-value adjustment in one file (`src/npp_palette.cpp`).

## Upgrade path

If you're on v0.1.27 and use Lua / Perl / D / Ruby on a dark theme: upgrade. The keyword highlighting becomes visible.
If you only use light theme or other languages: optional — no behaviour change.

The in-app updater from v0.1.20+ will offer this automatically.
