# Notepatra v0.1.92 — SQL formatter deep-dive: T-SQL bracket-id preservation, MERGE / DISTINCT ON / FETCH WITH TIES support, GO + PRINT pre-mask, identifier-case fix

**Release date:** 2026-05-19

Local-iteration release: the SQL formatter (`Tools → Format SQL`) got a full audit against each dialect's official documentation and a top-to-bottom rewrite of the AST walk. No new file types / lexers / backends / installer changes. Same install commands, same artifact names, same flavor split.

The user-reported `[onelook-db-1]` regression that prompted the audit is fixed — and 9 other latent bugs found alongside it are fixed in the same release.

---

## What was broken before

The audit cross-checked our formatter against Microsoft Learn (T-SQL), postgresql.org (PG), dev.mysql.com (MySQL 8), sqlite.org (SQLite), docs.oracle.com (Oracle PL/SQL), and ANSI SQL:2016. Findings, ranked by user-impact:

| # | Symptom | Affected dialects | Root cause |
|---|---|---|---|
| 1 | `[onelook-db-1]` mangled to `[ onelook - db - 1 ]` | T-SQL | Legacy `sqlformat` fallback treated `-` as subtraction inside bracket-quoted identifiers |
| 2 | `MERGE INTO target USING source ...` collapsed to one line | T-SQL, Oracle, ANSI | Writer had no `Statement::Merge` arm; fell through to `Display` which is single-line |
| 3 | `SELECT DISTINCT ON (user_id) ...` rendered as bare `DISTINCT` | PostgreSQL | Match treated `Some(d)` opaquely; dropped the `ON (cols)` list |
| 4 | `FETCH FIRST 10 ROWS WITH TIES` dropped entirely | PostgreSQL, ANSI | `q.fetch` field never read by Writer |
| 5 | `ON DUPLICATE KEY UPDATE c = VALUES(a)` lowercased to `values(a)` AND identifiers like `Email`, `Name` mangled | MySQL, PG, SQLite | `to_lowercase()` applied to whole Display-emitted string |
| 6 | `SELECT 1 GO SELECT 2` (T-SQL batch) hit parser-fallback for the entire input | T-SQL | sqlparser-rs has no `GO` concept |
| 7 | `PRINT 'hello'` made parser drop into legacy formatter | T-SQL | sqlparser-rs doesn't recognize PRINT |
| 8 | `T-SQL OUTPUT`, MySQL aliased-row UPSERT, SQLite multi-conflict UPSERT failed to parse | T-SQL, MySQL 8.0.19+, SQLite 3.35+ | sqlparser-rs 0.52 too old |
| 9 | `[col]]name]` (T-SQL escaped `]]`) bracket-id wasn't tested | T-SQL | Test asserted only `!out.is_empty()` |
| 10 | Bracket-id test asserted nothing about positional correctness | T-SQL | Same |

## SQL formatter — concrete changes (`rust-core/src/sql_fmt.rs`)

### `sqlparser-rs` bump 0.52 → 0.55

Bringing in 3 years of upstream fixes. Breaking API churn was substantial — 13 distinct compile errors across `Statement::Update` (new `or` field, `from` now `UpdateTableFromKind` enum), `Statement::Insert.table` (now `TableObject` enum), `OrderBy` (now `kind: OrderByKind` with All/Expressions variants), `OrderByExpr` (`asc`/`nulls_first` moved into `options`), `ObjectName` (parts now `ObjectNamePart` enum), `Expr::Case` (`conditions/results` merged into `Vec<CaseWhen>`), `SelectItem::QualifiedWildcard` (now `SelectItemQualifiedWildcardKind` enum), `JoinOperator` (5 new variants — `Join`, `Left`, `Right`, `Semi`, `Anti` — for unqualified forms without OUTER), `JoinConstraint::Using` (now `Vec<ObjectName>` not `Vec<Ident>`). All migrated.

### `Statement::Merge` Writer arm — Layout

```text
MERGE INTO Target AS t
USING Source AS s
    ON t.id = s.id
WHEN MATCHED THEN
    UPDATE SET t.name = s.name
WHEN NOT MATCHED THEN
    INSERT (id, name) VALUES (s.id, s.name)
```

Each `WHEN MATCHED` / `WHEN NOT MATCHED [BY TARGET|SOURCE]` clause goes on its own line with the action body (`UPDATE SET ...`, `DELETE`, `INSERT ...`) indented one level. Predicates (`WHEN MATCHED AND <expr> THEN ...`) preserved.

### `DISTINCT ON (cols)` — PostgreSQL

`Distinct::On(exprs)` variant now expands as `SELECT DISTINCT ON (col1, col2, ...)` instead of bare `DISTINCT`. The `Distinct::Distinct` variant unchanged. Affects T-SQL via `(Some(top), Some(d))` formatting path too — TOP + DISTINCT ON works for the rare hybrid.

### `FETCH FIRST N ROWS [PERCENT] [WITH TIES | ONLY]`

New `fmt_fetch()` helper emits the SQL:2008 form on its own line after OFFSET. Supports the `ROWS ONLY` (default) and `ROWS WITH TIES` (PG, ANSI) variants, and the PERCENT modifier.

### T-SQL `GO` batch separator — pre-split

New `split_tsql_go_batches()` walks the input with full string/comment-state tracking and splits on lines that contain only `GO` (case-insensitive, leading/trailing whitespace allowed). Each batch parses + formats independently. Re-emits `GO` between batches.

### T-SQL `PRINT` statement — pre-mask

New `protect_print_statements()` / `restore_print_statements()` pair. Captures `PRINT <expr>` at statement boundaries (file start or post-`;`) through the next `;` or newline, replaces with a parseable `SELECT '__NP_PR_N__'` placeholder, restores verbatim after format. String-state aware so `'PRINT'` inside a literal doesn't trigger.

### Bracket-identifier masking (carried forward from v0.1.91)

`protect_bracket_identifiers()` / `restore_bracket_identifiers()` — already in place from v0.1.91 — now also covers the user-reported `[onelook-db-1]` regression and `[col]]name]` (T-SQL `]]` escape for literal `]`). Test hardened: was `!out.is_empty()`, now positional + verbatim-content assertions.

### Identifier-case fix in ON CONFLICT / MERGE INSERT

New `apply_keyword_case()` helper replaces previous `.to_lowercase()` whole-string calls on `Display`-emitted fragments. Walks token-by-token:

- Single-quoted strings → verbatim
- `"..."`, `` `...` ``, `[...]` quoted identifiers → verbatim
- Identifier-like words matched against a sorted list of 78 SQL reserved words → case applied
- Everything else (function names not in keyword list, identifiers) → preserved

Eliminates: `INSERT INTO Users (Email, Name) VALUES (...) ON CONFLICT (Email) DO UPDATE SET Name = EXCLUDED.Name` no longer mangles `Email`/`Name` to lowercase in lowercase-keyword mode; MySQL `VALUES(a)` no longer mangles to `values(a)` in mixed-case mode.

## What's still in the fallback path (deferred to future release)

| Dialect | Construct | Plan |
|---|---|---|
| T-SQL | `OUTPUT INSERTED.* INTO @v` clause on UPDATE/DELETE/MERGE | Needs `Statement::Update.output` field — present in 0.55, but Writer arm not yet built. v0.1.93 candidate. |
| MySQL 8.0.19+ | `INSERT … AS new(m,n,p) ON DUPLICATE KEY UPDATE c=new.a+new.b` | sqlparser parses it but the Writer's `ins.on` path uses `Display` directly. v0.1.93 candidate. |
| SQLite 3.35+ | Multiple `ON CONFLICT` clauses | sqlparser-rs limitation — single conflict only in 0.55. Upstream fix tracked. |
| Oracle | `CONNECT BY PRIOR … START WITH`, `(+)` outer-join | No real `OracleDialect` in sqlparser; uses `GenericDialect`. Would need pre-rewrite. |
| All | DDL (`CREATE TABLE`, `ALTER`) | Falls through to `Display`. Single-line output. v0.1.94+ candidate. |
| All | EXPLAIN, DCL (`GRANT`, `REVOKE`) | Same. |

These all still produce *correct* output (parsed, re-emitted) — just not multi-line. The graceful-fallback `-- (parser fallback: ...)` comment surfaces when even sqlparser refuses; rare with the 0.55 bump.
