# Notepatra v0.1.88

**Save As file-type dropdown now actually drives the saved extension.**

## What changed

v0.1.87 shipped a ~72-entry Save As file-type dropdown, but the user-reported the same day that picking "Python" and typing `foo` still saved as `foo` (no extension) — the dropdown was populated, but `QFileDialog::setDefaultSuffix` was never wired so the selected filter didn't actually drive the extension. v0.1.88 fixes the end-to-end contract.

## The fix

Five changes wire Qt's auto-extension API end-to-end, force the dialog that fires the signals reliably, and re-apply the lexer when the extension changes:

1. **`QFileDialog::setDefaultSuffix` is set at init from the preselected filter.** Picking "Python (*.py *.pyw *.pyx)" sets the suffix to `py`; typing `foo` and clicking Save produces `foo.py`.
2. **The `filterSelected` signal keeps the suffix in sync** when the user switches filters mid-dialog. Switching to "Rust (*.rs)" mid-flow updates the suffix to `rs`.
3. **`QFileDialog::DontUseNativeDialog`** — without this, the GTK / KDE / native Windows dialog silently DROPS the `filterSelected` signal AND returns a stale `selectedNameFilter()` after Accept, so even with (1) and (2) wired correctly, picking JavaScript and typing `foo` would save as `foo.txt` (the suffix from the initial Plain Text filter). Forcing Qt's own non-native dialog makes the signals fire reliably across every platform — same dropdown UX.
4. **Post-Accept safety net** — `applySaveAsFilterSuffix(path, filter)` runs after Accept and appends the first `*.ext` pattern's extension if the path doesn't already end with one of the filter's extensions. Bare-name filters (Dockerfile, CMakeLists.txt, .gitignore) and the "All Files (*)" filter are correctly left alone.
5. **`Editor::saveFile()` re-applies the lexer when the path's extension implies a different language.** Pre-fix, Save As .txt → .cpp saved the bytes correctly but the editor kept Plain Text indefinitely (no syntax highlighting, status bar still said "Plain Text") until the user re-opened the file. Now `m_filePath` change triggers `detectLanguageFromPath(newPath)` and `applyLexer(newLang)` — syntax highlighting, status bar, and language menu all flip together live.

| Scenario | v0.1.87 | v0.1.88 |
|---|---|---|
| Save As → pick Python → type `foo` | `foo` (no extension) | `foo.py` |
| Save As → pick Python → type `foo.py` | `foo.py` | `foo.py` (unchanged) |
| Save As → pick Python → type `foo.txt` | `foo.txt` | `foo.txt.py` (filter wins) |
| Save As → pick All Files → type `foo` | `foo` | `foo` (unchanged) |
| Save As → pick Dockerfile → type `Dockerfile` | `Dockerfile` | `Dockerfile` (bare-name match) |
| Save As .txt tab → pick C++ → save | bytes saved, editor stays Plain Text | bytes saved, editor flips to **C++** live (syntax highlighting + status bar) |

Same fix applied to the close-tab "Save before close?" prompt (`closeTab()`).

## The meta-lesson

v0.1.87 tested "the function returns 72 entries" and assumed the rest. v0.1.88 codifies — in a regression test — the actual user contract: **"select Python → save → file ends in .py"**. Saved as `feedback_test_the_user_visible_contract_not_proxies.md` so the next bug fix gets a contract test instead of a proxy test.

## Out of scope

- No other v0.1.87 functionality changed (UTF-8 fast path, EOL bound, Box<[u8]> FFI, large-file UX gates all unchanged).
