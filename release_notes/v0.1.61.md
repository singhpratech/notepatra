# Notepatra v0.1.61 — UX overhaul: smarter gating, vision drops, coding redesign

**Date:** 2026-05-10
**Tag:** `v0.1.61`
**Build:** Linux x64 / Linux ARM64 / macOS Apple Silicon / Windows x64

A user-driven session — 13 distinct improvements landed, plus three bonus chrome consolidations. Coordinated by five parallel agents (four research, two implementation in isolated worktrees). Items 9 (data charts) deferred to v0.1.63 with a complete library-evaluation report; v0.1.62 will deliver the VS Code-parity Git Source Control in Coding mode.

---

## What changed

### Item 1 — Smart input gating

The AI dock's text input and Send button now auto-enable the instant a model probe completes. v0.1.59 introduced gating but raced `setEnabled(true)` against `currentTextChanged`, so the input stayed disabled until the user wiggled the dropdown or pressed Reset. v0.1.61 installs an event filter on `m_modelCombo` for `QEvent::EnabledChange` — every enable transition retriggers `updateInputAvailability()`, eliminating the dead state.

Placeholders rewritten to be action-oriented. Each disabled state now teaches the exact fix:

* **Ollama offline** — *"Open a terminal and run `ollama serve`, then click ↻ Refresh. Or switch the backend dropdown to llama.cpp / OpenRouter / OpenAI / Azure to use a different runner."*
* **No models installed** — *"Run `ollama pull qwen2.5-coder:7b` for code work (~5 GB), or `ollama pull llama3.2:3b` for a lightweight chat model (~2 GB). Then click ↻ Refresh above."*
* **API key required** — *"Click ⚙ Settings (top of the AI dock) to paste your key for OpenRouter / OpenAI / Azure / Ollama Cloud, save, and pick a model from the dropdown."*
* **Detecting** — *"Detecting available models… If this hangs, click ↻ Refresh or switch the backend dropdown."*

### Item 2 — Git toolbar button dropped (MVP)

The standalone red "Git" feature-shortcut on the toolbar is gone. Plugins → Git Integration (inbuilt) still opens the existing tab-based Git panel. Full VS Code-parity Source Control inside Coding mode lands in v0.1.62 — the research is complete (per-hunk gutter popup with Stage/Revert, atomic `git apply --cached` synthesis, branch picker, sync, conflict resolution helper) and 90% of the existing infrastructure (gutter markers, `CompareWidget`, `GitGutter::getChangedLines`) carries directly.

### Item 4 — Context gates at sendPrompt

The pre-send guard now refuses doomed requests with friendly assistant cards:

* **Coding mode without a workspace** — pointer to File → Open Folder…
* **Data mode without a saved DB connection** — pointer to Manage Connections, with hint about DuckDB for raw CSV/Parquet files.

### Item 5 — Copy buttons on user messages + auto-scroll

Both the widget-rendered chat bubble (during streaming) and the HTML-rendered transcript (history reload) now expose a `⧉ copy` link below each user message — matching the assistant card's long-standing copy button. The HTML path routes through the existing `copy://message/N` handler in `handleChatLink`. The widget path uses a direct `QApplication::clipboard()->setText(...)` connect. Auto-scroll was already wired across renderTranscript and streaming-token-append paths — verified end-to-end in this release.

### Item 6 — File explorer is Coding-mode-only with hide/unhide

The file-explorer dock now appears only when **Coding mode is active**. Toggle Coding ON → explorer shows. Toggle Chat or Data → explorer hides; the editor takes the full width. Right-click any folder or file in the tree → **Hide "X"** adds the path to a per-workspace hidden-list (persisted via `Config::explorerHiddenPaths`). **Show hidden (N)** clears the list. Implemented via a new `HiddenPathProxy : QSortFilterProxyModel` that filters by absolute-path set. Four show-sites (File → Open Folder, View → Folder as Workspace toggle, GitPanel `repositoryOpened`, `toggleAiDock`) are gated so the explorer only auto-surfaces when Coding mode is active in a visible dock.

### Item 7 — Ctrl+N in fullscreen creates background tabs

Verified — pressing `Ctrl+N` while the AI dock is in fullscreen mode creates a new editor tab without exiting fullscreen. The tab is positioned in the (hidden) editor area; when the user later restores split layout (toggle Chat mode), the tab is visible and active. Lexers auto-attach by extension when the file is saved.

### Item 8 — Coding area redesigned: single panel + bottom segmented toggle

The biggest UI change. The old QTabWidget split between "Chat" and "Composer" tabs is **gone**. The AI dock now hosts **one unified conversation surface** with a **3-segment toggle at the bottom** of the panel:

```
┌─────────────────────────────────────────────┐
│  …conversation messages, tool cards,        │
│   edit plans, streaming stats…              │
├─────────────────────────────────────────────┤
│  > Type a message…                          │
├─────────────────────────────────────────────┤
│   ●Chat       ○Compose       ○Agent         │
└─────────────────────────────────────────────┘
```

**Why**: research across Continue.dev, Copilot Chat, Cursor 3.0, and Cody showed top tabs implied page-navigation semantics (settings panel) while bottom segmented controls map to the iOS/Slack keyboard-accessory model — mode is a property of the next message, not a destination. The same QSS pattern as the existing Chat/Coding/Data mode pills is reused, with a `ChatModeSegment` enum (`Chat=0`, `Compose=1`, `Agent=2`) replacing the old `m_chatTabs->currentWidget()` checks. `m_editPlan` is now reparented to `m_chatContent` and hidden by default, surfaced inline in the conversation flow whenever the agent emits a `dry_run` write_file / apply_diff call.

`composerActive` (which forces `dry_run: true` on write tools) is now keyed off `m_chatModeSegment == Compose` — independent of intent — so users can drive Composer-style edits even outside Coding intent if they explicitly opt in.

### Item 10 — Vision drag-drop with capability detection

Drag any image (PNG, JPG, WEBP, GIF, BMP) or document (PDF, DOCX, PPTX) onto the AI dock and Notepatra will auto-detect whether the currently-selected model supports vision. If it doesn't, the drop is refused with a styled error bubble:

> 🖼 Can't attach **`<filename>`** — **`<model>`** doesn't support image input.
>
> Switch to a vision-capable model, then drop the image again:
> - **Local (Ollama)**: `ollama pull qwen2.5vl:7b` or `ollama pull gemma3:4b`
> - **Cloud**: pick `claude-sonnet-4-6`, `gpt-5`, or `gemini-2.5-flash` from the model dropdown.

**Detection strategy** (per a three-tier survey of Ollama + cloud APIs):

* **Ollama**: trust the `/api/show` capability cache (already wired in v0.1.55 as `m_ollamaModelCaps`). If the cached caps list contains "vision", the model is vision-capable. **Conservative-false** when the cache is empty — silent-drop on non-vision Ollama is the worst trap.
* **Cloud / OpenAI-compat / Anthropic / Gemini**: prefix allowlist (May-2026 accurate) — `claude-3.5+`, `claude-4+`, `gpt-4o`, `gpt-4.1+`, `gpt-5`, `o4-*`, `gemini-1.5+`, `gemini-2+`, `gemini-3+`, plus Ollama vision tags (`qwen2.5vl`, `llava`, `gemma3`, `llama3.2-vision`, `minicpm-v`, `moondream`, `mistral-small3.1`).

Drag-and-drop is enabled on the whole AI panel via `setAcceptDrops(true)` + `dragEnterEvent`/`dropEvent` overrides. The `attachFile()` happy-path (file dialog button) goes through the same `acceptAttachment()` helper for the capability gate, so both entry-points share refusal logic. PDF/DOCX/PPTX drops still flow through the existing `extractFileContent` text-extraction path — Poppler-based PDF→PNG rendering for vision models is on the v0.1.62 roadmap.

### Item 11 — Runtime "wrong model" responses

Before dispatching a request, sendPrompt now checks the model's capability against the user's mode:

* **Coding mode + non-tool-capable model** → refusal card naming alternatives: *local* `qwen2.5-coder:7b` / `qwen2.5-coder:14b` / `llama3.1:8b` / `mistral-nemo`; *cloud* `claude-sonnet-4-5` / `claude-opus-4-7` / `gpt-5` / `gpt-4o` / `gemini-2.5-flash`.
* **Data mode + insufficient model** → recommend local `qwen2.5-coder:14b` (or 7b / `deepseek-coder:33b`), or cloud `claude-sonnet-4-5` / `gpt-5` / `gemini-2.5-pro` / `deepseek-r1`.

These complement the existing amber-vs-green dropdown coloring — the runtime guard catches the case where a user picks an amber model anyway.

### Item 12 — Parallel agents used aggressively

The release was coordinated by **four research agents** (VS Code git architecture, chat-panel UI patterns, vision-model API survey, charting library evaluation) and **two implementation agents in isolated worktrees** (item 8 coding redesign, item 10 vision drag-drop), plus a separate test-scenarios author. Research reports inform v0.1.62 (git, vision PDF rendering) and v0.1.63 (charts). Implementation worktrees branched off the v0.1.60 base, then their branches were merged back into `feature/v0.1.61-bigfeatures` — both auto-merged cleanly without conflict.

### Item 13 — 38-case manual test plan

A structured test plan covering Sections A (14 golden-path user journeys), B (edge cases per feature), C (regression hot spots), D (performance smoke), E (template) is included with this release. The plan is the verification baseline before any future Coding-mode feature lands.

### Bonus chrome consolidations

* **Coding and Data modes auto-fullscreen.** Toggling Coding or Data ON expands the AI dock to take the full window (v0.1.57 did this for Coding only). Switching back to Chat restores the previous split layout.
* **Hide ⛶ expand button in Coding/Data.** Those modes are AI-first; the only chrome button is ✕ close. The user exits fullscreen by toggling back to Chat. (Chat mode keeps the ⛶ toggle as before.)
* **Hide 🔒 Share file checkbox in Chat / Data.** The "Share file with AI" toggle controls whether the open editor file ships with the prompt — meaningful only in Coding mode. Chat and Data modes don't have an open-file concept worth gating, so the toggle now appears only when Coding mode is active.
