# Notepatra v0.1.128

**The editor now generates passwords, and the strength number it shows is a count rather than an opinion.**

One new built-in tool. It opens from the Built-in Tools toolbar — the **Password** button, third, immediately after **AI** — or from Tools → "Password Generator — Random / Passphrase", and it is a toggle: press it again while the "Password Generator" tab is focused and the tab closes.

It ships in every build, including the default Lite binary, and it adds no dependency: the randomness comes from Qt Core. No network, no download, no backend, no AI. It works fully offline.

## Two modes

**Random characters.** Length 4 to 256, default 20, over a-z, A-Z, 0-9 and Symbols, plus a free-text "extra characters" field for anything else you want in the alphabet (whitespace and control characters are ignored). Optional "Exclude look-alikes" drops `0 O 1 l I`. "At least one from each set" is on by default. Default settings report 129 bits.

The symbol set is 27 characters:

```
! # $ % & ( ) * + , - . / : ; < = > ? @ [ ] ^ _ { } ~
```

It leaves out the single quote, double quote, backslash, backtick, pipe and space on purpose. Those are the characters that break when a password is pasted into a shell command, a YAML file or a database connection string — the places a generated password actually goes.

**Passphrase.** 3 to 24 words, default 6, drawn from a built-in 2,048-word list, so each word is worth exactly 11 bits and six words is 66 bits. The wordlist is compiled into the binary; no dictionary file is read at runtime. Separator is hyphen, period, underscore, space or none, with optional "Capitalise each word" and optional "Append two digits", which adds log2(100) bits.

Both modes generate 1 to 100 independent values at once, with Generate, Copy, Insert into editor and Open in new tab.

## Why the bits number goes down when you tighten the settings

The figure the panel shows is the base-2 logarithm of how many distinct values the current settings can produce. It is not a heuristic score of how complicated the result *looks*, which is what most password meters show.

So tick "At least one from each set" and the number **drops** slightly. That is correct, and it is the part worth understanding: the guarantee rules out every password that happens to miss a set, so there are fewer possible passwords than before, not more. The figure is computed by inclusion-exclusion over the selected sets. Most generators advertise the unconstrained count while enforcing the constraint, which overstates the result.

The same honesty constrains how the values are drawn:

| Choice | What Notepatra does | Why the alternative would make the number wrong |
|---|---|---|
| Source of randomness | `QRandomGenerator::system()`, Qt's cryptographic generator — on x86-64 that is the CPU's **RDRAND** instruction first, with the OS entropy pool (`getentropy`/`getrandom`, `RtlGenRandom`) as fallback. Measured: ~7M draws, *zero* `getrandom` syscalls | The seeded `global()` generator is predictable from its seed, so the count of possible values would not be the count of *reachable* values |
| Mapping bytes to characters | Rejection sampling | Taking a modulo makes some characters likelier than others whenever the alphabet size does not divide 2^32 |
| Enforcing "one from each set" | Draw again until the constraint holds | Placing one character from each set and shuffling makes some strings likelier than others, and makes the bits figure a lie |

The re-draw approach is what lets inclusion-exclusion be the right maths: every password satisfying the constraint remains equally likely.

## What it deliberately does not do

Nothing generated is written to disk.

The panel is a plain widget, not an editor. Session save/restore, the AI-context sweep and the MCP read verbs are all gated on the tab being an editor — so a generated value is never written to `session.json`, never sent to an AI backend, and not readable by a connected MCP client. No MCP verbs were added for this release; the tool count stays 49.

Copy puts the value on the system clipboard and takes it back after 30 seconds — but only if the clipboard still holds that value, so it will never clobber something you copied in the meantime.

What it does **not** claim is that the value is wiped from memory. Qt strings are copy-on-write and cannot be reliably wiped, so the UI does not pretend otherwise.

## Everything tells you what it is

Every control in the panel carries a hover explanation — both mode radios, the
length slider, each character set, the look-alike and one-of-each switches, the
word count, the separator, the readout, the strength meter, and both section
boxes. Several of them exist to tell you what a setting does *not* buy you: a
fixed separator and blanket capitalisation add no entropy, because neither is a
random choice, and the tooltips say so rather than letting the layout imply
otherwise.

One rendering bug is worth naming because it is easy to repeat. The spin-box
arrows first shipped as solid black squares: the stylesheet used the CSS
border-triangle idiom, `width: 0` with transparent side borders, which a browser
draws as a triangle and Qt's stylesheet engine draws as a filled box — and which
would not have looked native on Windows or macOS regardless. Spin boxes and
combo boxes are now kept out of the stylesheet and themed by palette, so the
platform style keeps drawing its own arrows.

The same defect existed in two older panels and is fixed here too: the SQL
Formatter's *Indent* spinner had no arrows at all, and the REST Client's method
combo had none either. A source lint now reads `src/*.cpp` and fails the build
on any of the three shapes that cause it, so a panel added later cannot bring
it back.

## Verification

78 C++ suites on the Full build (74 on Lite), up from 76 and 72. The two new suites are `test_passwordgen`, covering the entropy maths and the CSPRNG draw paths, and `test_passwordgen_panel`, covering the widgets. Full offscreen `ctest` is 78/78 green.

The session-privacy claim was checked the direct way rather than by reading the gating code: `session.json` was inspected with the Password Generator tab open and focused, and it recorded zero tabs.
