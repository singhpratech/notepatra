# v0.1.59 — Input gating when no model is ready + author-link refresh

**Release date:** 2026-05-10 · **Platforms:** Linux x64 / ARM64 · macOS Apple Silicon · Windows x64 · **Bare binary:** ~9 MB stripped

Two small but high-touch UX fixes. Nothing changes about how Notepatra runs when a model is online — but the dock now refuses to silently swallow keystrokes the moment the dropdown is in a placeholder state, and the "Prateek Singh" credit on the website footer + the in-app About dialog finally points at the author's blog instead of a bare GitHub profile.

## ⌨️ Chat input is disabled when no model is selected

Until now the chat input was always editable even when the dropdown read `(detecting…)`, `(Ollama offline)`, `(no models installed)`, or `(API key required)`. Pressing Send while in that state ran a defensive guard inside `sendPrompt()` that cleared the chat and printed an error bubble — correct, but the user only learned about it after they'd typed and hit Send.

v0.1.59 gates the input + Send button on the dropdown's visible state across all three modes (Chat / Coding / Data):

- `m_modelCombo->currentTextChanged` → `AIPanel::updateInputAvailability()`.
- A "real model" is the dropdown both being enabled and showing a label that isn't wrapped in parens. Every placeholder/error entry in this file already follows the `(...)` convention (`(detecting…)`, `(Ollama offline)`, `(no models installed)`, `(API key required)`, `(no model)`), so one helper covers every case without touching the nine `setEnabled(false)` call sites scattered across the constructor + probe handlers.
- When not ready, `m_customInput->setEnabled(false)` and a state-specific placeholder explains *why*:
  - `Ollama is offline — start it ('ollama serve') and click ↻ Refresh.`
  - `No models installed — 'ollama pull qwen2.5-coder:7b' then click ↻.`
  - `API key required — open ⚙ to add one, then pick a model.`
  - `Detecting available models…` (during in-flight probe)
- The Send button now has a `:disabled` style that drops the label opacity to 45% so the dock visibly tells the user the action is unavailable, not just unresponsive.

The existing defensive guard at `aipanel.cpp:2747` (clearChat + error bubble on bad model) stays as a backstop in case anything bypasses the new gating.
