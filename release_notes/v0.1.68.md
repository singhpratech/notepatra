# Notepatra v0.1.68 — AI dock auto-exits fullscreen on editor tab switches too

**Date:** 2026-05-10
**Tag:** `v0.1.68`
**Build:** Linux x64 / Linux ARM64 / macOS Apple Silicon / Windows x64 — both lite and Linux-full flavors

A focused follow-up to v0.1.67 closing the remaining auto-exit gap.

---

## The gap v0.1.67 left

v0.1.67 added `MainWindow::exitAiFullscreenIfActive()` and wired it into 14 **tool-tab** open sites (Project Search, Terminal, Git, REST Client, SQL Formatter, JSON/HTML/Bracket Tools, Compare, Welcome). That fixed the case where clicking a left-rail tool button while the AI dock was fullscreen left the new tab buried under the dock.

**But it didn't cover editor-tab switching.** Pressing `Ctrl+Tab`, clicking a tab in the tab bar, double-clicking a Project Search result, or opening a file via `File > Open` while the AI dock was fullscreen still left the newly-focused tab hidden behind the dock — the focus shift was real but invisible, so the editor felt frozen.

## The fix

`src/mainwindow.{h,cpp}` — instrument the `QTabWidget::currentChanged` signal directly so **every** tab-focus change, however it's triggered, calls `exitAiFullscreenIfActive()`.

A naive hook would have broken the v0.1.61 background-tab UX rule (Ctrl+N while AI fullscreen should keep the dock fullscreen and create the new tab in the background so the user doesn't lose AI flow). So the fix is gated by a one-shot flag:

```cpp
// mainwindow.h
bool m_skipAiAutoExitOnNextTabChange = false;
```

```cpp
// mainwindow.cpp — currentChanged slot
if (m_skipAiAutoExitOnNextTabChange) {
    m_skipAiAutoExitOnNextTabChange = false;
} else {
    exitAiFullscreenIfActive();
}

// mainwindow.cpp — newFile() (Ctrl+N) sets the skip flag right before
//                  the programmatic setCurrentIndex so the background-
//                  tab create-flow is preserved.
m_skipAiAutoExitOnNextTabChange = true;
m_tabs->setCurrentIndex(idx);
```

`openFile()` deliberately does **not** set the skip flag — when the user explicitly opens a file (File > Open, double-click in file tree, double-click search result), the expectation is that the new file becomes visible. So those paths correctly collapse the fullscreen dock.

## Coverage matrix after this fix

| Action while AI dock is fullscreen | v0.1.66 | v0.1.67 | **v0.1.68** |
|---|---|---|---|
| Click a tool button (Project Search, Terminal, Git, …) | no effect | dock collapses ✓ | dock collapses ✓ |
| `Ctrl+Tab` to switch editor tab | no effect | no effect ✗ | **dock collapses ✓** |
| Click a tab in the tab bar | no effect | no effect ✗ | **dock collapses ✓** |
| `File > Open` / double-click search result / double-click file in tree | no effect | no effect ✗ | **dock collapses ✓** |
| `Ctrl+N` (new editor tab) | no effect | no effect (intentional) | no effect (intentional — preserves v0.1.61 background-tab UX) |
| Hex Editor (opens as modal dialog) | n/a | n/a | n/a |

The 14 explicit `exitAiFullscreenIfActive()` calls inside the tool-tab handlers from v0.1.67 are now technically redundant (the `currentChanged` hook would also fire when the new tool tab becomes current), but they remain in place as no-ops because the helper short-circuits when fullscreen isn't active. Belt-and-braces.

## Tests

All 26 deterministic regression tests pass on the lite build (`build-lite/` with `BUILD_TESTING=ON`). The behavior is UI state machine that the headless test suite doesn't exercise, so verification is by audit: every `setCurrentIndex` call site in `src/mainwindow.cpp` was reviewed (50+ sites) — only `newFile()` needs the skip flag and has it; every other site correctly auto-exits because they represent user-initiated focus changes.

## Files changed

* `src/mainwindow.h` — new `bool m_skipAiAutoExitOnNextTabChange = false;` member with inline rationale explaining the v0.1.61 UX rule it protects.
* `src/mainwindow.cpp` — `QTabWidget::currentChanged` slot consumes (and resets) the flag, otherwise calls `exitAiFullscreenIfActive()`. `newFile()` sets the flag immediately before `setCurrentIndex` to preserve the Ctrl+N background-tab create-flow.
