## Editor — per-line change-history strip (Notepad++ style)

Margin 3 now paints a thin per-line strip: **orange** on lines edited since the last save, **green** on lines that have been edited and persisted at least once this session. Notepad++ users will recognise the behaviour exactly.

- **Why manual implementation, not `SCI_SETCHANGEHISTORY`:** Ubuntu 24.04's `libqscintilla2-qt5-15` 2.14.1+dfsg-1build3 ships Scintilla compiled WITHOUT change-history support (the message round-trips as a no-op, `SCI_GETCHANGEHISTORY` always reads 0 regardless of input — confirmed via PyQt5 round-trip). Notepatra now tracks per-line state itself via Scintilla's regular `SCN_MODIFIED` / `SCN_SAVEPOINTREACHED` / `SCN_SAVEPOINTLEFT` notifications, which every QScintilla build exposes.
- **Visual:** `QsciScintilla::FullRectangle` marker shape so only the 4 px margin column paints — never the whole line. Margin 3 marker mask constrained to bits 21–24 via `SCI_SETMARGINMASKN` so the bookmark margin stays clean.
- **Pre-v0.1.91 bug it replaces:** earlier git-diff-driven gutter painted **whole-line backgrounds** because the marker shape was `Background`, AND marked **every line** of an untracked file as "added" (Notepad++ correctly paints untracked files as nothing). Three compounding bugs filled markdown drafts with a wall of green. Switching to Change-History semantics eliminates all three.
- **Safety nets:**
  - `m_loadingFile` flag wraps every wholesale `setText()` so the file-open path doesn't paint every line orange.
  - `SCN_MODIFIED.line` parameter is unreliable in QScintilla 2.14.1 (only filled for fold events) — `onScintillaModified()` recomputes line from `position` via `SCI_LINEFROMPOSITION` when `line <= 0`.
  - `onSavePointReached()` does `markerDeleteAll(23)` as belt-and-braces (no orange survives a save regardless of state sync), then paints green on every tracked line, then a full widget `update()` to force the margin repaint on X11 compositors that don't synthesise margin paint events from marker state changes alone.

## Cross-platform paths — holistic `QDir::toNativeSeparators` sweep

Every UI surface that displays a filesystem path now wraps the value in `QDir::toNativeSeparators(...)`. On Linux/macOS this is a no-op (the native separator IS `/`); on Windows it converts to `\` so users see `C:\Users\name\file.txt` instead of Qt's internal `C:/Users/name/file.txt`.

## Status bar — per-tab change-line counter

The status bar gains a new label `N modified  ·  M saved` between the cursor-position field and the EOL/encoding fields. Visible when either count is non-zero, hidden otherwise (no visual noise on freshly-loaded files).

- `modified` = lines edited since the last save (orange marker count).
- `saved` = lines that have been edited at some point this session AND already persisted to disk (green marker count). Reset to zero on file reload.
- Implementation pattern: Editor keeps two parallel `QSet<int>` members (`m_modifiedLines`, `m_savedLines`) in lockstep with markers 22/23, emits a single `changeHistoryUpdated()` signal at the end of every mutating handler. MainWindow connects the signal to a tab-aware lambda that updates the status bar only if the affected editor is the current tab. Counters are O(1) — no buffer-walking, no marker iteration on every cursor move.

**Test:** `test_changehistory_statusbar` — 14 assertions across 6 scenarios (fresh load → label hidden; edit → `1 modified · 0 saved`; save → `0 modified · 1 saved`; edit different line → `1 modified · 1 saved`; re-edit saved line → `2 modified · 0 saved` (green count drops because the saved line lost its green); save again → `0 modified · 2 saved`).

Files: `src/editor.{h,cpp}`, `src/statusbar.{h,cpp}`, `src/mainwindow.cpp`.

## Find / Replace dialog — bottom status bar, tab carry-forward, two-step wrap

Three independent improvements to the Find/Replace modal:

### 1. Notepad++-style bottom status bar

A single italic status line at the bottom of the dialog (under the tab widget) reports the result of every action: Find Next, Count, Find All in Current, Find All in All Opened, Replace, Replace All, Replace All in Opened, Mark All, Find in Files. Blue (theme accent) for success messages; red (theme `errorFg`) for "Not found" / "No editor tab" / "Reached end of document". Word-wraps to a second line if the message is long.

Before v0.1.91 the Find tab's grid had an in-tab `m_resultLabel` visible only when the Find tab was active; the Replace tab's results targeted a `m_resultsOutput` field that had been set to `nullptr` (v0.1.48 cleanup), so Replace All / Replace All in Opened / Find in Files results **silently dropped on the floor**. The new bottom bar is now the single source of truth for every tab; the in-tab `m_resultLabel` is hidden.

### 2. Find ↔ Replace string carry-forward

Switching from Find to Replace (or vice-versa) now copies the search string into the destination tab's "Find what" field — provided the destination is empty. Never clobbers a value the user has already typed into the other tab. Hooked into `QTabWidget::currentChanged`; the non-clobber guard is critical and is covered by a dedicated test scenario.

### 3. Two-step wrap at cycle end

Iterating Find Next through all matches no longer silently wraps. When you reach the last match, the next Find Next press **stops** with `"Reached end of document — press Find Next again to wrap to top"` (red). The cursor stays put. The SECOND consecutive Find Next press actually wraps and resumes from the top with `"Search wrapped — resumed from top"`. Same behaviour for Find Previous in the reverse direction.

State (`m_atFindCycleEnd`, `m_lastFindText`, `m_lastFindForward`) is reset on text change or direction flip — typing a new needle starts a fresh cycle. Honours the existing `m_wrapAround` checkbox: if the user has explicitly turned wrap off, just report "Reached end" without offering to wrap.

**Test coverage:** `test_findreplace_carry_forward` — 20 assertions across 5 scenarios covering carry-forward (Find→Replace), reverse-direction carry-forward (Replace→Find), non-clobber on re-switch, dialog status bar fires on Find Next + Replace All, and the full Find Next cycle (3 matches → 3 "Found" → "Reached end" → "Search wrapped" → cursor jumped back to line 0).

Files: `src/findreplace.{h,cpp}`.
