# Notepatra v0.1.98 — Windows in-app updater fixed

**Release date:** 2026-05-25

v0.1.96 added a guard that hard-disabled the in-app update check whenever it detected an "end-of-life" OpenSSL runtime (1.0.x / 1.1.x). That guard was a misdiagnosis: it shows Windows users an *"In-app update check disabled"* dialog and never checks for updates — even though the bundled **OpenSSL 1.1.1w** connects to GitHub's TLS endpoint perfectly fine. v0.1.98 removes the gate, so **Check for Updates works again on Windows**.

---

## What was broken

On Windows, **Help → Check for Updates** (and the silent startup check) popped *"In-app update check disabled — this build ships an end-of-life OpenSSL runtime"* and stopped. The only path forward was opening the Releases page in a browser and downloading the MSI by hand.

## Root cause

The v0.1.96 guard blamed a launch-time hang on the OpenSSL 1.1 TLS stack and hard-skipped the update check on any 1.0.x/1.1.x runtime. But:

- **"EOL" ≠ "broken."** OpenSSL 1.1.1w (the version Notepatra's Windows build bundles) speaks the modern TLS that `api.github.com` requires. The handshake succeeds.
- **The real v0.1.96 launch hang was unrelated** — it was the session-restore loop, which v0.1.96 already fixed separately.
- **The update check was never the risk the guard imagined.** It is already asynchronous (`QNetworkAccessManager`), already bounded by an **8-second abort timer**, and already guarded by `QSslSocket::supportsSsl()`. None of those can hang the UI.

So the gate disabled a working feature for every Windows user and protected against nothing.

## The fix

`src/mainwindow.cpp` — `checkForUpdates()` drops the `eolOpenSSL` hard-disable block entirely. The remaining, sufficient safety net stays exactly as it was:

| Guard | What it covers |
|---|---|
| `QSslSocket::supportsSsl()` early-return | no OpenSSL present at all → one-click "Open Releases Page" |
| async `QNetworkAccessManager::get()` | never blocks the UI thread |
| 8-second abort `QTimer` | a slow/stalled request can't hang — it's aborted and reported |
| TLS-aware error handler | a genuine SSL failure still offers the browser fallback with a readable reason |

## One-time manual step for current Windows users

The gate lives in the binary you're already running (v0.1.96 / v0.1.97), so those builds still can't auto-update themselves. Download **v0.1.98 once** from the Releases page (or click *Open Releases Page* in the dialog). From v0.1.98 onward, **Check for Updates works in-app** as normal.

## Out of scope

- **Bundling OpenSSL 3 on Windows** — a larger CI change (the Qt 5.15.2 we build against targets the OpenSSL 1.1 ABI). 1.1.1w still works for our TLS needs; moving to OpenSSL 3 is security hygiene, queued separately rather than rushed into this fix.
