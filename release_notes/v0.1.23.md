# Notepatra v0.1.23 — Critical dark-theme fix (editor body painted white on "System" + dark OS)

**Released:** 2026-04-25

A critical follow-up to v0.1.22. The user's `img2.png` screenshot showed the SQL Formatter on Windows with dark menu bar / toolbar / panel header, but a glaring **white editor body** below the status banner. The same bug affected Editor / JSON / HTML / Bracket / Markdown panels for any user with `Config::theme = "System"` on a dark OS.

---

## Highlights

### 🌙 Critical dark-theme fix — editor body no longer paints white on "System" + dark OS

**Root cause:** `Config::theme` stays as the literal user preference forever — `"System"` is *not* rewritten to `"Light"`/`"Dark"` at startup so the next launch can re-detect the OS preference. Chrome stylesheets went through `applyThemeToAll(resolveTheme(name))` which DID resolve `"System"` → so chrome painted dark. But `npIsDarkTheme()`, `applyNotepadPlusPalette()`, and `Editor::applyLexer()` compared `Config::theme` directly against `"Dark"`. `"System" == "Dark"` is false → every "is this dark?" check fell through to LIGHT-mode colours. Result: dark chrome, white editor.

**Fix:**
- `theme_detect.h` gains `npResolvedThemeName()` — returns `"Light"` / `"Dark"` / `"Monokai"` by resolving `"System"` via `detectSystemTheme()`. `npIsDarkTheme()` now uses it.
- `src/sqlfmtpanel.cpp` `applyPalette()` calls `npResolvedThemeName()` instead of `Config::theme`.
- `src/fmtpanel.cpp` `applyLexer()` calls `npResolvedThemeName()`; the panel-local `fmtIsDark()` helper now defers to `npIsDarkTheme()`.
- `src/editor.cpp` `applyLexer()` resolves `"System"` before computing editor paper / foreground; the hardcoded `setPaper(QColor("#FFFFFF"))` is gone — paper now tracks the resolved theme so Editor instances paint dark on dark.
- `src/editor.cpp` 1-arg `applyNotepadPlusPalette` overload also resolves before calling the underlying function.

### Notes

- Linux / macOS / Windows users on explicit `"Light"` / `"Dark"` / `"Monokai"` themes are unaffected; only `"System"` theme on a dark OS was buggy.
- All v0.1.22 truncation fixes (close-icon mojibake, button widths, header heights, status wrap, model-dropdown width, Copy Output clipping) are bundled here too.
