# Notepatra v0.1.66 — Manage Connections UX + website cleanup

**Date:** 2026-05-10
**Tag:** `v0.1.66`
**Build:** Linux x64 / Linux ARM64 / macOS Apple Silicon / Windows x64 — both lite and Linux-full flavors

UX-heavy release. The Database Connection Manager now ships preset templates for every supported DB (SQL Server, PostgreSQL, MySQL, SQLite, DuckDB) plus a local SQL Server Docker harness for testing. Website trimmed: FAQ no longer carries an obsolete Windows-cache fix from v0.1.23→v0.1.24, and the historical version list collapses to a single "See every release on GitHub" link (60+ entries was bloating the page).

---

## What changed

### Manage Connections — presets + smart defaults

`src/dbconnections.{h,cpp}`. New **Preset** dropdown at the top of the form with seven ready-to-use templates:

| Preset | Driver | Port | Notable defaults |
|---|---|---|---|
| SQL Server (localhost, ODBC) | QODBC | 1433 | `DRIVER={ODBC Driver 18 for SQL Server};Encrypt=no` |
| SQL Server Express (named instance) | QODBC | default | `localhost\SQLEXPRESS` + `Trusted_Connection=yes` |
| Azure SQL Database | QODBC | 1433 | `Encrypt=yes;TrustServerCertificate=no` |
| PostgreSQL (localhost) | QPSQL | 5432 | `postgres` / `postgres` |
| MySQL / MariaDB (localhost) | QMYSQL | 3306 | `mysql` / `root` |
| SQLite (file on disk) | QSQLITE | — | Database focus + Browse… |
| DuckDB (file or `:memory:`) | DUCKDB | — | `:memory:` default |

Pick one and the form fills with sensible defaults. You can still edit anything afterwards — the preset is a starting point, not a constraint.

### Per-driver smart defaults

`onDriverChanged()`:

- Auto-fills the default port (1433 for QODBC, 5432 for QPSQL, 3306 for QMYSQL) **only if the port is still 0** — never clobbers an explicit user value.
- Per-driver placeholder text on every field. SQL Server's Username placeholder is `sa   (leave empty for Windows Auth)`; PG's is `postgres`; the Options field gets driver-specific templates.

### Driver-availability install hints

New `m_driverHint` QLabel below the form, refreshed on every driver change:

- **Amber + actionable install commands** when the Qt SQL plugin for the selected driver is missing. SQL Server / QODBC gets per-OS instructions for Microsoft's `msodbcsql18` plus `libqt5sql5-odbc` / `unixodbc-dev`. Linux + macOS + Windows all covered.
- **Green usage tip** when the driver is present. Tips like "Named instances use the SQL Browser service — leave Port at default" / "For TLS-required servers add `sslmode=require`" / "DuckDB Database field is multi-mode: `:memory:`, file path, S3 URI".

### Local SQL Server Docker harness

`docker/sql-server-local.yml` + `scripts/sql-server-local-setup.sh`. One command:

```bash
bash scripts/sql-server-local-setup.sh
```

- Spins up `mcr.microsoft.com/mssql/server:2022-latest` bound to **127.0.0.1:1433** (localhost-only).
- Waits for healthy, creates `NotepatraTest` database with `customers` / `products` / `orders` tables (5 + 5 + 9 rows seeded).
- Registers a `sql-server-local` connection in `~/.config/notepatra/db-connections.json` with XOR-obfuscated password matching Notepatra's internal scheme.
- Idempotent — safe to re-run.
- `--teardown` (stop + remove container) and `--wipe` (also drop the data volume) flags.

Apple Silicon note: SQL Server's official image is Linux x64 only. Docker Desktop on M-series Macs runs it under Rosetta/QEMU — works for testing, ~3× slower than native. Microsoft never shipped a native ARM64 SQL Server image.

### Comprehensive "How to connect" documentation

`docs/docs.html` — new **"How to connect — step by step (v0.1.66+)"** subsection under Data Analyst Mode covering all five databases:

- **SQL Server** — local Docker setup + connecting to existing servers + Windows Auth notes + Azure SQL TLS configuration
- **PostgreSQL** — local + RDS/Cloud SQL/Neon/Supabase with `sslmode`, Unix-socket connections
- **MySQL / MariaDB** — local + managed with `SSL_CA`, Unix-socket
- **SQLite** — file-based, no host/port
- **DuckDB** — multi-mode Database field (files, S3, `:memory:`)

Plus:

- **Driver-availability matrix** per OS (Linux apt-get / macOS brew / Windows bundled) — answers "where do I get the plugin?" at a glance
- **Troubleshooting** for the five most common connection failures: "Driver not loaded", "data source name not found", "Server certificate not trusted", "password authentication failed", "Can't connect on localhost"

### Website cleanup

`docs/index.html`:

- **FAQ trimmed** — removed the obsolete Windows-MuiCache fix for v0.1.23 → v0.1.24 upgrades. That was a one-time shell-cache wipe needed only for users coming from versions that had non-ASCII in the embedded `VERSIONINFO`. New installs from v0.1.24 onward never hit it.
- **Historical version cards collapsed** — every release before v0.1.65 used to render as a full feature-list card on the page (60+ cards by v0.1.65). Page weight was ballooning. Replaced with a single "See every release on GitHub →" link block. The LATEST card still renders inline. Source of truth for history is the GitHub Releases page itself.
- Net effect: `docs/index.html` shrunk from 4787 lines to 2201 lines (~54% smaller).

### Version-history housekeeping

- v0.1.63 and v0.1.64 tags now have notes-only GitHub Releases ("rolled into v0.1.65"). Previously the tags existed but no Release was published (CI failed silently on the QJsonDocument bug). Now the Releases page shows a continuous v0.1.62 → v0.1.63 → v0.1.64 → v0.1.65 → v0.1.66 ladder with no gaps. The "rolled into" releases carry no binaries — they point users at v0.1.65 for artifacts.

### Tests

All 25 deterministic regression tests pass on the lite build. No new tests in this release (UX work, not behavior changes).
