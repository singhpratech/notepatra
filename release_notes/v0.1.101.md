# Notepatra v0.1.101 — in-app updater finalizes even when a prior download is locked

**Release date:** 2026-05-25

A fix for the in-app updater on macOS (and a hardening for every platform): the update would download and verify successfully, then fail at the last step with *"Could not finalize the download file. Your current installation is untouched."* v0.1.101 makes the finalize step land on a fresh filename instead of giving up.

---

## What was wrong

On macOS, **Help → Check for Updates → Download** fetched the DMG, verified its SHA-256 (and cosign signature), and then errored: *"Could not finalize the download file."* Retrying just reproduced it.

## Root cause

The updater downloads to `~/Downloads/<name>.part`, verifies it, then moves it to `~/Downloads/<name>`. The move did `if (exists) remove(); rename();` — but it **ignored whether the remove succeeded**. On macOS, once the updater has `open`ed a DMG, that disk image is **mounted in Finder**, and macOS refuses to delete a mounted image's backing file. So the stale `notepatra-macos-arm64.dmg` from a previous attempt couldn't be removed, `QFile::rename` then refused to overwrite the still-present file, and every retry re-mounted and re-wedged it.

## The fix

`src/updater.cpp` — the finalize step is now resilient:

1. **Deduplicated landing name.** If the destination exists and can't be removed, the move falls back to a browser-style `notepatra-macos-arm64 (1).dmg` (then `(2)`, …) so it **always lands somewhere fresh** rather than failing.
2. **Copy + remove fallback.** If the atomic rename itself fails (odd filesystem, busy source handle), it falls back to copy-then-delete.
3. The success message and the installer/Finder handoff use the **actual** path the file landed at.

This is a net improvement on **every** platform — previously any unremovable same-named file in Downloads aborted the update; now it just lands beside it.

### If you're stuck right now (no new build needed)

Quit Notepatra, **eject** any mounted "Notepatra" disk image in Finder, delete `~/Downloads/notepatra-macos-arm64.dmg` (and any `.part`), then retry — or download v0.1.101 from the releases page and drag it into Applications once. From v0.1.101 onward the in-app updater handles this itself.

## Out of scope

- Bundling OpenSSL 3 on Windows — still queued as separate security hygiene.
