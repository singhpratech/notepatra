# Notepatra v0.1.30 — Live streaming token-rate on AI bubble

**Released:** 2026-04-26

User asked: *"can we stream tokens and seconds on each response card to stream"* — i.e. show the live token-count, token-rate, and elapsed wall-clock time as the model generates, not just after it completes.

v0.1.26 already added per-response stats to the bubble header (`1234 tok · 123.4 tok/s · 2.3 s`) but those only appeared after the response was done. v0.1.30 makes them stream live.

---

## What you'll see

On every model response from now on, you get a small live-stats label inside the assistant card while the model is generating:

```
QWEN3.5:2B
⏱ 145 tok · 23.4 tok/s · 6.3 s     ← updates every 250 ms while streaming
def fibonacci(n):
    if n < 2:
        return n
    return fibonacci(n-1) + fibonacci(n-2)
```

When the stream ends:
- The live label disappears
- The bubble re-renders with the canonical `eval_count` / `prompt_eval_count` / wall-clock baked into the header (this is the v0.1.26 mechanism — chat history retains the final stats)

So you get the best of both: live feedback during generation, plus a permanent record after.

## Display modes

Three states based on how much time has elapsed:

| When | Display |
|---|---|
| First 200ms (no tokens yet) | `⏱ generating… 0.3 s` |
| Tokens received, < 200ms | `⏱ 12 tok · 0.18 s` (tok/s suppressed — too noisy with tiny numbers) |
| 200ms onwards | `⏱ 145 tok · 23.4 tok/s · 6.3 s` (full triple) |

## Why 250 ms refresh rate?

Tested 100 ms → too jittery, label flickers visibly between updates.
Tested 500 ms → feels laggy, doesn't capture the responsiveness of fast local models.
**250 ms (4 Hz)** → feels live without UI thrash. Each tick is a `QLabel::setText()` with a formatted string — sub-millisecond cost.

## Stop-button cleanup

While I was in the streaming code I also fixed a pre-existing minor bug: hitting **Stop** during generation didn't fully end the streaming card. `OllamaClient::cancel()` disconnects + aborts the network reply silently — no `finished` or `error` signal fires after that. The streaming card was being left mid-state. v0.1.30 hooks the stop button to also call `endAssistantBubble()` cleanly, which now also stops the live-stats timer.

```bash
chmod +x Notepatra-0.1.30-linux-x86_64.AppImage
```


## Try it

After upgrading:
1. Open AI panel → pick any Ollama model
2. Type a prompt that takes a few seconds to answer (e.g., "explain memory ordering in Rust" or "write me a Python script to fetch GitHub stars for a repo")
3. Watch the `⏱ N tok · X tok/s · Y s` line in the bubble header update live as the response streams
4. After completion: the bubble re-renders with final canonical Ollama-reported counts in the header

Works with every model + every backend (Ollama / llama.cpp / OpenAI-compatible).
