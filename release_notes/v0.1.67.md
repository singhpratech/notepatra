# Notepatra v0.1.67 — Three independent AI threads + tool-tab UX + release-engineering hardening

**Date:** 2026-05-10
**Tag:** `v0.1.67`
**Build:** Linux x64 / Linux ARM64 / macOS Apple Silicon / Windows x64 — both lite and Linux-full flavors

Two user-visible UX wins plus a quiet round of release-pipeline hardening (the kind that pays itself back the next time CI tries to silently fail):

1. **AI Assistant — three independent per-mode conversations.** The three modes (Chat / Coding / Data) now each keep their own conversation thread. Flipping modes no longer mixes the previous mode's bubbles with the new mode's system prompt.
2. **AI dock auto-exits fullscreen when you open a tool tab.** If you have the AI dock blown up to fullscreen and then click Project Search / Terminal / Git / REST Client / SQL Formatter / JSON Tools / HTML Tools / Bracket Tools / Compare / Welcome, the dock collapses back to its sidebar size so the tool tab is actually visible. Editor-tab creation (Ctrl+N) deliberately still creates a background tab — that's a v0.1.61 UX choice we want to preserve.
3. **Release engineering: CI runtime-smoke gate on full-flavor builds, jq-free release verification, and two static-analysis nits the strict-warnings sweep surfaced.**

---

## The bug

Pre-v0.1.67 there was one chat session per workspace, shared by all three modes. So if you had a Coding-mode conversation going (the AI was operating under the strict-coding-agent system prompt with `write_file` / `apply_diff` tools wired in) and you clicked **Data**, the same bubbles stayed on screen but the next model turn ran with the data-analyst system prompt instead. The model would either:

* Try to apply the coding-mode system prompt to a data question and refuse the new request.
* Carry the coding-mode tool history into a data-mode turn — confusing the model and producing erratic responses.

Most obvious symptom: the AI's first reply after a mode swap would mention coding (or data) when the new mode shouldn't be talking about that at all.

## The fix

`src/aipanel.{cpp,h}` — `m_messages` (the single per-workspace conversation vector, 32 references across the file) is gone. Replaced with three independent vectors:

| Vector | Mode | Tool surface |
|---|---|---|
| `m_chatMessages` | Chat (default) | none — plain conversation |
| `m_codingMessages` | Coding Mode | agentic file ops (`write_file`, `apply_diff`, `read_file`, `list_dir`, `run_command`, git_*, search_files) |
| `m_dataMessages` | Data Analyst | `csv_query`, `query_sql`, `generate_chart` |

A new private helper, `activeMessages()`, picks the right vector based on which of the three QAbstractButton mode toggles is checked. Every read and write to chat state now goes through it.

When you flip modes, the mode-toggle handler:

1. Cancels any in-flight stream so it doesn't keep pumping tokens into the now-rebuilt chat surface.
2. Force-saves the outgoing mode's bubbles to disk (no more racing the 2-second debounce).
3. Calls `renderTranscript()` to wipe every chat-bubble widget from the layout and re-add bubbles from the new active vector.
4. Scrolls to the bottom.

`clearChat()` (the Reset button) now clears **only the active mode's vector**. The other two retain their state. Force-saves immediately so the cleared state survives a restart.

## On-disk format change + migration

`~/.config/notepatra/chat-history/<sha1-of-workspace>.json` schema bumps `"version": 1` → `"version": 2`:

```json
// Old (v1, v0.1.39-v0.1.66)
{
  "version": 1,
  "workspace": "/path/to/workspace",
  "messages": [{ "role": "user", "text": "...", ... }, ...]
}

// New (v2, v0.1.67+)
{
  "version": 2,
  "workspace": "/path/to/workspace",
  "chat":   [...],
  "coding": [...],
  "data":   [...]
}
```

`loadChatHistory()` detects the format automatically:

* `{"version": 2, ...}` → split into the three vectors verbatim.
* `{"version": 1, "messages": [...]}` → migrate into `m_chatMessages`; `coding` and `data` start empty.
* Top-level array (very old v0.0 dump) → same migration as v1.

No user action required. First save after the upgrade rewrites in v2 format.

## Save-cadence rework

* `saveChatHistory()` is now callable directly (was timer-only).
* New `saveChatHistoryNow()` cancels the pending 2-second debounce timer and saves synchronously. Called at every key transition: user submit (appendUserBubble), assistant stream end (endAssistantBubble), mode switch (applyModeWithCancel), Reset (clearChat).
* The 2 s debounce stays wired as a backstop for the streaming-chunk flurry (token frames fire 20+ times/second; we don't want to write the JSON on every chunk).

## Tests

* New `test_ai_chat_history.cpp` — 61 sub-checks across four sections:
  1. Cross-mode partitioning (`activeMessages()` swaps the right vector; no cross-contamination on switch).
  2. `clearChat()` clears only the active vector.
  3. Save + reload round-trips all three vectors verbatim (text, role, model, promptTokens, evalTokens, elapsedMs all preserved).
  4. v1 migration (both flat-array and `{version:1, messages:[]}`) lands in the chat vector with coding/data empty.
* All 26 deterministic regression tests pass on the lite build (`build-lite/` with `BUILD_TESTING=ON`).

## Roll-off behaviour

The on-disk 1 MB cap is unchanged but now rotates through `chat` → `coding` → `data` when trimming oldest messages, so heavy use of one mode doesn't starve the other two.

## Auto-exit AI dock fullscreen on tool-tab open

Before v0.1.67: if you fullscreened the AI dock and then clicked a tool button on the left rail, the tool tab DID open, but it was buried under the fullscreened AI dock. You had to manually un-fullscreen the dock first. Worse, the tool button gave no visible feedback that anything had happened, so it felt like the button was broken.

After v0.1.67: opening any tool tab while the AI dock is in fullscreen calls a new `MainWindow::exitAiFullscreenIfActive()` helper that flips `AIPanel::forceExitFullscreen()`, which uses the same one-call path that the AI dock's own fullscreen-toggle button uses. The dock returns to its previous sidebar geometry, the tool tab takes the rest of the editor area, and you see the result of the click.

Instrumented at 14 tool-tab open sites: Project Search, Terminal, REST Client, SQL Formatter, Git diff, Git panel, JSON Tools (parent + Compare child), HTML Tools (parent + Compare child), Bracket Tools (parent + Compare child), Compare picker, Welcome tab.

Deliberately NOT instrumented:
* **Editor tabs (Ctrl+N / file open).** v0.1.61 introduced the rule that Ctrl+N while the AI dock is fullscreen creates the new editor in the background so you don't lose your AI flow. That UX is preserved.
* **Hex Editor.** Opens as a modal dialog, not a tab; the fullscreened dock doesn't occlude it.

## Release engineering

The four parallel verification agents that ran against v0.1.66 before the v0.1.67 cut surfaced a small set of release-pipeline gaps. The actionable ones land in this release:

* **CI runtime-smoke gate on `-full` builds.** The v0.1.63 silent-failure incident was a *runtime* crash behind `#ifdef NOTEPATRA_WITH_WEBENGINE`. The previous gate only ran `ldd | grep webengine` after the build, which catches a missing link but not a boot-broken binary. v0.1.67 adds `QT_QPA_PLATFORM=offscreen ./notepatra --version` on both Linux x64 and Linux ARM64 full-flavor builds, so any future regression in the WebEngine init path fails CI on that job instead of shipping to Releases.
* **Explicit `-DCMAKE_BUILD_TYPE=Release` on the test-step reconfigure.** Today's single-config Make caches the build type, so dropping the flag during `cmake .. -DBUILD_TESTING=ON` still runs Release binaries through ctest. But if anyone ever moves Linux CI to Ninja Multi-Config, ctest would silently switch to Debug. Now re-asserted at every reconfigure.
* **Release job pinned to `ubuntu-24.04`.** Was `ubuntu-latest`, which would silently roll forward and could shift cosign / SLSA action runtime expectations under us.
* **Stale comments fixed.** Chocolatey openssl.light was removed (FireDaemon download is the actual source); the "macOS / Windows full-flavor ship in v0.1.65" comment was aspirational and never delivered (full flavor is Linux-only by design — Charts Pack downloads on-demand on the other OSes).
* **`scripts/post-release-verify.sh` no longer needs `jq`.** Replaced the `gh release view --json ... | jq -r '.assets[].name'` pipe with `gh release view --json assets --jq '.assets[].name'` — same pattern `scripts/stale-text-check.sh` already uses, leveraging gh's embedded gojq.
* **Static-analysis nits cleaned up.** `src/themes.h:82` had a Windows registry path comment ending in `\`, which the preprocessor treats as line-continuation inside `//` and cascades 12 `-Wcomment` warnings through every TU that includes it. `src/lexer_extras.cpp:657` got `Q_UNUSED(set)` on `LexerGitignore::keywords` — that lexer is intentionally pure-pattern (no keyword sets), so the parameter is genuinely unused.

The other static-analysis findings (Qt5→Qt6 forward-compat warnings around `QRegExp` and `QTextCodec`) are intentionally deferred to the eventual Qt6 port.
