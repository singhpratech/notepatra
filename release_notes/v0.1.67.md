# Notepatra v0.1.67 — AI Assistant: three independent per-mode conversations

**Date:** 2026-05-10
**Tag:** `v0.1.67`
**Build:** Linux x64 / Linux ARM64 / macOS Apple Silicon / Windows x64 — both lite and Linux-full flavors

Bug-fix release with a small but visible UX win. The AI Assistant's three modes — **Chat**, **Coding**, **Data** — now each keep their own conversation thread. Flipping from one mode to another no longer mixes the previous mode's bubbles with the new mode's system prompt.

---

## The bug

Pre-v0.1.67 there was one chat session per workspace, shared by all three modes. So if you had a Coding-mode conversation going (the AI was operating under the strict-coding-agent system prompt with `write_file` / `apply_diff` tools wired in) and you clicked **Data**, the same bubbles stayed on screen but the next model turn ran with the data-analyst system prompt instead. The model would either:

* Try to apply the coding-mode system prompt to a data question and refuse the new request.
* Carry the coding-mode tool history into a data-mode turn — confusing the model and producing erratic responses.

Most obvious symptom: the AI's first reply after a mode swap would mention coding (or data) when the new mode shouldn't be talking about that at all.

## The fix

`src/aipanel.{cpp,h}` — `m_messages` (the single per-workspace conversation vector, 32 references across the file) is gone. Replaced with three independent vectors:

| Vector | Mode | Tool surface |
|---|---|---|
| `m_chatMessages` | Chat (default) | none — plain conversation |
| `m_codingMessages` | Coding Mode | agentic file ops (`write_file`, `apply_diff`, `read_file`, `list_dir`, `run_command`, git_*, search_files) |
| `m_dataMessages` | Data Analyst | `csv_query`, `query_sql`, `generate_chart` |

A new private helper, `activeMessages()`, picks the right vector based on which of the three QAbstractButton mode toggles is checked. Every read and write to chat state now goes through it.

When you flip modes, the mode-toggle handler:

1. Cancels any in-flight stream so it doesn't keep pumping tokens into the now-rebuilt chat surface.
2. Force-saves the outgoing mode's bubbles to disk (no more racing the 2-second debounce).
3. Calls `renderTranscript()` to wipe every chat-bubble widget from the layout and re-add bubbles from the new active vector.
4. Scrolls to the bottom.

`clearChat()` (the Reset button) now clears **only the active mode's vector**. The other two retain their state. Force-saves immediately so the cleared state survives a restart.

## On-disk format change + migration

`~/.config/notepatra/chat-history/<sha1-of-workspace>.json` schema bumps `"version": 1` → `"version": 2`:

```json
// Old (v1, v0.1.39-v0.1.66)
{
  "version": 1,
  "workspace": "/path/to/workspace",
  "messages": [{ "role": "user", "text": "...", ... }, ...]
}

// New (v2, v0.1.67+)
{
  "version": 2,
  "workspace": "/path/to/workspace",
  "chat":   [...],
  "coding": [...],
  "data":   [...]
}
```

`loadChatHistory()` detects the format automatically:

* `{"version": 2, ...}` → split into the three vectors verbatim.
* `{"version": 1, "messages": [...]}` → migrate into `m_chatMessages`; `coding` and `data` start empty.
* Top-level array (very old v0.0 dump) → same migration as v1.

No user action required. First save after the upgrade rewrites in v2 format.

## Save-cadence rework

* `saveChatHistory()` is now callable directly (was timer-only).
* New `saveChatHistoryNow()` cancels the pending 2-second debounce timer and saves synchronously. Called at every key transition: user submit (appendUserBubble), assistant stream end (endAssistantBubble), mode switch (applyModeWithCancel), Reset (clearChat).
* The 2 s debounce stays wired as a backstop for the streaming-chunk flurry (token frames fire 20+ times/second; we don't want to write the JSON on every chunk).

## Tests

* New `test_ai_chat_history.cpp` — 61 sub-checks across four sections:
  1. Cross-mode partitioning (`activeMessages()` swaps the right vector; no cross-contamination on switch).
  2. `clearChat()` clears only the active vector.
  3. Save + reload round-trips all three vectors verbatim (text, role, model, promptTokens, evalTokens, elapsedMs all preserved).
  4. v1 migration (both flat-array and `{version:1, messages:[]}`) lands in the chat vector with coding/data empty.
* All 26 deterministic regression tests pass on the lite build (`build-lite/` with `BUILD_TESTING=ON`).

## Roll-off behaviour

The on-disk 1 MB cap is unchanged but now rotates through `chat` → `coding` → `data` when trimming oldest messages, so heavy use of one mode doesn't starve the other two.
