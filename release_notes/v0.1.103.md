# Notepatra v0.1.103

**Diagrams now render natively in the default binary — on every platform, including macOS Apple Silicon and Windows — with no WebEngine, no Chromium, and no separate "Full" download.**

## What changed

The diagram tool shipped in v0.1.102 drew its flow / ER / system diagrams inside an embedded Chromium (QtWebEngine) view using dagre.js. That worked on Linux x64 and Windows Full builds, but it meant the picture **never appeared** on the default lite binary, on the macOS Apple Silicon build, or anywhere WebEngine wasn't bundled — the one place most users actually run Notepatra. Shipping a 95 MB Chromium just to lay out boxes and arrows was also the wrong trade for a feature this small.

v0.1.103 replaces the whole WebEngine pipeline with a **native Qt renderer** built on `QPainter`. The same `.npd` text compiles to the same diagram — laid out, drawn, zoomed, panned and exported entirely in C++. There is no longer a "Full vs Lite" split for diagrams: the default binary renders them everywhere.

## The addition

`src/diagram/diagram_render.{h,cpp}` is a new, Qt-widget-free rendering module:

1. **Layout engine** — longest-path layering + 10 barycenter crossing-reduction sweeps + centered rows, so columns line up and edges cross as little as possible.
2. **Border-anchored bezier edges** — anchors fan out around each node and spanning edges bow sideways, so connectors don't pile on top of each other or run through boxes.
3. **~55 hand-drawn icons + ~150 aliases** (`postgres`→database, `k8s`→kubernetes, …) for system / ER / flowchart vocabularies — all drawn with `QPainter`, no emoji, no image assets.
4. **Five palettes** — ocean / forest / clay / mono / default, each with light-readable text.

`src/diagram/diagram_view.{h,cpp}` is rewritten as a native `QWidget`: scroll-to-zoom (zoom-to-cursor), drag-to-pan, double-click-to-fit, and hover tooltips via hit-testing — no browser, no JS bridge.

### Export

Export routes through `DiagramView::exportTo()` and the menu is now built dynamically from what your Qt actually supports:

| Format | Availability |
|--------|--------------|
| PNG    | every build (2× supersampled) |
| JPEG   | every build |
| PDF    | every build (`QPdfWriter`, exact page size) |
| SVG    | where the Qt **Svg** module is present (`QSvgGenerator`) |
| HTML   | where Qt Svg is present (self-contained inline SVG, opens in any browser) |
| WebP   | where the Qt **WebP** image plugin is present |

Formats that aren't available on a given build are hidden from the menu and refuse cleanly rather than writing a broken file.

## Why this is better than WebEngine

| Aspect | WebEngine (v0.1.102) | Native Qt (v0.1.103) |
|--------|----------------------|----------------------|
| macOS Apple Silicon | **no diagram** | renders |
| Default lite binary | **no diagram** | renders |
| Windows `.msi` | only Full variant | renders |
| Dependency weight | ~95 MB Chromium | none beyond Qt |
| Offline / air-gapped | needs bundled assets | always works |
| Export | browser-driven, async | direct, synchronous, 6 formats |

What we give up: Chromium's text shaping and the dagre.js layout. The native layout is our own (good for the diagram shapes we support); it is not a general-purpose graph layout engine. For the flow / ER / system diagrams the tool targets, output is on par.

## Test coverage

`test_diagram_view.cpp` is rewritten for the native path (builds in **both** flavors, no WebEngine):

```
layout_has_geometry     paint_is_nonempty
hittest_finds_node      export_all_formats
icon_aliases_render
```

`export_all_formats` exercises every format through the real `DiagramView::exportTo()` path and asserts valid magic bytes (PNG `‰PNG`, JPEG SOI, `%PDF`, `RIFF`, `<?xml`, `<!doc`); formats absent from the build must refuse, not write garbage.
