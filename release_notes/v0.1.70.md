# Notepatra v0.1.70 — AI cleanup + Notepad++-style session persistence

Released: 2026-05-11

This is a focused cleanup release. Two concrete user-facing rewrites
land here, both driven by direct feedback during local testing.

## Notepad++-style session persistence

Closing the app no longer prompts. All open buffers — file-backed and
untitled, modified and pristine — are serialised to
`~/.config/notepatra/session/session.json` on close (and on a 10 s
autosave tick during normal use). Relaunch silently restores every
tab with its content, cursor position, name, and `modified` flag.

Individual tab close (the `X` on a tab) still shows the
Save / Discard / Cancel dialog, exactly as it did before — that's
the place to make the explicit save-or-discard decision. App close
is now an unconditional commit-to-disk so you can quit at any time
without losing work.

Two pieces removed to make the new flow clean:

- The legacy `recovery_*.txt` files + crash-recovery prompt now run
  only as a fallback when `session.json` is absent. With session.json
  present they're wiped on launch so you can't get the
  "Restore recovered files?" double-restore that bolted a stray
  `[recovered]` tab on top of the silently-restored session.
- The 10 s autosave tick stopped writing the per-tab recovery files
  — `saveSession()` carries the full unsaved buffer content now, so
  the second writer was redundant.

## Model-capability gates removed

Notepatra no longer pre-judges whether your selected model is
"strong enough" for Coding or Data mode. The hand-maintained
substring allowlists rotted with every release (Gemma 4 26B got
rejected as "too small" despite being a 17 GB multimodal model with
native tool calling) and the gates produced false-positive error
bubbles in chat history that persisted even after the model picker
changed. Cut clean:

- `appendErrorBubble(...isn't strong enough for the Data Analyst mode…)`
- `appendErrorBubble(...doesn't support tool calls…)`
- The `⚠ … is too small` banner near the Data action bar
- The amber dropdown coloring in `decorateModelsByMode()` (rows now
  read in the default foreground; no second-guessing tooltips)

Trust the user's pick. The Ollama `/api/show` capabilities cache
remains the ground-truth for whether tools fire; cloud / OpenAI-compat
backends always get tools attached and the server decides. Context
gates (no folder open → Coding refuses; no DB connection → Data
refuses) stay — those are about workspace state, not model identity.

Memory saved (`feedback_no_hardcoded_model_allowlists.md`) so future
sessions don't reintroduce these.

## Data Mode now shows what's attached + tells the model

Two changes that make Data Mode actually usable when you have a DB
saved:

1. **Visible "Attached: …" chip.** A small green pill below the
   Manage Connections / Browse Schemas row in Data mode reads
   `✓ Attached: <conn name> (N tables) — visible to the model via
   query_sql.` Multiple saved connections render as a `·`-joined
   list. If a connection can't be opened it shows in red. Zero
   connections shows an amber nudge pointing at the Manage
   Connections… button. Refreshed automatically on dialog close +
   on mode entry.
2. **Schema injected into the Data system prompt.** Every Data-mode
   send now embeds the saved connections + their first ~30 user
   tables into the system prompt with a hard "These are the ONLY
   data sources available via `query_sql`; do NOT speculate about
   other data sources or the editor workspace" preamble. Fixes the
   "I see a variety of files and directories in your workspace"
   hallucination where the model answered about the file tree when
   asked about the database.

New `DbConnections::listTables(record)` helper added (per-driver
introspection — `sqlite_master`, `INFORMATION_SCHEMA.tables` for
PostgreSQL/MySQL, `sys.tables` for SQL Server via QODBC). Used by
both the chip and the system-prompt injection.

## Chat-bubble breathing room

The chat surface had been creeping tight. This release re-balances
spacing top-to-bottom:

- Bubble inner padding bumped: 14/16 → 22/24 (assistant), 10/16 →
  14/20 (user)
- Inter-bubble gap: 14 → 26 px
- Card outer margin: 14/12 → 20/18
- Chat container margin: 12 → 18
- Line-height: 1.55 → 1.7
- Tables + blockquotes get explicit CSS rules now (previously
  fell through to QTextBrowser defaults)
- Chart widgets: 14 px spacer above, 10 px below, 280 px minimum
  height so bar/line charts don't squash

## Bubble auto-fit (kills trailing whitespace under short replies)

`QTextDocument::setDocumentMargin(0)` kills Qt's hidden 4 px frame
margin that was padding every bubble. The `+ 8 px` slop on the
height calculation was the empty band users were seeing under
single-line replies — also removed. A viewport-resize event filter
re-fits every bubble's height when the panel/splitter width
changes, so the body refits cleanly on dock resize instead of
freezing at first-render height.

## Misc

- QODBC connection string composition fix: SQL Server connections
  now build `DRIVER=…;SERVER=host,port;DATABASE=…;UID=…;PWD=…;` and
  pass it via `setDatabaseName()` instead of the per-field setters
  (which don't compose for QODBC). This is what makes the Notepatra
  local Docker preset actually connect.
- SQL Server local preset (case 2 in the Manage Connections preset
  dropdown) wired with port 14330, NotepatraTest DB, sa user — for
  use with `docker/sql-server-local.yml`. Password ships in the
  yml + setup script for local testing only.
- Conversation-history threading fix in `ollama.cpp` — when there
  are prior messages, the send now uses `/api/chat` and splices the
  history between system and current user message, so the model
  actually sees the conversation it's in (was previously sending
  an empty history every turn).
- SVG icons (bot, git-branch, database, image, file, file-text,
  lock, unlock, lightbulb, wrench, x, check, folder,
  alert-triangle) added to `resources/icons/` + registered in
  `icons.qrc`. Replaces emoji codepoints that tofu'd on systems
  without a color emoji font.

## Verification

- Live test on the running binary: short and long replies fit
  without trailing whitespace; Data mode chip + schema injection
  observed working against the pharma-db SQL Server (synthea_medical
  + PharmaInsights databases visible).
- No new compile warnings beyond the baseline.
