# Notepatra v0.1.6 — JSON Tools / HTML Tools / SQL Formatter overhaul

You said the plugin panels "look like a dead beat" — buttons did nothing visible, AI Fix never reported what happened, text typed into JSON Tools rendered white-on-white, and the default font felt aggressive. This release fixes all of that.

## Fixed

### 🐛 JSON Tools / HTML Tools / Bracket Tools — buttons now actually do something visible

The Format / Minify / Fix+Format buttons silently returned without doing anything if the editor was empty when the panel was opened. Root cause: `m_inputText` was set ONCE at panel-open time from the editor's selection or content. If the user opened the panel with no editor text and then **pasted JSON directly into the panel** (which is editable!), `m_inputText` stayed empty and every button click was a no-op.

Fixed: `inputText()` now reads the panel's current Scintilla content first, falls back to the seeded input. **You can now open JSON Tools, paste broken JSON into the panel, click Format → it formats.**

Plus every button click now shows a status banner above the panel:

```
Empty input — paste content into the panel below first    [red banner]
Running Format on 1234 chars...                           [teal banner]
✓ Format done — 1567 chars, 42 lines                      [green banner]
```

So you can never wonder whether a click registered.

### 🐛 JSON Tools panel: text was rendering white-on-white

When you typed into the panel directly, the text was invisible because the lexer's default per-style colors weren't initialized — same root cause as the v0.1.1 Windows editor lexer bug. Fixed by calling `applyNotepadPlusPalette()` on the panel's lexer plus an explicit black foreground / white background fallback for any text typed before the lexer kicks in.

### 🐛 AI Fix (Ollama) now reports clearly

The AI Fix button in JSON Tools used to silently fail if Ollama wasn't running, or if the model dropdown showed "(not connected)". Now it:

- Re-checks Ollama availability synchronously on click (not just at panel-open time)
- Shows `"Ollama not running — click setup steps below"` if the daemon is down
- Shows `"No Ollama model selected"` if the dropdown has no real model
- Shows `"Asking <model> to fix the JSON..."` while running
- Shows `"✓ AI fix complete — N chars"` when done
- Shows `"✗ AI fix failed: <reason>"` on error

### 🎨 Default font no longer feels aggressive

Two changes:

1. **Bumped Consolas from 11pt → 10pt** across the editor, all formatter panels, the SQL panel, and the compare view. 10pt matches Notepad++'s default size more closely.
2. **Removed bold from styles that don't need it.** v0.1.5's palette was bolding keywords AND operators AND preprocessor AND class names AND function names AND HTML tags — almost every line of code had bold text in it, which made the page feel heavy. Notepad++'s default `stylers.xml` only bolds **keywords** and **Markdown headers**. v0.1.6 matches that. Page now feels lighter.

### 🐛 Compare picker now lists unsaved tabs

The Compare/Diff plugin already iterated over all tabs (including unsaved ones), but the labels didn't make it obvious. Now:

```
Tab 1: notepatra.cpp
Tab 2: README.md ● unsaved
Tab 3: untitled.txt ● untitled
Browse file from disk...
```

So you can compare in-progress work without saving first.

## Added

### 🗄 SQL Formatter panel: Dialect dropdown

The SQL Formatter plugin now lets you pick the SQL dialect:

| Dialect | Extra keywords highlighted on top of ANSI SQL |
|---|---|
| **ANSI SQL** | Standard `SELECT FROM WHERE INSERT UPDATE DELETE...` |
| **T-SQL (SQL Server)** | `DECLARE TOP OUTPUT MERGE NVARCHAR DATETIME2 IDENTITY OFFSET FETCH PIVOT OVER PARTITION RANK ROW_NUMBER...` |
| **PL/SQL (Oracle)** | `NUMBER VARCHAR2 PLS_INTEGER PACKAGE BODY CURSOR EXCEPTION SYSDATE NVL DECODE CONNECT BY PRIOR LEVEL ROWNUM...` |
| **MySQL** | `AUTO_INCREMENT ENGINE INNODB UNSIGNED ZERONFILL ENUM TINYINT MEDIUMINT YEAR LONGTEXT...` |
| **PostgreSQL** | `SERIAL BIGSERIAL BYTEA JSONB UUID INET CIDR RETURNING CONFLICT PLPGSQL MATERIALIZED LATERAL UNNEST...` |
| **SQLite** | `AUTOINCREMENT WITHOUT ROWID PRAGMA VACUUM COLLATE NOCASE GLOB MATCH...` |

Switching dialects via the dropdown re-colourises the visible buffer immediately so dialect-specific keywords paint blue. Implementation uses `SCI_SETKEYWORDS` directly (the public `QsciLexerSQL::setKeywords` is `protected`, so we go straight to Scintilla).

### 📊 BIG status banner in plugin panels

A 36px tall colored banner at the top of every formatter panel that updates on every button click. Teal/blue for progress + success, red for errors. Replaces the silent v0.1.5 behavior where buttons gave no visible feedback.
