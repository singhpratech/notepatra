# Notepatra v0.1.20 — Windows single-instance · updater closes app before install

**Released:** 2026-04-24

A follow-up to v0.1.19 focused on two user-reported Windows UX papercuts:

1. **Double-clicking a file while Notepatra is open spawned a fresh clone per file** instead of reusing the running window as a new tab.
2. **"Check updates & install" stalled on "app already running"** because the updater handed off to `msiexec` without closing Notepatra first.

---

## Highlights

### 🪟 Windows — double-click a file opens a new tab, not a new window

- **Single-instance file-open bridge.** `main.cpp` now probes a per-user `QLocalServer` (`notepatra-<sha1(home)>`) before creating `QApplication`. If a primary is already running, the second invocation forwards its file args + `--line` as JSON and exits in ~220 ms.
- The primary's `newConnection` handler calls `MainWindow::handleRemoteOpen`, which opens each file as a tab, jumps to line, and `raise()`/`activateWindow()`s the window — your double-click feels instant.
- `-n` / `--new` bypasses both probe and listen for users who genuinely want a second independent window.

### 🪟 Updater — closes Notepatra before running the installer

- The **"Ready to Install"** dialog on Windows now explicitly says the running copy will close so the installer can replace it, reminds you to save open files first, and the confirm button is labelled **Close Notepatra & Install**.
- After `QProcess::startDetached` launches `msiexec` / setup.exe, `QTimer::singleShot(500, qApp, quit)` quits Notepatra so Windows doesn't refuse the overwrite with "app already running".
- macOS (DMG drag) and Linux (folder open) paths are untouched — neither holds a handle on the running binary, so no quit is needed there.

## Installation

### Linux (AppImage)

```bash
wget https://github.com/singhpratech/notepatra/releases/download/v0.1.20/Notepatra-0.1.20-linux-x86_64.AppImage
chmod +x Notepatra-0.1.20-linux-x86_64.AppImage
./Notepatra-0.1.20-linux-x86_64.AppImage
```

### macOS

```bash
curl -fsSL https://github.com/singhpratech/notepatra/releases/download/v0.1.20/Notepatra-0.1.20.dmg -o ~/Downloads/Notepatra-0.1.20.dmg
open ~/Downloads/Notepatra-0.1.20.dmg
```

### Windows

- **MSI** — `Notepatra-0.1.20.msi`
- **NSIS installer** — `Notepatra-Setup-0.1.20.exe`
- **Portable ZIP** — `Notepatra-0.1.20-windows-x64.zip`

### One-command installer scripts

```bash
# Linux, macOS
curl -fsSL https://notepatra.org/install.sh | sh

# Windows PowerShell
irm https://notepatra.org/install.ps1 | iex
```

## Upgrade notes

- The in-app updater from v0.1.19 will pick this up automatically — and because of the v0.1.20 fix, the Windows install will actually complete cleanly this time (the updater closes Notepatra for you before handing off to msiexec).
- No config, no scripts, no FFI changes — purely two Windows UX fixes.
- Linux and macOS get the single-instance bridge too (useful if you run `notepatra file.txt` from a terminal while the app is open), but the primary impact is on Windows where Explorer double-click was spawning clones.
