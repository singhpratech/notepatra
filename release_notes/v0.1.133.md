# Notepatra v0.1.133

**The tools that change your text can no longer change what it means, the AI assistant stops losing work, MCP goes from 49 to 119 tools, and the REST client runs `.http` files.**

This is a large release that came out of three audits (the AI assistant, the MCP server, and the non-AI formatters) plus an adversarial review of the SQL safety check. Several long-standing behaviours changed because the old behaviour could lose or alter data; those are called out under "Behaviour changes" at the end.

## JSON, HTML and bracket tools: never change meaning

These tools were rebuilt and then tested against millions of generated documents (5 million per JSON and bracket target, about 100 million for HTML, each compared with an independent parser).

- **JSON Format and Minify change only whitespace.** They used to rewrite numbers (`-0` became `-0.0`, 30-digit integers were rounded), drop duplicate keys, re-encode escapes, and Minify could remove spaces inside strings. Key order, duplicate keys, number text and escapes are now copied exactly.
- **Invalid JSON is left untouched, with a precise message**, for example `line 1, column 5: the array opened at line 1, column 1 is never closed with ']'`. Format used to "repair" it silently and report success.
- **JSON Fix + Format repairs only what is unambiguous**: trailing commas, comments, single or curly quotes, unquoted keys, Python `True`/`False`/`None`, raw control characters in strings, a missing colon, and a comma missing at a line break. Every change is listed with its line and column. Anything ambiguous (a file cut off mid-way, `NaN`, an extra closing bracket) is declined with the reason.
- **The fix report is shown in the banner, not written into your text.** The output of Fix + Format is valid JSON you can copy.
- **HTML Format changes only whitespace a browser does not render.** The old formatter added and removed spaces between inline tags, re-indented `<pre>` and `<textarea>`, and mangled `<` inside scripts, comments and attribute values. Tags, attributes, text, scripts and comments are now copied byte for byte.
- **HTML Minify uses the same safe formatter.** The old one could join script lines so a `//` comment swallowed the code after it, and removed the space between words split across lines.
- **HTML "Fix + Format" is now "Check + Format".** It formats the page, or leaves it unchanged and tells you what to fix and where (for example a `</p>` that would also close a still-open `<b>`). It no longer appends closing tags or writes a report block into the page.
- **Bracket Auto-Fix never touches balanced code**, ignores brackets inside strings, comments, regexes and template text, and lists what it inserted or removed. It used to alter more than half of already-balanced code samples.
- **Bracket Check no longer replaces your text with its report.**
- **AI Fix no longer reports success** when the model's reply is not valid JSON or is HTML the formatter cannot follow; it shows the reply and the reason.

## AI assistant

### Chat
- **A quick action with no model selected no longer wipes the conversation** (on screen and on disk).
- **Sending while a reply is streaming keeps the partial reply** (it behaves like pressing Stop first).
- **OpenAI-compatible models that reject `max_tokens` or `temperature`** get one automatic retry with `max_completion_tokens` / without temperature, remembered for the session. No model names are matched.
- **Quick actions respect Auto-attach.** With it off (or outside Coding mode), Explain, Fix and the others send only your selection, and ask for a selection if there is none. They used to send the whole file.
- **Data mode works with just a CSV** open or attached; it no longer demands a database connection or tells Lite users to add DuckDB.

### Coding agent
- **An agent write never reloads over unsaved edits.** If the tab is modified you get the normal "File Changed" prompt.
- **Agent edits keep the file's encoding, byte-order mark and line endings.** CRLF files stayed CRLF only by luck before, and Latin-1 or UTF-16 files were corrupted. A file that cannot be round-tripped safely is refused. This applies to `apply_diff`, `write_file` and Compose's Apply.
- **Two Compose edits to the same file both land.** The second used to overwrite the first.
- **`write_file` is atomic.**

### Data analyst
- **CSV loading follows RFC 4180**: quoted fields with commas, quotes and line breaks load correctly.
- **Money and percentages load as numbers** (`$1,234.50`, `(1,234.50)`, `12.5%`), so `SUM` and `AVG` are right. Decimal-comma columns and mixed currencies stay text.
- **Dates are stored in sortable ISO form** when a column parses unambiguously as month-first or day-first; a column that could be either stays text rather than being guessed.
- **The preview shows the exact column names SQL needs** (`Unit_Price`, with the original header beside it).
- **Header detection** handles a pandas-style empty first cell and numeric header cells.

## Security

- **Read-only SQL check: six bypasses closed.** An adversarial review ran about a thousand inputs through the check and executed many on real DuckDB and SQLite. Closed: statements hidden behind nested block comments; `EXPLAIN ANALYSE` and quoted-option forms that execute a write; PostgreSQL `U&"…"` escaped names that dodge the function deny-list; the wider `dblink_*`, large-object, advisory-lock and admin function families; SQL Server Service Broker, loop and `xp_cmdshell`-family statements after a `SELECT`; and DuckDB file reads through quoted or dotted table names. The PostgreSQL, MySQL and SQL Server rules were verified against the classifier, not against live servers.
- **The check no longer blocks ordinary queries** such as `COUNT(comment)`, `MIN(start)`, nested `REPLACE()`, DuckDB `PIVOT`, and `EXPLAIN ANALYZE SELECT`.
- **The agent's `search` tool applies the secrets deny-list** and no longer follows symlinks out of the workspace. `write_file` through a symlink pointing outside the workspace is refused.
- **`git_show` and `git_diff` cannot print deny-listed files** (`HEAD:.env` and similar), redact them from larger diffs, and never run external diff or textconv commands.
- **MCP project search and file open judge a symlink by its target.**
- **`list_dir` shows deny-listed files by name only**, without size.
- **`config.json` (API keys) and `db-connections.json` are written owner-only (0600) on Linux and macOS**, atomically, and an existing looser file is tightened on load.
- **The cloud-free build has no cloud Settings button or dialog.**

## MCP server: 49 to 119 tools

The goal is that an MCP client can drive everything in the editor except the built-in AI assistant. The 119 tools are 46 read, 22 act and 51 write. Every write still shows an Approve/Deny card in the window.

What reaches the network: the server opens no connections of its own (stdio to the client, a local socket to the editor). Tools that use a saved database connection talk to that database with its stored credentials: `run_query`, `list_tables`, `describe_table` and `test_connection` without a card, `export_query_results` and `execute_sql` after approval. `rest_request`, `git_fetch`, `git_pull` and `git_push` run only after approval.

- **Editing**: sort, dedupe, trim, join and reverse lines; change case; comment and uncomment; duplicate, delete and move lines; line endings and encoding; undo and redo; regex, match-case and whole-word find and replace, including across all open tabs on one card.
- **Tabs and files**: activate, close, reload, rename, save all, read-only.
- **Tools**: hash, Base64 and URL encoding, diff, bracket check and fix, explicit JSON repair, Markdown conversion, Mermaid import, symbol list, password generation, hex dump.
- **View and settings**: theme, word wrap, zoom, folding, bookmarks, Preview pane, an allow-listed set of editor preferences, workspace folder.
- **Git**: stage, unstage, commit, branches, stash, discard, hunks, conflict resolution, fetch, pull (fast-forward only) and push (never forced).
- **Noter**: search, rename, trash, restore, delete, export, and reminder snooze, dismiss and delete.
- **Data**: table descriptions, connection test, connection management (without passwords), and approved single-statement writes.
- **REST**: parse `.http` files, convert to and from cURL, and send a request after approval.

Fixes to the existing tools:

- **Tools act on the tab you name.** `goto_line` and `set_language` ignored `tab_id` and used the focused tab; a stale id is now an error everywhere.
- **An approved write follows its document.** If a tab is moved or closed while a card waits, the write goes to the right tab or fails cleanly.
- **The Approve card shows a countdown and flashes the taskbar**, and is readable in Dark and Monokai (the header was black on dark). Clients that send a progress token get progress notifications while a card waits.
- **Saving or exporting to dangerous locations is refused before any card** (shell start-up files, `authorized_keys`, autostart folders, credential files).
- **Diagram tools accept `tab_id`**, and `export_diagram` offers the formats the app really supports.
- **Exports are written atomically.**
- **`mcp-endpoint.json` is removed on SIGTERM/SIGINT.**

Not exposed, deliberately: running shell commands or the terminal, running or installing plugins, the updater, SSH key generation, and any stored password or key.

A new remote-gateway scope, `write_external`, covers the five writes that reach outside the editor (`execute_sql`, `rest_request`, `git_fetch`, `git_pull`, `git_push`). It is never granted by default.

## REST client

- **`.http` and `.rest` files**: several requests per file separated by `###`, with a marker beside each. Click it, use "Send Request" in the context menu, or press Ctrl+Alt+R. Files written for the VS Code and JetBrains REST clients work.
- **Variables and environments**: `{{name}}` from file-level `@name = value` lines and from `http-client.env.json` (with `http-client.private.env.json` for secrets), chosen in an Environment dropdown. A request with an undefined variable is not sent.
- **Import cURL and Copy as cURL.** Copy keeps variables unexpanded so a token is not put on the clipboard.
- **Response headers view, Open in tab, Save, and Cancel.** Binary and very large responses are summarised instead of dumped.
- **History** of the last 50 requests. Secret header values, token-like query parameters and password/token-style fields in JSON and form bodies are stored as `<redacted>`; the rest of a body is stored as sent, so a secret elsewhere in it is not removed.
- Redirects are still not followed (Qt would forward the `Authorization` header to another host); the redirect target is shown.

## Noter

- **Noter no longer touches your Documents folder at startup unless you use Noter.** On macOS this removes the permission prompt, and the frozen window behind it, for people who never opened Noter. Existing Noter users keep their reminders.
- **When the system blocks the Noter folder, Noter says so** (with the macOS settings path) instead of looking empty; the MCP note tools return the same message as an error.

## Packaging

- **Every packaged artifact is started for real in CI**: the Linux tarballs (Lite and Full), `.deb`, `.rpm`, AppImage, and the Windows portable zips. Until now only macOS had this. The Windows MSI and setup program are not covered yet.
- **The `.deb` and `.rpm` now declare the Qt SVG library.** The `.deb` did not start on a clean install made without recommended packages.
- The macOS launch test no longer changes a developer's own preferences when run outside CI.

## Hardening from the pre-release review

Before release, an independent review read the whole change set looking for gaps between the pieces. These were found and fixed before anything shipped:

- **Approve cards show everything.** A bare carriage return used to vanish from the card, so SQL could look commented out and still run. Every line break and control character is now visible, and the full text of an edit, SQL statement or commit message is shown in a scrollable box.
- **What you approve is what runs.** A REST request is resolved once, when its card is built, and sent exactly as shown. Git writes refuse to run if the workspace, the hunk or the conflict changed while the card waited. Closing or reloading a tab refuses if you typed in it meanwhile.
- **A second SQL statement cannot hide behind a lock hint** on the approval path, and on SQL Server connections a keyword glued to a number (`1DROP`) or an ODBC `{call}` is refused on the read path.
- **SQL Server writes can be approved.** One ordinary `INSERT`, `UPDATE`, `DELETE`, `MERGE` or simple table change is approvable through MCP; before, every write on an ODBC connection was refused.
- **Nothing under `.git/` can be written by the AI agent, Compose or MCP**, because a written git config or hook runs commands.
- **Notepatra's own settings folder is off limits to the AI and to MCP**, for reading and writing. It holds API keys and saved connection passwords.
- **Saves never write through a planted link.** Agent edits, notes, note drafts, the session file and chat history use unique temporary files and replace a link at their name instead of following it.
- **Closing a diagram with unsaved changes through MCP needs a card**, as do terminal, REST and tool tabs.
- **MCP reads never start Noter** or create its folder.
- **ODBC connection fields cannot add connection-string keywords.**
- **A settings save that fails is logged** instead of being silently ignored.

## Behaviour changes to know about

- JSON **Format** no longer repairs invalid JSON; use **Fix + Format**.
- JSON **Fix + Format** no longer closes brackets missing at the end of a file, because that is indistinguishable from a truncated file. It tells you which are missing.
- HTML **Fix + Format** is now **Check + Format** and never adds closing tags.
- AI quick actions outside Coding mode with Auto-attach need a selection.
- On SQL Server connections a column literally named `receive` now asks for approval.
- MCP: `format_json`, `format_sql` and `format_html` moved to the read tier; `format_html` returns an error when the formatter declines.
- Changing a saved connection's driver, host, port or user through MCP clears its stored password.

## Not verified in this release

- The SQL Server rules (glued keywords, approvable single writes) were verified against the classifier and its tests, not a live SQL Server.
- A small XML or plain-text request body containing a password is stored in REST history as typed; only JSON and form bodies are redacted.

- The PostgreSQL, MySQL and SQL Server safety rules were not run against live servers.
- The Windows MSI and NSIS installers have no launch test.
- `.http` files have no syntax highlighting yet; request bodies from a file (`< path`) and response chaining are not supported.
