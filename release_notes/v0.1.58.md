# v0.1.58 — Composer wiring complete: dry_run → Edit Plan → Apply

**Release date:** 2026-05-09 · **Platforms:** Linux x64 / ARM64 · macOS Apple Silicon · Windows x64 · **Bare binary:** ~9 MB stripped

v0.1.57 shipped the Composer surface — Slice A's tab split, Slice E's `@file` mention picker, Slice F's Ctrl+I inline edit modal, plus the EditPlanList + DiffView widgets compiled but **not wired**. The Composer tab was a literal placeholder reading *"Composer — coming in Slice B/C/D"*.

v0.1.58 closes that loop: every piece is now connected end-to-end.

---

## 🧠 Composer tab is live (Slice B/C/D)

When you toggle Coding Mode and click the **Composer** tab, you now see the **Edit Plan list**:

- The model issues `write_file` / `apply_diff` calls with `dry_run: true` (driven by the `composerModeLayer` in the system prompt).
- AIPanel's `handleToolCall` intercepts the `{dry_run: true, proposed: {path, before, after, mode}}` body and routes the proposal into `EditPlanList::addEdit` instead of touching disk.
- The dock auto-switches to the Composer tab so you see the queued edit immediately.
- Every row is a self-contained mini-card: file path, +N/-M stats, expand-to-diff toggle, per-row remove button.

## ✅ Apply All / Apply Selected actually writes files

`EditPlanList::applyRequested` is now connected to a new `AIPanel::applyComposerEdits` slot:

- Each `(absPath, afterText)` pair is written atomically (`.tmp + rename`) — same pattern `AiTools::executeWriteFile` uses for the non-dry path, so a kill-9 mid-write can never leave a corrupt file.
- After a successful write, `fileWrittenByAgent(absPath, wasNew)` fires — the open editor reloads its buffer or pops the file open in a new tab.
- Failures surface as a single grouped error bubble; partial success leaves the bad rows visible so you can retry.

## 🪟 Workspace-aware row labels

`EditPlanList::setWorkspaceRoot` is now synced from `setWorkspaceContext`. Per-row labels render relative to the project root (`src/foo.cpp`) instead of dumping a full absolute path (`/home/.../project/src/foo.cpp`).

## 🤖 System prompt closes the loop

`composerMode=true` is now passed through to `AiSystemPrompt::build` / `buildWithProjectContext` whenever the user is on the Composer tab in CodingStrict intent. The existing `composerModeLayer` in the system prompt instructs the model to **always** pass `dry_run: true`, so files never bypass the Edit Plan review step.

## What's still per-mode

| Mode / tab | Tool routing |
|---|---|
| Chat tab (Coding mode) | `write_file` / `apply_diff` execute directly (existing v0.1.57 behaviour) |
| **Composer tab (Coding mode)** | **`write_file` / `apply_diff` go via dry_run → Edit Plan → user clicks Apply** |
| Editor → Ctrl+I | Inline modal with side-by-side diff (independent of Composer) |
| Data Mode | Unchanged — DuckDB engine, no file writes |
