# Notepatra v0.1.62 — VS Code-parity Git in Coding mode

**Date:** 2026-05-10
**Tag:** `v0.1.62`
**Build:** Linux x64 / Linux ARM64 / macOS Apple Silicon / Windows x64

The "real" Source Control work the v0.1.61 release notes promised. Coordinated by two parallel implementation agents in isolated worktrees, each delivering one of the two pillars: gutter-popup + per-hunk staging, and CompareWidget hunk-buttons + merge-resolution helper.

---

## What changed

### Per-hunk stage / revert from the editor gutter

Click any green / red / blue line marker in the editor's gutter → a **`GutterHunkPopup`** appears, anchored to that line, showing:

- The hunk's before-vs-after content rendered in an embedded `DiffView` (left-old / right-new).
- **Stage Hunk** — pipes a synthesized unified diff to `git apply --cached --whitespace=nowarn` via `QProcess`. Only that hunk hits the index; the rest of the file stays in working-tree state.
- **Revert Hunk** — same patch in reverse against the working tree.
- **Copy Diff** — drops the unified-diff body to clipboard.

The popup closes on outside-click via `Qt::Popup | Qt::FramelessWindowHint | Qt::Tool` flags + `WA_DeleteOnClose`. After a successful stage / revert, `GitGutter::updateGitGutter()` re-reads the file and refreshes the line markers atomically.

### Patch synthesizer with safety rails

New `src/git_hunk_apply.{h,cpp}` exposes a `GitHunkApply` namespace with:

* `repoRootForFile(absPath)` — `git rev-parse --show-toplevel` with canonical-path resolution.
* `synthesizePatch(absFilePath, repoRoot, hunks, &errorKind)` — emits a `diff --git a/path b/path` + `--- a/...` + `+++ b/...` + per-hunk `@@` headers + `rawDiffLines`, CRLF-normalized to LF.
* `applyHunk(absFilePath, hunk, reverse, &errorKind, &message)` — runs `git -c core.autocrlf=false -c core.safecrlf=false apply --whitespace=nowarn --cached -` (`--reverse` for revert), 5-second timeout.

**Safety rails** (mirrors the existing `ai_tools.cpp::resolveSafePath` pattern but inlined to avoid pulling QSql / dbconnections into editor.cpp's link unit):

- Workspace-anchor + canonical-path resolution: every target path must canonicalize INSIDE the repo root after symlink follow.
- Hardcoded deny-list: `~/.ssh/`, `~/.gnupg/`, `~/.aws/`, `*.pem`, `*.key`, `id_rsa*`, `/etc/passwd`, `/etc/shadow`, etc.
- 5000-line hunk cap → `error_kind: too_large`. Renames and regenerated artifacts belong in `git add <file>`, not per-hunk.
- Empty hunks → `error_kind: io_error`. Drift / patch-reject → `error_kind: conflict` with the `git apply` stderr surfaced in the popup's error label.

### Editor wiring

`src/editor.{h,cpp}`:

- Margin 3 sensitivity (`setMarginSensitivity(3, true)`) — the gutter margin owning the line markers now fires `marginClicked` signals.
- `onMarginClicked(margin, line, modifiers)` — when `margin == 3`, looks up the hunk containing that line via the new `GitGutter::hunksForFile(absPath)` + `hunkIndexForLine(absPath, line)` accessors, rebuilds before/after text from the hunk's raw diff lines, computes screen anchor via `SCI_POINTXFROMPOSITION` / `SCI_POINTYFROMPOSITION` mapped to global coords, instantiates `GutterHunkPopup`, and connects `hunkStaged` / `hunkReverted` → editor-side gutter refresh.

### `CompareWidget` per-hunk Stage / Revert buttons

`src/compare.{h,cpp}` — `CompareWidget::setGitContext(repoRoot, filePath)` enables a scrollable hunk strip docked between the existing toolbar and the file-name headers. One row per contiguous run of non-equal diff rows, formatted as:

```
Hunk 3/7 · rows 124–138    [Stage hunk]  [Revert hunk]  [Jump →]
```

Click `Stage hunk` / `Revert hunk` → emits `stageHunkRequested(filePath, hunkIndex)` / `revertHunkRequested(filePath, hunkIndex)` which `MainWindow` routes to `GitHunkApply::applyHunk`. Click `Jump →` scrolls both editors to that hunk's start line. Hidden until `setGitContext()` is called (which `GitPanel::openDiffInTabWithGit` does automatically).

### Marker-based merge resolution helper

`src/merge_helper.{h,cpp}` + `src/merge_helper_widget.{h,cpp}` — a focused MVP for the v0.1.62 milestone. (Full 3-way merge editor with LOCAL / BASE / REMOTE panes is v0.2.)

* `scanConflicts(buffer)` — linear scan for column-0 `<<<<<<<`, `=======`, `>>>>>>>` markers; returns `QVector<ConflictRegion { startLine, separatorLine, endLine, ours, theirs, oursLabel, theirsLabel }>`. Nested marker text inside content is treated as text (column-0 requirement).
* `applyResolution(buffer, region, choice)` — rewrites the buffer programmatically with `Ours` / `Theirs` / `Both` and removes the markers.

The widget renders each region as a `QFrame` row containing:

```
Conflict 2/4 · lines 312-345 · ours: HEAD · theirs: feature/refactor
[Take ours]  [Take theirs]  [Take both]  [Jump →]
```

Plus a QScintilla annotation above each conflict region in the editor with the same label. Wired into `GitPanel`: a file with `UU` status now gets a **Resolve** button on its row instead of the +/- buttons. Clicking opens the file in the editor + mounts a top-level `MergeHelperWidget`.

### Drop-down dropdown

Already in v0.1.61 — the standalone Git toolbar shortcut was removed. v0.1.62 makes that drop justified: the gutter popup + CompareWidget integration + merge helper now cover the file → stage → commit loop *inside* Coding mode, where the file explorer + AI dock + per-hunk staging all live.

## What's still deferred to v0.1.63 and beyond

| Feature | Why | Target |
|---|---|---|
| **Vision PDF page rendering** — Poppler-Qt5 integration so dropped PDFs render to per-page PNG for vision-capable models | Needs `libpoppler-qt5-dev` build dep + tiered UX (page 1 silent, 2-10 with chip, 11+ ask) | **v0.1.63 candidate** |
| **Data Analyst charts** — `generate_chart` tool, inline Vega-Lite rendering, modal with "explain this chart" + PNG/SVG/pptx-embed export | Significant scaffolding required (QtWebEngine plugin architecture, pptx-writer with miniz) | **v0.1.63** |
| **Full 3-way merge editor** (LOCAL / BASE / REMOTE panes with accept-current / accept-incoming inline gutters) | The v0.1.62 marker-based helper covers ~90% of conflicts; the remaining 10% are renames + cross-branch deletes that need richer UI | **v0.2** |
| **Stage selected lines** within a hunk (partial-line `git stageSelectedRanges` equivalent) | Per-line clipping algorithm exists in VS Code's `staging.ts:122-151` — reproducible but invasive UX | **v0.2** |
