# Notepatra v0.1.43 — the Data Analyst release

**Released:** 2026-04-30

---

## What's new in one line

The AI assistant gains a real **Data Analyst Mode** — it can query CSVs, run SQL against your saved database connections, and emit live charts inline in the chat. All of it native (Qt SQL + QtCharts) — no Python sandbox, no external chart service.

---

## The headline feature: Data Analyst Mode

Toggle the new **`Data`** checkbox in the AI panel header (next to `Coding`). The header band switches to an accent-orange "AI · 📊 DATA" so it's unmistakable which mode you're in. Mutually exclusive with Coding Mode — the panel stays focused on one job at a time.

When Data Mode is on:

1. **Attached CSVs get smart previews.** Drop a 50 MB sales CSV into the chat. Instead of dumping the raw bytes (which would blow the model's context window), Notepatra sends the model a structured digest:
   ```
   CSV: sales-2026.csv
   Size: 52431200 bytes · Delimiter: , · Header: yes · Rows: >1000

   Schema:
     order_id (INTEGER) — range 1 .. 184293
     customer_id (INTEGER) — range 1 .. 5821
     order_date (DATE) · range 2026-01-01 .. 2026-04-30
     amount (REAL) — 12 nulls · range 0.99 .. 19842.50
     category (TEXT) · e.g. electronics, books, home, food, fashion

   First 5 rows:
     1,2381,2026-01-04,128.50,electronics
     ...
   ```
   The full file stays accessible via `csv_query` (below).

2. **Database connections.** Click **Manage Connections…** to add SQLite, PostgreSQL, MySQL, or SQL Server connections. Each gets a `name` you can refer to from the chat. The dialog tests the connection with one click and shows you which Qt SQL drivers are actually installed on your system.

3. **Two new agentic tools** the AI uses on your behalf:
   - **`csv_query(file_path, sql, …)`** — loads the CSV into in-memory SQLite (table name `csv`, column names matching the header), runs your SQL, returns the rows. The model can ask `SELECT category, SUM(amount) FROM csv WHERE order_date >= '2026-04-01' GROUP BY category ORDER BY 2 DESC` instead of trying to mentally scan a million-line file.
   - **`query_sql(connection_name, sql, …)`** — runs SQL against a saved connection. SELECT / WITH / EXPLAIN / PRAGMA / SHOW / DESCRIBE allowed by default. INSERT / UPDATE / DELETE / DDL require an explicit `confirm:true` flag, which the model is instructed to set only after asking you first.

4. **Live charts inline in the chat.** When a visualization clarifies the answer, the model emits a fenced spec:

   ~~~chart
   {"type":"bar","title":"Revenue by category, last 30 days",
    "x":"category","y":"revenue",
    "data":[
      {"category":"electronics","revenue":284921.50},
      {"category":"books","revenue":52183.25},
      {"category":"home","revenue":98442.10}
    ]}
   ~~~

   Notepatra parses each one and renders a **real interactive QChartView** under the assistant's prose. Supported types: `line`, `bar`, `pie`, `scatter`. Theme-aware. If the spec is malformed, the chat falls back to showing the JSON as a code block — nothing breaks.

5. **`.notepatra/data-analyst.md` instruction file.** Drop one in your workspace and its contents are auto-prepended to the system prompt as a "Project data context" layer. Per-workspace, version-controllable, capped at 8 KB. Use it for things like:
   ```markdown
   - The `orders` table joins `customers` on `customer_id`.
   - Treat NULL in `amount` as 0 (legacy import bug, never backfilled).
   - `rate` is a percentage stored as 0–1, not 0–100. Don't average it.
   - Q1 = Jan-Mar, fiscal year matches calendar.
   ```
   Then ask "show me last quarter's top-revenue customers" and the model already knows the schema and quirks.

6. **Model capability gating.** Multi-table SQL and chart-spec emission are harder than `read_file`. When you toggle Data Mode on with a model below the recommended bar (e.g. `llama3.2:1b` or unknown small models), the panel shows an inline orange banner: *"⚠ llama3.2:1b may struggle with multi-table SQL and chart specs. Try one of: Claude 4 Opus / Sonnet, GPT-5 / GPT-4.1 / o3, Gemini 2.5 Pro."* The mode still works — the banner is the heads-up.

## What you'll see in the chat

Ask `summarize this CSV and chart the top categories by revenue`. With a capable model (Claude, GPT-4/5, qwen2.5-coder:14b+, llama3.1:8b+, …), you get:

- A short **Findings** section (top categories, anomalies, outliers).
- A one-sentence **Method** line — what query ran.
- A **chart** rendered live in the chat panel.
- 1–2 **Suggested follow-ups** ("Want a breakdown by month? Want to exclude wholesale orders?").

The structure isn't a UI scaffold — it's how the system prompt asks the model to organize the output, so the experience is consistent across models.

## Honest limitations — read these

1. **Connection passwords are obscured at rest, NOT encrypted.** They live in `~/.config/notepatra/db-connections.json` as XOR + base64. Anyone with the source can decode them — this is for *"don't show plaintext passwords to people walking past my screen"*, NOT *"survives a stolen laptop"*. For production secrets, use OS keychain integration (planned for later), `.pgpass` / `~/.my.cnf`, or instance-role IAM.

2. **Driver availability depends on your Qt install.** SQLite ships with Qt by default — it just works. PostgreSQL / MySQL / SQL Server need separate Qt SQL plugins:
   - **Linux (Debian/Ubuntu):** `sudo apt install libqt5sql5-psql libqt5sql5-mysql libqt5sql5-odbc`
   - **macOS Homebrew:** included in `brew install qt@5`
   - **Windows:** install via `aqtinstall` or the Qt installer; the Notepatra Windows release ships with the matching plugin DLLs.

   The Manage Connections… dialog tells you exactly which drivers are missing on your system.

3. **Chart rendering uses QtCharts.** That adds about 4 MB to the binary, but in exchange you get real interactive charts that respect your theme and don't need a browser engine.

4. **CSV ingestion caps at 250,000 rows by default** for `csv_query` (configurable via `max_load_rows`). That's enough for typical analysis; if you have a larger file, query the underlying database instead.

5. **Mutations are explicitly gated.** `query_sql` refuses INSERT / UPDATE / DELETE / DDL unless you've approved them. The model is told to ask first. There is no "yolo mode" — by design.

## What's NOT in v0.1.43 (deferred)

- **PPT / image data extraction** — for now, attaching a `.pptx` falls back to the existing text extractor; chart images aren't OCR'd into structured data. v0.1.44+ candidate.
- **Real OS-keychain integration for connection passwords.** The XOR obscuration is a placeholder. v0.1.44+ candidate.
- **Multi-series charts** — current `chart` spec supports a single `x` / `y` per chart. Multi-line / stacked-bar charts are a v0.1.44+ extension.
- **Chart export** to PNG / SVG. The QChartView is interactive; you can right-click → Save image as a workaround.
