# Notepatra v0.1.60 — Stale-text drift killed + wired audit

**Date:** 2026-05-10
**Tag:** `v0.1.60`
**Build:** Linux x64 / Linux ARM64 / macOS Apple Silicon / Windows x64

---

## Summary

A 24-hour follow-up to v0.1.59. v0.1.59 shipped with the in-app **About** dialog still claiming *"100+ file types · 48 language lexers · Local AI via Ollama / llama.cpp / OpenAI-compatible"* — frozen since v0.1.31. The version *number* itself flowed correctly through the `NOTEPATRA_VERSION` compile define, but the **hardcoded feature counts in the About body string did not**. The GitHub repo description (rendered on github.com and in every search snippet linking the repo) was even further out of sync — *"~4 MB bare binary, 100+ file types, local AI via Ollama / llama.cpp / OpenAI-compatible"* — frozen at maybe v0.1.20-era numbers.

Two fixes:

1. **Get every surface to the truth.**
2. **Wire it so this can't drift again.**

---

## What changed

### 🪪 About dialog now states the real numbers

`src/mainwindow.cpp:3411` was hardcoded at `100+ file types · 48 language lexers` and `Local AI via Ollama / llama.cpp / OpenAI-compatible`. Updated to:

> 226 file extensions · 92 language lexers. Plugin system. 2 GB files.
> 6 AI backends — Ollama / llama.cpp / OpenRouter / Ollama Cloud / OpenAI / Azure OpenAI. Zero telemetry.

The GitHub repo description (`gh repo edit`) now reads:

> Native C++/Rust code editor for the AI era — Linux/macOS/Windows, ~9 MB bare binary, 226 file extensions / 92 language lexers, Rust-powered search, 6 AI backends (Ollama / llama.cpp / OpenRouter / Ollama Cloud / OpenAI / Azure OpenAI). Free forever, GPL-3.0.

### 🔧 Wired stale-text audit so this can't drift again

New `scripts/stale-text-check.sh` — canonical counts at the top:

```bash
LEXER_COUNT=92
FILE_EXT_COUNT=226
BACKEND_COUNT=6
BACKEND_LIST="Ollama / llama.cpp / OpenRouter / Ollama Cloud / OpenAI / Azure OpenAI"
```

…then 21 grep-asserts across every surface that has ever drifted:

* App About body (`src/mainwindow.cpp`) — file-extension count, lexer count, backend count, full backend list
* `README.md` — intro stat line, releases-table row for current tag
* `docs/index.html` — stat cards (`>226</span>...File Types`, `>92</span>...Language Lexers`), meta description, current version-card
* `docs/docs.html` — `92 language lexers as of vX` line + `Latest release is vX` callout
* `CHANGELOG.md` — top entry is the current version
* `release_notes/vX.md` exists for the current tag
* **Live GitHub repo description** — queried via `gh repo view --json description`, asserted to contain canonical counts

The script is **wired into `scripts/release-check.sh`** as a sub-step under `── stale-text audit (feature counts) ──`. Running release-check before tagging now runs the audit automatically; failures point at the exact surface that drifted with the line that needs fixing.

When a count actually changes (a lexer is added, a backend retires, etc.), bump the constant at the top of the script *and* every surface in the same commit. The script tells you which surface still has the old value if you miss one.

### 🧹 Misc stale-text cleanups

* `.github/ISSUE_TEMPLATE/bug_report.yml` — version placeholder `v0.1.8` (frozen since April) → `v0.1.60`.
* `SECURITY.md` — five SHA-256 / cosign / SLSA verification examples bumped from `releases/download/v0.1.0/` to `releases/download/v0.1.60/` so copy-paste commands work without noticing the URL is for the very first release.
* `AGENTS.md` — local test-build command replaced a five-test list (`test_lexers test_palette test_fmtpanel_diff test_ollama test_aifix`) with the `notepatra_all_tests` meta-target so contributors don't miss any of the 26 test binaries.
* `src/mainwindow.cpp` — Language-menu code comment count fixed from `"78 languages"` (frozen at v0.1.55) to `"92 lexers / 226 file extensions"`.

## Why

> *"this is not my job, you have to find and update memory and be very aware for everything we update and we will be doing very frequently — I cannot be doing this. We have to wire it."*

Manual checklists rot. Wired checks don't.
