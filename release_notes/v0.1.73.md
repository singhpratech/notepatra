# Notepatra v0.1.73 — AI dock blank-on-reopen fix

Released: 2026-05-11

Single-issue patch on top of v0.1.72.  No new features, no scope
changes — just two coordinated fixes for the AI dock close → reopen
flow.

## The bug

> "AI toggle is working fine, but when I close using the red ✕ button
> and then click [the toolbar AI button] to bring it back, then all
> goes blank."

Reproducible immediately after v0.1.72 shipped.  Reported during the
post-release sanity walk-through.

## Root cause

Two coupled issues in the AI dock visibility path:

1. **The red ✕ close button in the AI panel header bypassed the
   canonical hide handler.**  Its click handler called
   `parentWidget()->setVisible(false)` directly, which:
   - Did NOT update `Config::aiDockVisible` (so on next launch the
     dock came back even though the user had clicked × to close it).
   - Did NOT update the toolbar AI button's checked state (so it
     stayed visually "on" while the dock was hidden).
   - Did NOT call `exitAiFullscreenIfActive()` — so a × close while
     in fullscreen left sibling widgets hidden.
   - Most importantly: did NOT go through `setAiDockVisible()`'s
     splitter-rebalance bookkeeping path.

2. **`rebalanceAiDockSplit()` bailed unconditionally on
   `m_aiDockSizedOnce`.**  That flag was meant to prevent clobbering
   the user's mid-session splitter drag, but after a full hide-then-
   show cycle Qt's `QSplitter` leaves the hidden widget's slot at
   ~0 px.  `setVisible(true)` alone doesn't restore the slot width
   — without an explicit `setSizes()` the user sees a 0-px wide,
   visually-empty dock.

The two layered like this: × close went through the un-canonical path
(issue 1) so by the time the toolbar tried to re-open, the splitter
slot was 0 px and `rebalanceAiDockSplit()` refused to rescue it
(issue 2).

## Fix

### `src/aipanel.{h,cpp}` — close button emits a signal

```cpp
// aipanel.h — new signal
void closeDockRequested();

// aipanel.cpp — close button handler
connect(closeBtn, &QPushButton::clicked, this, [this]() {
    emit closeDockRequested();
});
```

The AIPanel no longer pokes its grandparent's visibility directly.
It announces "user wants the dock closed" and MainWindow handles it.

### `src/mainwindow.cpp` — canonical hide via the signal

```cpp
connect(m_aiDockPanel, &AIPanel::closeDockRequested, this, [this]() {
    setAiDockVisible(false);
});
```

`setAiDockVisible(false)` is the single source of truth for hiding the
dock: persists `Config::aiDockVisible = false`, calls
`exitAiFullscreenIfActive()`, hides the file explorer (which is gated
on dock visibility + coding mode), and updates the toolbar button.

### `src/mainwindow.cpp` — `rebalanceAiDockSplit()` rescues 0-px slot

```cpp
// Inside rebalanceAiDockSplit() — replaces the unconditional
// `if (m_aiDockSizedOnce) return;` bailout.
int aiSlotW = 0;
if (m_aiDockHost) {
    const QList<int> cur = m_splitter->sizes();
    for (int i = 0; i < m_splitter->count() && i < cur.size(); ++i) {
        if (m_splitter->widget(i) == m_aiDockHost) {
            aiSlotW = cur.at(i);
            break;
        }
    }
}
// Threshold of 40 px: anything below that is "collapsed" — too small
// to be a deliberate user drag.
if (m_aiDockSizedOnce && aiSlotW > 40) return;
```

The mid-session-drag preservation still works (drag the splitter to
70/30, click toolbar to toggle, re-open: width survives).  But a full
hide-show cycle that leaves the slot at 0 px now triggers the 60/40
default re-application.

## Regression tests (`test_ai_fullscreen_exit.cpp`)

Added two new scenarios — both FAIL on v0.1.72 and PASS on v0.1.73:

- **S16: hide-show cycle restores dock width** — drives
  `setAiDockVisible(false)` → `setAiDockVisible(true)` and asserts the
  reopened dock has > 50 px width.
- **S17: red ✕ close → toolbar re-open works** — finds the × button
  by tool-tip, clicks it, then re-opens via `setAiDockVisible(true)`,
  asserts the dock has > 50 px width AND `Config::aiDockVisible` was
  updated by the click handler.

53 sub-checks total in `test_ai_fullscreen_exit` (up from 47 in
v0.1.72), 28/28 ctest pass on the lite build.

## Out of scope

  `notepatra-local-ai` build) all carry forward unchanged.

  `test_network_policy` allowlist stays.
