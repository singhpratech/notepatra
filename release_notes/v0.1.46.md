# Notepatra v0.1.46 — hotfix on top of v0.1.45

**Released**: 2026-05-08

A one-line bug from v0.1.45.

## What broke

v0.1.45 added stacked history to the bottom-docked `SearchResultsPanel`,
but the most-common code path — `doFindAllCurrent`, triggered by the
**Find All in Current** button on the Find tab — still called
`sr->clear()` BEFORE the new `beginSession()` call. So every single-file
search wiped the panel's entire history right before adding the new
session. Symptom: only ever one session visible; previous searches
always gone.

## Fix

Removed the stale `sr->clear()` from `doFindAllCurrent`. All three Find
paths in `findreplace.cpp` now have consistent behaviour:

- **Find All in Current** (Find tab) → `beginSession(needle)` → add files
  → final `setHeader` for the totals.
- **Find All in All Opened** (Find tab) → `beginSession(needle)` → add
  files → final `setHeader`.
- **Find All** (Find in Files tab) → uses its own in-dialog text widget
  (`m_resultsOutput`), unrelated to `SearchResultsPanel`.

After the fix:
- Press **Find All in Current** with `pwd` → new session row at top.
- Press **Find All in Current** with `host` → new session row at top,
  `pwd` collapses below it.
- 10 sessions cap; oldest pruned.

`clear()` is now reserved for an explicit user action (close the panel
and reopen — or a future "Clear history" button on the panel itself).

## Files changed

- `src/findreplace.cpp` — single `sr->clear()` line removed from
  `doFindAllCurrent`.
- `CMakeLists.txt` — `0.1.45 → 0.1.46`.
