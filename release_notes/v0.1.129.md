# Notepatra v0.1.129

**`ssh-keygen` puts your username and your machine's name into every key it makes. This one leaves the comment blank.**

The Password Generator grows a third page. The two radio buttons are now a left rail — **Password**, **Passphrase**, **SSH key** (`Alt+1` / `Alt+2` / `Alt+3`) — and the menu entry reads `Tools → Password Generator — Passwords / Passphrases / SSH keys`. It still ships in every build including the default Lite binary, and all three pages work with the machine offline.

The other half of the release is the diagram tool: `.npd` diagrams are now drawn flat, gain two light palettes and a theme-following default, and learn to draw groups, notes, legends and dashed edges.

## SSH keys

| Key type | Strength | When to pick it |
|---|---|---|
| **Ed25519** — recommended | 256-bit key, ~128-bit security | The default for new keys. One short line in `authorized_keys`, fast to sign with, constant-time by construction. OpenSSH 6.5 and newer — everything shipped since 2014. |
| ECDSA P-256 | ~128-bit security | Only when a policy names a NIST curve — a FIPS-constrained environment, or a smartcard that offers nothing else. |
| ECDSA P-384 | ~192-bit security | The same case, when the policy asks for more than 128-bit strength. |
| RSA 3072 | ~128-bit security | For an old server or a hardware token that cannot do Ed25519. The size that matches Ed25519's strength. |
| RSA 4096 | ~140-bit security | The same old-server case. The extra bits buy little over 3072 and cost noticeably more on every connection. |
| RSA 2048 — legacy | ~112-bit security | The smallest size still worth issuing, and only for hardware that refuses anything bigger. |

**The comment field is empty by default, and that is the feature.** `ssh-keygen` fills it with `user@host`. That string is not decoration: it travels with the public key into every `authorized_keys` file the key is ever pasted into, on servers you do not control, and it tells anyone who reads that file your account name and the name of your machine. Type a label if you want one — `work-laptop` — but nothing is written there for you.

**An optional passphrase encrypts the private key** with `aes256-ctr` and `bcrypt-pbkdf` at 16 rounds — the same construction `ssh-keygen` writes, asserted by a test, so `ssh-add` and every other OpenSSH tool read the file directly.

**The public line and its SHA256 fingerprint appear as soon as the key exists; the private key does not.** It stays off-screen until you tick **Show private key**. **Copy private key** arms the 30-second clipboard wipe; **Copy public key** does not, because a public key is not a secret.

**Save private key…** creates the file, sets it to `0600`, and *then* writes the bytes, so the key is never briefly world-readable. It refuses to overwrite an existing file — pick another name rather than losing a key you still use — and writes the `.pub` companion at `0644` beside it. The suggested name follows the key type: `id_ed25519`, `id_ecdsa`, `id_rsa`.

**Generation runs off the GUI thread.** Ed25519 is effectively instant. RSA-4096 measured between 1.6 and 5.9 seconds, during which the button reads *Generating…* and the window keeps painting.

**It is checked against OpenSSH itself.** The test suite runs the system `ssh-keygen` over generated keys: `-y` reproduces the same public line, `-lf` the same fingerprint, and `-y -P` opens the encrypted key and rejects the wrong passphrase.

### What to do with the key

```
# 1. Save the private key from the panel:  ~/.ssh/id_ed25519
#    (the .pub companion is written beside it)

# 2. Load it into the agent — passphrase once per session.
ssh-add ~/.ssh/id_ed25519

# 3. Put the PUBLIC line on the server.
ssh-copy-id -i ~/.ssh/id_ed25519.pub you@server
#    …or paste it yourself into ~/.ssh/authorized_keys on the server,
#    one key per line, file 0600 inside a 0700 ~/.ssh

# 4. GitHub / GitLab: Settings → SSH keys → New key, paste the same line.

# 5. Verify.
ssh -T git@github.com
ssh-keygen -lf ~/.ssh/id_ed25519.pub    # the fingerprint the panel showed
```

Never paste the private key anywhere. The only thing that leaves the machine is the public line — the one the panel shows without being asked.

## Where the randomness comes from — changed

**Every draw now goes through the OS random source** (`getrandom` on Linux, the platform equivalent elsewhere) by way of the Rust core. That covers the SSH keys *and* every password and passphrase. `QRandomGenerator::system()` is now the fallback, not the source.

This is a correction, not a boast. Before v0.1.129 the source was Qt's generator, and on x86-64 Qt fills from the CPU's **RDRAND** instruction first — measured under `strace` on a release build, ~7 million draws issued *zero* `getrandom` syscalls. A reader who took "the OS CSPRNG" at face value was reading about something else. Now the sentence and the syscall agree.

Nothing downstream changed: rejection sampling still keeps every character equally likely, and *At least one from each set* is still enforced by drawing the whole value again rather than placing one character per set and shuffling — so the bits figure means exactly what it meant in v0.1.128.

The cost is about **0.6 MB** of binary for the pure-Rust crypto (RustCrypto `ssh-key` 0.6.7). No new runtime dependency, no download, no network.

## Diagrams (`.npd`)

**Flat rendering.** No gradients, no drop shadows: a 1.5 px border, the application's own font, and a tighter grid. It reads like something drawn for a design document rather than for a slide.

**Light palettes.** `paper` and `slate` join the dark ones, and **`palette auto` is the new default** — the palette a file gets when it names none. It follows the app theme (light → `paper`, dark → `default`) and re-renders when the theme changes. A per-node colour now renders as a **tint** on a light ground — soft wash, full-strength border, normal dark text — instead of a solid fill.

**New grammar:**

```
direction LR                         TB (top-down, default) | LR
a -.-> b                             dashed — async / optional / best-effort
a <.-> b                             dashed, both ways
group "Edge tier" : cdn api          a labelled container behind those nodes
note api "Rate-limited to 100 rps"   a card pinned beside the node
legend dashed "async"                legend row — dashed swatch
legend #cc785c "hot path"            legend row — colour swatch
```

Every id in a `group` must be a real node, and a node belongs to one group only. The legend box is drawn only when the file has at least one `legend` line. **Import Mermaid** now maps `-.->` to a dashed edge and `subgraph … end` to a `group`.

## Regressions and known issues

- **Existing `.npd` files without a `palette` line will look different.** They now resolve to `palette auto`, so on a light theme they render light where they used to render dark. Add an explicit `palette default` — or any named dark palette — to the file to pin the old appearance.
- **`group`, `note`, `legend`, `direction` and `layout` are now reserved words.** A diagram that used one of them as a *node id* must rename that id; it will no longer parse as a node.
- **Windows does not set the `0600` permission** on a saved private key. The call is POSIX and is skipped there, so the file inherits whatever the parent folder grants — check the file's permissions and tighten them yourself after saving.
- **RSA-4096 can take several seconds** — 1.6 to 5.9 s measured. That is the algorithm, not a hang; the button reads *Generating…* and the UI stays live. Ed25519 is instant.
- **The 30-second clipboard wipe cannot reach a clipboard-history tool.** It removes the value only if the system clipboard still holds it. A clipboard manager that already stored the entry, or a clipboard synced to another device, keeps its copy — that is outside the editor's reach.
- **A `note` widens the row it sits in.** Notes are placed to the right of their node (below it under `direction LR`) and the layout reserves the space, so a long note spreads the diagram. Keep note text short.
- **Mermaid bare ids inside a `subgraph` are not grouped yet.** A node that appears in the block only as a naked id — no shape, no edge — is imported but ends up outside the generated `group`.
- **An open advisory rides along with the RSA key types: RUSTSEC-2023-0071 against `rsa` 0.9.10**, which `ssh-key` 0.6.7 pulls in. The advisory — the Marvin attack — describes a timing sidechannel in RSA *private-key operations*, that is decryption and signing, and the crate has no fixed release to move to. Notepatra uses it to **generate** a key pair and never signs or decrypts with it, and the Ed25519 and ECDSA paths go through different crates entirely (`ed25519-dalek`, `p256`, `p384`), so it is carried as a documented ignore in `rust-core/.cargo/audit.toml` rather than silently. It is named here because you deserve to know it is in the tree, and because it is one more reason the default is Ed25519.

## Verification

Per-suite assertion counts from this release: `test_passwordgen` **67**, `test_passwordgen_panel` **99**, `test_npd_parser` **117**, `test_mermaid_import` **44**, `test_diagram_view` **19**, plus **175** Rust tests in `rust-core`. Full offscreen `ctest` is **79/79 green**.

`test_diagram_view` is new in this release. The SSH interoperability tests shell out to the system `ssh-keygen` and are skipped where it is not installed, so a green run on a machine without OpenSSH proves less than one with it — CI has it.
