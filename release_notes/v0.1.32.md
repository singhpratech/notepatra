# Notepatra v0.1.32 — PowerShell hotfix + per-language brand palettes

**Released:** 2026-04-26

Two issues addressed:

1. **PowerShell `New-Object` rendering as default text** — actual bug, confirmed on the user's Windows screenshot. Keyword-set ordering was off-by-one against Scintilla's `SCI_SETKEYWORDS` slots.
2. **Python / SQL / JSON / PowerShell all looking like generic blue+violet** — per-language brand palettes restored, driven by deep multi-editor research (N++ + VS Code Dark+/Light+ + PowerShell ISE + SSMS + PyCharm Darcula + Sublime Mariana).

---

## 1. PowerShell highlighting bug fix

### The bug

User shared a Windows screenshot showing `New-Object` rendering as plain white text in a `.ps1` file, instead of being highlighted as a cmdlet.

### The root cause

`LexerPowerShell::keywords(int set)` had its keyword sets misordered against Scintilla's `SCI_SETKEYWORDS` slots. QScintilla's `keywords(int set)` API is **1-based**, but maps to Scintilla's **0-based** slot index (`set N` → `SCI_SETKEYWORDS(N-1, ...)`).

Pre-v0.1.32:

| `keywords(set)` | Old payload (wrong) | Scintilla idx | What Scintilla calls this | What the lexer rendered |
|---|---|---|---|---|
| set 1 | control-flow keywords | 0 | PowerShell Keywords | ✓ correct |
| set 2 | `-eq`, `-ne`, `-and`, ... | 1 | **Cmdlets** | operators got cmdlet style 9 (wrong, but accidentally invisible) |
| set 3 | `Add Get Set New ...` (Approved Verbs) | 2 | **Aliases** | verbs got alias style 10 |
| set 4 | `ls cd gci ...` (real aliases) | 3 | **Functions** | aliases got function style 11 |
| set 5 | `New-Object Get-Item ...` | 4 | **User1** | full cmdlets got User1 style 12 — and **the palette didn't theme User1**, so they fell through to default text colour (white on dark) |

That's why `New-Object` was white.

### The fix

Sets reordered to match Scintilla's contract:

| `keywords(set)` | New payload | Scintilla idx | What Scintilla colours it |
|---|---|---|---|
| set 1 | Control-flow keywords (`begin`, `break`, `function`, `if`, `foreach`, `param`, ...) | 0 | Keyword (style 8) → blue bold |
| set 2 | Full Verb-Noun cmdlets (`New-Object`, `Get-Item`, `Where-Object`, ...) + Approved Verbs (`Add`, `Get`, `Set`, `New`, ...) | 1 | **Cmdlet (style 9) → blue (light) / cyan (dark)** |
| set 3 | Aliases (`ls`, `cd`, `gci`, ...) | 2 | Alias (style 10) → lighter cyan |
| set 4 | (empty — Functions slot reserved for user-defined function names) | 3 | Function (style 11) |
| set 5 | .NET type names for `[type]` literals (`string`, `int`, `datetime`, ...) | 4 | User1 (style 12) |

Operators (`-eq`, `-ne`, `-and`) removed from the keyword sets entirely — Scintilla's PowerShell lexer recognises the `-word` prefix natively as an operator without needing a keyword list.

`New-Object` now paints as a cmdlet on every theme.

## 2. PowerShell ISE canonical palette

Microsoft's PowerShell ISE has a signature triple of colours that PowerShell users from Windows have muscle memory for. Microsoft preserves the same three colours in the official "PowerShell ISE" theme bundled with the VS Code PowerShell extension. v0.1.32 mirrors them:

| Token | Light | Dark | Source |
|---|---|---|---|
| `$variable` | **`#FF4500` OrangeRed** | `#FF7F50` Coral | ISE TokenColor.Variable + VS Code PS-ISE theme |
| Cmdlet (`New-Object`) | **`#0000FF` blue** | `#9CDCFE` light-blue | ISE TokenColor.Command + VS Code PS-ISE theme |
| Alias (`ls`, `gci`) | `#0080FF` lighter blue | `#9CDCFE` light-blue | distinct from cmdlets |
| Comment (`#`) | `#008000` green italic | `#7F9F7F` sage italic | inherited from generic palette |
| String (`'..'` / `"..."`) | `#808080` grey | `#CC9393` rose | inherited |
| Number | `#FF8000` orange | `#8CD0D3` cyan | inherited |
| Keyword (`function`, `if`, `foreach`) | `#0000FF` blue bold | `#DFC47D` warm sand bold | inherited |
| Operator (`+ - = -eq`) | `#000080` navy bold | `#9F9D6D` olive bold | inherited |

The `$variable` orangered is the most distinctive PS-only signature — open any `.ps1` and you can tell it's PowerShell at a glance.

## 3. Per-language brand palettes (the "Python and SQL look the same" complaint)

v0.1.31 had pruned per-language overrides aggressively, leaving Python, SQL, JavaScript, TypeScript, C/C++ all using the same generic blue+violet palette. v0.1.32 restores brand-distinct accents for the most-used languages, driven by data from a multi-editor palette research pass:

### Python — VS Code Dark+ canonical

| Token | Light | Dark | Source |
|---|---|---|---|
| Keyword (`def`, `class`, `if`, `return`) | `#0000FF` blue bold | `#DFC47D` warm sand bold | Consensus across N++ Light + VS Code Light+/Dark+ (PyCharm's orange `#CC7832` is an outlier) |
| Built-ins / types (`print`, `len`, `int`, `str`) | `#267F99` teal | `#4EC9B0` teal | VS Code Dark+ Python type colour |
| Function / class names | `#795E26` amber | `#DCDCAA` amber | VS Code Dark+ entity.name.function |
| Decorator `@property` | `#FF8000` orange italic | `#93E0E3` cyan italic | npDecorator (generic) |
| String, number, comment, operator | (generic palette) | (generic palette) | |

### SQL — SSMS canonical

| Token | Light | Dark | Source |
|---|---|---|---|
| Keyword (`SELECT`, `FROM`, `WHERE`, `JOIN`) | `#0000FF` blue bold | `#DFC47D` warm sand bold | SSMS + N++ canonical |
| **System functions / types** (`COUNT`, `SUM`, `INT`, `VARCHAR`, `DATETIME`) | **`#FF00FF` MAGENTA** | `#C586C0` magenta-ish | **SSMS signature** — Microsoft's official colour-coding doc lists system functions in magenta |
| String (`'..'`) | `#808080` grey | `#CC9393` rose | inherited |
| Comment (`-- /* */`) | `#008000` green italic | `#7F9F7F` sage italic | inherited |
| Number | `#FF8000` orange | `#8CD0D3` cyan | inherited |

The blue+magenta combo is what makes a `.sql` file feel like SQL — instantly recognisable to anyone who has used SSMS.

### JSON — VS Code Light+/Dark+ canonical

| Token | Light | Dark | Source |
|---|---|---|---|
| Property key (`"name":`) | **`#0451A5` JSON-blue** | `#9CDCFE` light-blue | VS Code meta.structure.dictionary.key |
| Boolean / null (`true`, `false`, `null`) | `#0000FF` blue bold | `#569CD6` blue bold | VS Code constant.language |
| String value | `#808080` grey | `#CC9393` rose | inherited |
| Number | `#FF8000` orange | `#8CD0D3` cyan | inherited |
| Operator (`{}[],:`) | `#000080` navy bold | `#9F9D6D` olive bold | inherited |

Five clearly distinct token kinds per JSON file: keys (dark JSON-blue), booleans (bright blue), strings (grey/rose), numbers (orange/cyan), operators (navy/olive bold).

### JavaScript / TypeScript / CoffeeScript — VS Code Dark+ canonical

Industry default. Keywords blue, types teal `#4EC9B0` dark / `#267F99` light, function/class names amber `#DCDCAA` dark / `#795E26` light.

### C / C++ / C# — VS Code teal types

Secondary keywords (type names like `int`, `char`, `std::string`) paint VS Code teal `#267F99` light / `#4EC9B0` dark, the de-facto C-family expectation. v0.1.31 had used N++ canonical violet, but VS Code's teal is far more familiar to C-family devs.

### Bash — purple secondary keywords

Built-ins (`echo`, `cd`, `read`) and shell-keyword2 paint violet `#8000FF` light / `#CEDF99` sage dark — distinct from the primary control-flow blue keywords.

### Languages keeping their existing brand (no v0.1.32 change)

- **Rust** — rust-amber `#DEA584` keywords + teal types
- **Go** — Go-cyan `#00ADD8`
- **Swift** — Xcode-pink keywords + Swift-orange attributes
- **Kotlin** — Darcula-orange `#CC7832` keywords + gold `#FFC66D` types
- **Java** — IntelliJ navy / Darcula
- **D** — red brick / coral
- **HTML / PHP** — tag-blue + attribute-red
- **CSS** — selector-violet + property-red
- **XML** — tag-blue
- **Ruby** — ruby-red `#CC342D`
- **Markdown** — blue headers + maroon emphasis

## 4. New `property` matcher

Added `d.contains("property")` to `applyNotepadPlusPalette`'s style-kind matcher chain. Without this matcher, JSON property keys (description "Property name") fell through to default text colour. Now they pick up the per-language `npKeyword2` so:

- JSON keys paint `#0451A5` light / `#9CDCFE` dark
- CSS property names paint via the CSS branch's `npKeyword2`
- YAML / TOML keys (when their lexers report a "property" style) paint via the language's `npKeyword2`

## 5. Multi-editor palette research data

Comprehensive hex tables comparing default palettes across:

- **Notepad++** master `stylers.model.xml` (light) + `DarkModeDefault.xml` (dark)
- **VS Code Dark+ / Light+** built-in defaults (`microsoft/vscode` `extensions/theme-defaults/themes/`)
- **PowerShell ISE** classic + the official "PowerShell ISE" theme bundled with the VS Code PowerShell extension
- **SQL Server Management Studio (SSMS)** documented colour-coding
- **PyCharm Darcula** (`JetBrains/intellij-community` `PythonDarcula.xml`)
- **Sublime Text Mariana** default

across 11 languages: Python, PowerShell, SQL, JSON, JavaScript, TypeScript, HTML, CSS, Bash, YAML, C/C++, Markdown.

Key consensus findings:
- **Comments are always green** (variants: `#008000` light / `#6A9955` or `#7F9F7F` dark) — universal.
- **Strings are always warm** (red / orange-brown / dusty-pink) — never blue.
- **Numbers are orange-warm or pale-green-cool** — never blue.
- **`$variable` in PowerShell**: ISE + MS extension agree on `#FF4500` OrangeRed; VS Code Dark+ generic uses `#9CDCFE`; N++ doesn't theme it at all.

Key disagreements (Notepatra picks a side):
- **Python keyword colour**: Camp Blue (N++/VS Code) vs Camp Orange (PyCharm). Notepatra picks blue (broader convention).
- **HTML tag in light theme**: Camp Blue (N++/VS Code Dark+) vs Camp Maroon (VS Code Light+). Notepatra picks blue.
- **String in dark theme**: Camp Orange-Brown (`#CE9178` VS Code) vs Camp Green (`#99C794` Mariana). Notepatra picks rose/grey (N++ + VS Code consensus).

## Try it

After upgrading:
1. Open a `.ps1` file with `New-Object`, `Get-Item`, `Where-Object` — they paint blue (light) / light-cyan (dark) as cmdlets, no longer white.
2. Use `$variable` — paints OrangeRed `#FF4500` light / coral `#FF7F50` dark, the ISE signature.
3. Open a `.py` file — keywords blue, built-ins (`print`, `len`) teal, function names amber. Distinctly Python-flavoured.
4. Open a `.sql` file — keywords blue, functions (`COUNT`, `SUM`, `INT`) magenta. SSMS-flavoured.
5. Open a `.json` file — keys dark JSON-blue, true/false/null bright keyword-blue, strings grey/rose, numbers orange/cyan. Five clearly distinct tokens.
6. Switch between Python and SQL files — they no longer look identical.
