# Notepatra v0.1.26 — Six new lexers (PowerShell, Rust, Go, Swift, TypeScript, Kotlin) + terminal 256-colour/truecolour + per-response tokens & timing

**Released:** 2026-04-25

A focused polish release that fixes a long-standing pile of "wrong syntax highlighting" complaints and several smaller UX papercuts.

---

## What changed

### 🎨 Six new lexer subclasses

QScintilla doesn't ship lexers for several modern languages, and Notepatra was routing them to wrong-but-close existing lexers — sometimes catastrophically wrong:

| Extension | Was routed to | Now routed to |
|---|---|---|
| `.ps1`, `.psm1`, `.psd1` | **Batch (cmd.exe)** | **PowerShell** (Scintilla `SCLEX_POWERSHELL`) |
| `.rs` | C++ | **Rust** (custom keyword set) |
| `.go` | C++ | **Go** (custom keyword set) |
| `.swift` | C++ | **Swift** (custom keyword set) |
| `.ts`, `.tsx`, `.mts`, `.cts` | JavaScript | **TypeScript** (TS-only keywords) |
| `.kt`, `.kts`, `.ktm` | Java | **Kotlin** (Kotlin keywords) |

The PowerShell case was the worst — `REM` was treated as a comment in PowerShell files, `$variables` weren't recognised at all, here-strings (`@"..."@`) rendered as garbage. Now PowerShell scripts get proper highlighting for cmdlets (`Get-Process`), variables (`$env:VAR`), comparison operators (`-eq -ne -lt -gt`), here-strings, and stream comments (`<# ... #>`).

### 🎨 16 additional language extensions

| Family | Extensions added |
|---|---|
| Web / mobile | `.dart` |
| Systems | `.zig`, `.zon`, `.vlang`, `.odin` |
| JVM | `.scala`, `.sc`, `.groovy`, `.gradle` |
| Functional | `.hs`, `.lhs`, `.ml`, `.mli`, `.fs`, `.fsx`, `.fsi`, `.clj`, `.cljs`, `.cljc`, `.edn`, `.elm` |
| Scripting | `.nim`, `.nims`, `.jl`, `.awk`, `.cr` |
| Erlang | `.ex`, `.exs`, `.erl`, `.hrl` |

Each routed to its closest-fit existing lexer with custom keyword overrides where impactful.

### 📺 Terminal upgrade — 256-colour, truecolour, italic, faint, strikethrough

The pre-v0.1.26 terminal claimed 256-colour and truecolour support in its comments but the parser only handled 16-colour 30-37/40-47 + bold + underline. Modern CLIs (`bat`, `eza`, `fzf`, `delta`, `gh`, recent `cargo`/`npm`) emit `38;5;N` and `38;2;R;G;B` sequences which leaked through as literal digits — `bat foo.py` looked like a wall of `5;208m` fragments instead of syntax-highlighted code.

The upgraded `ansiToHtml()` now handles the full SGR spec real CLIs use:

```
0  reset
1  bold        2  faint           3  italic
4  underline   9  strikethrough
22 normal-intensity (cancel bold/faint)
23 not-italic  24 not-underline   29 not-strikethrough
30-37 FG       40-47 BG           39 default FG     49 default BG
90-97 bright FG                   100-107 bright BG
38;5;N  / 48;5;N             ← 256-colour palette
38;2;R;G;B / 48;2;R;G;B      ← 24-bit truecolour
```

Channel values clamped to `[0, 255]` for malformed truecolour input. Cancel-attribute codes (22/23/24/29) work, so tools that toggle styling mid-line (`man`, `git diff`) render without "stuck" attributes.

### 🤖 AI Assistant: per-response tokens + elapsed time

Every assistant bubble's header now shows the response cost:

```
QWEN3.5:2B          1234 tok · 123.4 tok/s · 2.3 s          ⧉ copy
```

Captured from:
- **Ollama**: `eval_count` (response tokens) + `prompt_eval_count` + wall-clock timing
- **OpenAI-compat backends**: `usage.completion_tokens` + `usage.prompt_tokens` + wall-clock timing

Tokens-per-second is only shown for runs longer than 200 ms (avoids divide-by-tiny-number noise on cached responses). Wall-clock elapsed time is always shown — works on every backend regardless of whether stats are reported.

### 🪟 Windows fixes

**`Think` checkbox no longer disappears when Coding Mode is enabled.** Previously `setVisible(!checked)` made it vanish, which was confusing UX. Now it stays visible but greyed-out with an explanatory tooltip:

> *Disabled while Coding Mode is on — Coding Mode forces code-only output, so reasoning blocks would interfere with the [Apply] button paste. Turn Coding Mode off to use thinking mode.*

**Mystery circle in AI input bar suppressed.** Qt's default scroll-area corner widget was being painted as a tiny grey dot in the bottom-right of the input box on Windows native style. Killed via `setCornerWidget(nullptr)` plus zero-height styling on the vertical scrollbar's add/sub-line buttons.

### 📏 Documentation truth-pass

User reported that the Windows install footprint on disk was around 75 MB and asked if we were over-promoting size. Audited `gh release view v0.1.25` against the README/website and found we'd been over-promoting download sizes by 1-2 MB across the board (an artefact of an earlier "size sync" that mis-bumped values). Six size strings corrected in README, six in the website. Added an explicit clarification:

- **Download size**: the `.msi` / `.dmg` / `.tar.gz` file size (~43.5 MB Windows MSI)
- **Installed footprint**: ~75-85 MB on Windows because the MSI extracts bundled Qt5 + QScintilla DLLs out of the compressed payload — normal for any Qt-based installer (KDE, Krita, Kdenlive all do the same)
- **Linux installs stay tiny** (~5 MB on disk) because Qt5 comes from the distro repo

VS Code is 300+ MB downloaded **and** 350+ MB installed — Notepatra is 6× to 14× smaller on every platform, in either direction.

## What's not in this release (intentional)

- **`[Open as file]` button on AI code blocks** — the user requested this ("AI writes Python prime numbers code → click button → primenumbers.py opens in new tab with proper highlighting"). It's a substantial UX-design feature that benefits from more careful thought; deferred to v0.1.27.
- **Native R lexer** with `<-`, `%>%`, R-specific keywords — `.r` files now route to Bash (much better than the old Octave routing) but a proper R lexer is on the v0.1.27 list.
- **Light-theme palette for the terminal** — terminal still uses VS Code dark palette regardless of editor theme, since the terminal frame stays dark. Theme-aware terminal palette is a future polish item.

## Installation

### Linux (AppImage)

```bash
wget https://github.com/singhpratech/notepatra/releases/download/v0.1.26/Notepatra-0.1.26-linux-x86_64.AppImage
chmod +x Notepatra-0.1.26-linux-x86_64.AppImage
./Notepatra-0.1.26-linux-x86_64.AppImage
```

### macOS

```bash
curl -fsSL https://github.com/singhpratech/notepatra/releases/download/v0.1.26/Notepatra-0.1.26.dmg -o ~/Downloads/Notepatra-0.1.26.dmg
open ~/Downloads/Notepatra-0.1.26.dmg
```

### Windows

- **MSI** — `notepatra-0.1.26.msi` (~43-44 MB download, ~75-85 MB installed)
- **NSIS installer** — `notepatra-setup-0.1.26.exe` (~36-37 MB download)
- **Portable ZIP** — `notepatra-windows-x64.zip` (~41-42 MB download, no installer)

### One-command installer scripts

```bash

curl -fsSL https://notepatra.org/install.sh | sh

# Windows PowerShell
irm https://notepatra.org/install.ps1 | iex
```

## Upgrade notes

- The in-app updater from v0.1.20+ will pick this up automatically.
- After upgrading, opening a `.ps1` / `.rs` / `.go` / `.swift` / `.ts` / `.kt` file should immediately show proper syntax highlighting (was wrong before).
- Try `bat foo.py` or `git diff` in Notepatra's terminal — output should now render with full colour, italics where applicable, and no leaked `38;5;` digits.
- AI bubble headers now show response time + token counts. If a backend doesn't report tokens, you'll still see elapsed time.
