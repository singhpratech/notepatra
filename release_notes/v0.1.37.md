# Notepatra v0.1.37 — Comprehensive lexer palette coverage

**Released:** 2026-04-26

User asked: *"keep fixing the palette until we make it right — I want all program lexers to work simply, the keywords / cmdlets / anything easily identified on all themes."*

Done. **1650 styles × 3 themes (Light / Dark / Monokai) = 0 gaps.**

---

## What got fixed

### The audit

A new `test_lexer_coverage` test walks every QScintilla lexer + all 6 Notepatra-local lexers (28 total) on Light / Dark / Monokai and asserts that no non-Default style description falls through to the default-text colour. Pre-v0.1.37 the audit found **359 gaps**:

```
30 — Escape sequence       (C++, JS, Rust, Go, Swift, Kotlin, TS — \n \t \uXXXX in strings)
27 — Task marker           (TODO / FIXME / XXX comments)
27 — IDL UUID              (CORBA / COM-style UUID literals)
22 — Operator on Monokai   (npOperator=#F8F8F2, identical to text colour — invisible)
 9 — Label                 (Bash, makefile targets, goto labels)
 9 — Here document         (Bash / Perl heredoc bodies + delimiters)
 6 each — Unquoted HTML value, PHP/XML/ASP fragments, SGML command, Scalar, POD,
          CDATA, Data section, Single-quoted heredoc, ...
 3 each — Module name, Media rule, MACRO block, JSON-LD IRI, Inline asm,
          Important, ID selector, Hash, FOREACH/IF/WHILE blocks,
          External command, Lua coroutines/IO subsets, Code block, Array,
          YAML Reference / Document delimiter / Text block marker,
          Markdown Strike out / Unordered list item / Special / Pre-char,
          Diff Removed/Added/Changed lines, CSS @-rule, ...
```

### The fix

Three-pronged:

**1. ~30 new matchers** added to the `applyNotepadPlusPalette` chain in `src/npp_palette.cpp`, before the catch-all identifier fallback. Each routes a style-kind to a semantically-appropriate accent:

| Style kind | Routes to | Why |
|---|---|---|
| Escape sequence (`\n`, `\xNN`) | `npRegex` | Distinct from string body, like regex literals |
| Task marker (TODO/FIXME) | `npError` bold | Attention-grabbing |
| IDL UUID | `npClassName` | Niche / muted accent |
| Here document | `npString` | Heredocs are strings |
| Scalar / Symbol / Substitution | `npVariable` | Variable-shaped tokens |
| POD | `npComment` italic | Comment-shaped block |
| Label / Target | `npClassName` bold | Names of flow targets |
| Section (INI/TOML `[foo]`) | `npKeyword` bold | Structure marker |
| Assignment / Default value | `npOperator` | Operator-shaped |
| Key (Properties/TOML left of `=`) | `npKeyword2` | Per-language brand |
| Reference / Anchor / Alias | `npClassName` | YAML named references |
| Document delimiter (`---`) | `npKeyword` bold | Top-level structure |
| List item (Markdown) | `npClassName` | Distinct from text |
| Block quote (Markdown `>`) | `npComment` italic | Quoted = aside |
| Strike (Markdown `~~`) | `npComment` | Greyed out |
| Horizontal rule | `npOperator` bold | Structural |
| Pre-char / Special | `npNumber` | Markup signal |
| SGML / CDATA | `npRegex` | Embedded markup |
| Fragment / Script tag | `npKeyword` bold | Block boundary |
| Entity (`&amp;`) | `npNumber` | Special token |
| `@-rule` (CSS `@media`) | `npKeyword` bold | Top-level directive |
| Removed line (Diff `-`) | `npError` | Deletion |
| Added line (Diff `+`) | `npComment` (green) | Insertion |
| Changed | `npNumber` | Modification |
| Position (Diff `@@`) | `npClassName` | Header |
| stdout / stdin / stderr | `npComment` | Muted |
| Value | `npString` | RHS |
| Text block marker (YAML `\|`/`>`) | `npNumber` | Block scalar marker |
| Quoted identifier | `npKeyword2` | Special name |
| `WHILE`/`IF`/`FOREACH`/`MACRO` block | `npKeyword` bold | Control-flow |
| Parameter expansion (`${var}`) | `npVariable` | Variable |
| Module name | `npClassName` bold | Namespace |
| Media rule | `npKeyword` bold | CSS at-rule |
| Compact IRI | `npClassName` | URL-shaped |
| Inline asm | `npString` | Embedded code |
| `!important` | `npError` bold | Emphatic |
| ID selector | `npClassName` bold | CSS named selector |
| Hash (CSS color `#FF0000`) | `npNumber` | Numeric literal |
| External command | `npVariable` bold | Shell command |
| Lua coroutines / I/O / system | `npKeyword2` | stdlib subset |
| Code block (Markdown ` ``` `) | `npString` | Embedded text |
| Array | `npVariable` | Variable-shaped |

**2. Monokai operator fix** — `npOperator` was `#F8F8F2` on Monokai (identical to default text), making operators visually invisible. Now `#FD971F` (Monokai amber) — matches the Monokai brand without colliding with any other accent.

**3. New per-language brand overrides:**
- **YAML** — keys, references/anchors, document delimiters all properly themed. YAML's "Identifier" style (which IS the key) special-cased in the identifier matcher to use `npKeyword2` instead of falling to plain text per the v0.1.31 generic identifier rule.
- **Properties / TOML / INI / .env / .gitconfig** — sections, keys, and values get distinct brand colours (was generic blue/violet; per-kind matchers now route correctly).
- **Diff** — `+`/`-`/`@@` lines get red/green/cyan via the new matchers; the brand keeps the keyword colour harmonised for diff headers.

./notepatra
```

```bash

## Try it

After upgrading:
1. Open a `.yaml` file — keys highlight blue, references cyan, `---` document delimiters blue bold
2. Open a `.toml` / `.ini` — sections `[foo]` blue bold, keys blue, values grey
3. Open a `.md` file with lists, block quotes, strikethrough — every element distinct
4. Switch to Monokai theme — operators (`+ - = ( )`) now visible (were invisible pre-v0.1.37)
5. Open a `.diff` / `.patch` — `+` lines green, `-` red, `@@` headers cyan
6. Any C++/Rust/Go/Swift/TS file — `// TODO` markers now red bold; escape sequences (`\n`) distinct from string body

Built with care. Report issues at https://github.com/singhpratech/notepatra/issues.
