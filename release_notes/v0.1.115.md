# Notepatra v0.1.115

**The AI assistant and the Data-analyst mode are now safe by construction. Every way a confused or prompt-injected model could write a file you didn't approve, or run a database mutation behind your back, is closed — and each fix is pinned by a real test that fails fast if the protection is removed. A five-wave hardening sprint (planned, implemented, tested, and adversarially re-verified) took the coding assistant from grade B to A- and the data-analyst piece from C+ to A-. Full ctest 70/70 (three new security/gate test suites, 217 new assertions); 8 red-state proofs; an adversarial re-verification fleet caught and closed a regression a fix itself introduced. No new dependencies, same bare binary, no user-facing feature changes — this is a pure safety, robustness, and quality release.**

### Fixed — Data-analyst database safety
- **Real read-only enforcement, three layers deep.** On-disk databases opened for analysis are now opened *engine-level* read-only (DuckDB `access_mode=READ_ONLY`; the in-memory CSV/Parquet ingestion scratch stays writable). The leading-keyword prefix allowlist that "guarded" reads before is replaced by a **structural SQL classifier** that strips comments and string literals, enforces a single statement, and walks every token — so CTE-wrapped DML (`WITH t AS (DELETE … RETURNING *) …`), `EXPLAIN ANALYZE <DML>`, `SELECT … INTO`, stacked statements, `INSTALL`/`LOAD`/`ATTACH`/`COPY`, assignment-form `PRAGMA`, and side-effecting functions (`load_extension`, `OPENQUERY`, `nextval`, `pg_terminate_backend`, …) are all rejected and routed to a human approval card. PostgreSQL/MySQL sessions get a server-side read-only transaction as a backstop.
- **Mutations need *your* approval, never the model's.** A data-changing `query_sql`/`csv_query` now surfaces an inline approval card previewing the exact SQL and only runs when you click Approve. The old "the model passed `confirm: true`" self-approval is gone — a model can no longer authorize its own writes.
- **Queries can actually be cancelled, and can't exhaust memory.** Database queries run off the GUI thread with a timeout and a working Stop button that genuinely interrupts a running DuckDB query (`duckdb_interrupt`), so a runaway query no longer freezes the app or piles up detached worker threads. Results are row-capped *before* materialization, so a cross-join can't OOM the app before it truncates.

### Fixed — AI coding assistant safety
- **Write tools exist only where writes are expected.** The Ask (read-only) segment and Data mode no longer receive `write_file`/`apply_diff` at all, and the host refuses a mutating tool call on any read-only surface even if the model tries to force one. Compose's dry-run is now enforced by the host, not merely requested in the prompt.
- **Atomic file writes.** Applying an edit now writes through a temp file and an atomic rename (`QSaveFile`) — a failure at any point leaves your original file byte-for-byte intact, closing a window where a failed rename could destroy both the old and new content. Byte-exact rollback is preserved (verified against a non-UTF-8 payload).
- **"Approve all this turn" is scoped.** Approving all pending *file writes* no longer silently authorizes a later *database mutation* (and vice-versa) — each kind is gated independently. Pending approvals are also discarded when you switch to the read-only Ask segment.
- **Truncated responses are a distinct, recoverable state.** A response cut off by a context limit, content filter, network drop, or backend stop now shows an inline "Response cut off — Retry" affordance with the cause, instead of masquerading as a complete answer. Truncated replies are also now recorded in the AI Interaction Log (previously dropped).
- **Keyboard pass + polish.** Esc hides the panel, a shortcut focuses the input, Edit-Plan rows toggle with Space / confirm with Enter, approval cards take Enter=Approve / Esc=Deny; the inner "Chat" segment is renamed **Ask** and the selected segment persists across restarts; an empty-state card offers example prompts.

### Testing & verification
- The previously-phantom read-only-gate test (git-excluded, never compiled, calling a function that didn't exist) is now a **real, tracked, CI-run test** — 143 assertions covering the full attack battery. New `test_ai_write_gate` (44 assertions: gate, atomic write incl. rename-failure, byte-exact rollback, truncation) and `test_db_query_runner` (async timeout/cancel with a real `duckdb_interrupt`, engine read-only, row-cap).
- **Full offscreen ctest 70/70** (up from 67), 100% throughout. Every security fix is **red-state proven**: revert the fix and the test fails *fast* (never hangs), restore and it's green.
- A 5-agent adversarial fleet attacked every fix; it found — and a follow-up wave then closed — a regression that a classifier fix *itself* introduced (a `WITH … <outer DML>` shape briefly slipped the gate), re-verified 23/23 closed with no new regression.

### Known trade-offs (deferred, non-blocking)
- Raw model-authored Vega chart specs still lack a Content-Security-Policy on `data.url`; CSV Latin-1 fallback and a newline-less-giant-file guard are unimplemented; database passwords remain XOR-obfuscated rather than keychain-stored. All are defense-in-depth / robustness items — none allow an unapproved mutation or data leak on normal use.

Same bare binary, no new dependencies. Full build (DuckDB bundled) and Lite build both green.
