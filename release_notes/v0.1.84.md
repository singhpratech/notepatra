# Notepatra v0.1.84 — palette deep refresh + ~50-language keyword research

**Biggest syntax-highlighting overhaul since v0.1.31.** Every supported language got its reserved-word coverage refreshed from primary vendor sources, two brand-new lexers (Plain Text + CSV) replace the previous monochrome fallback, and Markdown / YAML / CSS palettes got long-overdue contrast and tint work in all three themes (Light / Dark / Monokai).

## What changed

Users reported `.md`, `.yaml`, and `.txt` files "looked sad" and one SQL keyword "wasn't following the others." The root causes were three different bugs hiding behind a single symptom — **reserved words painting as plain identifier text**:

1. **Bare `.sql` tabs used Scintilla's hardcoded default keyword Set 0** — no MERGE, RETURNING, LATERAL, JSONB, OVER PARTITION BY, WITHIN GROUP, OPENROWSET, ASOF JOIN. The SQL Format Panel had been populating these via `SCI_SETKEYWORDS` since v0.1.21; the main editor tab had not.
2. **~50 languages had stale keyword lists** because `src/lexer_extras.cpp` overrides were hand-curated years ago and didn't track language evolution. Concrete bugs found via primary-source audit: R missing `repeat`, Groovy typo `yields`→`yield`, Crystal missing `next`/`until`, Dart missing `Record`/`augment`, GDScript missing `@rpc`/`@tool`/`@warning_ignore`, Solidity missing `blockhash`/`blobhash` (EIP-4844), Mojo missing `ref`, Julia missing `outer`/`public`/`Float16`, F# missing `ValueOption`/`ValueTuple`, Protobuf missing WKT siblings, HCL missing template directives.
3. **No lexer at all for `.txt`, and CSV fell back to Plain Text** — URLs, emails, numbers, ALL-CAPS headings, quoted strings, code fences in `.txt` files rendered identically; CSV files had no column-stripe / numeric-cell / header-bold differentiation.

## The fix

### SQL keyword union (new file `src/sql_keywords.h`)

Synthesised from six primary vendor sources:

| Source | URL |
|---|---|
| T-SQL / SQL Server | learn.microsoft.com/en-us/sql/t-sql/language-elements/reserved-keywords-transact-sql |
| PostgreSQL | postgresql.org/docs/current/sql-keywords-appendix.html |
| MySQL | dev.mysql.com/doc/refman/8.0/en/keywords.html |
| **DuckDB** | duckdb.org/docs/sql/keywords_and_identifiers — first release with full DuckDB SQL coverage (SUMMARIZE, DESCRIBE, EXCLUDE, ASOF, POSITIONAL, BERNOULLI, RESERVOIR, INSTALL/LOAD/ATTACH, HUGEINT/UHUGEINT/UTINYINT, read_csv/read_parquet/read_json) |
| SQLite | sqlite.org/lang_keywords.html |
| Oracle | docs.oracle.com/en/database/oracle/oracle-database/19/sqlrf/Oracle-SQL-Reserved-Words.html |

Three union strings — RESERVED, BUILTIN_FUNCTIONS, BUILTIN_TYPES — fed to `SCI_SETKEYWORDS` slots 0 / 1 / 4 in `lexerutils.cpp::populateExtraKeywords()` immediately after every `setLexer(QsciLexerSQL)`. Every dialect-specific reserved word now paints as keyword in every `.sql` tab.

Five parallel research agents pulled keyword + built-in + type lists from primary vendor documentation:

| Family | Languages |
|---|---|
| Mainstream compiled | Rust, Go, C (C23), C++ (C++23), C#, Java 21, Kotlin, Swift, Zig, D |

### NEW Plain Text lexer (`src/lexer_plaintext.{h,cpp}`)

Custom `QsciLexerCustom` subclass that regex-paints inside `.txt` files:

* URLs (https/http/www)
* Email addresses
* Numbers + currency
* ALL-CAPS heading lines (3+ uppercase words on their own line)
* Double-quoted, single-quoted, and backtick-fenced strings

Was 100% monochrome before. Hard-cap `paint()` closure pattern guarantees cumulative `setStyling` bytes never exceed `(end - start)` — avoids Scintilla's `CellBuffer.cpp:635` over-style assertion that first-cut development hit.

### NEW CSV / TSV lexer (`src/lexer_csv.{h,cpp}`)

Custom lexer for `.csv` and `.tsv`:

* Header row painted bold (style 1)
* Data cells alternate between Column A / Column B colours for striped-table visual
* Separators (`,` / `\t`) distinct
* Quoted fields including `""` escapes painted as strings
* Numeric cells distinct from text cells
* `#`-prefixed comment lines styled separately

Same hard-cap pattern as Plain Text — every `setStyling` call routes through a `paint()` closure with a `wantBytes` counter.

### Palette refresh (`src/npp_palette.cpp`)

| Surface | Before v0.1.84 | After v0.1.84 |
|---|---|---|
| Markdown H1–H6 | Single `npKeyword` colour for all six | Contrast gradient — H1 strongest, H6 lightest italic; uses existing per-theme palette vars so Light/Dark/Monokai inherit automatically |
| Markdown inline `code` | `npString` foreground only | Adds a paper-tint chip (`#F4F4F4` Light / `#2A2A2A` Dark / `#3E3D32` Monokai) so it visually reads as a code chip |
| YAML unquoted values | Pure black/sand (style 0 default) | Desaturated value-tint (`#5A5A5A` Light / `#B8B89F` Dark / `#E6DB74` Monokai) — distinct from keys (still JSON-blue) and prose |
| Markdown prose body | Pure black/sand | Slightly softer tint (`#2D2D2D` Light / `#C8C8B8` Dark) — body text reads as soft, structural tokens pop |
| CSS pseudo-classes / pseudo-elements | Fell through to identifier-default | New matcher branch routes to `npClassName` — `:hover` / `:focus-within` / `:has` / `::before` / `::after` etc. now distinct |

All five changes honour the **palette dark-parity** rule — every colour literal supplies all three ternary arms (Light / Dark / Monokai).

### Test infrastructure hardening

Three test executables (`test_network_policy`, `test_chart_types`, `test_fontpack`) had been registered with bare `add_test()` instead of the `notepatra_add_qt_test()` helper for releases, so they never appended to the `notepatra_test_targets` global property → never built as part of the `notepatra_all_tests` meta-target → never ran in CI or local `--target notepatra` builds. Fixed by switching to the helper.

Four dependent test executables (`test_options_actually_work`, `test_lexers_v0125`, `test_lexer_smoke`, `test_compare_widget`) needed `src/lexer_plaintext.cpp` + `src/lexer_csv.cpp` added to their source lists to resolve the new constructors at link time.

Updated `test_lexers_v0125.cpp` Plain Text assertion from "returns null" (v0.1.83 behaviour) to "returns LexerPlainText" (v0.1.84 behaviour), plus sibling test for CSV.

**Result: 31/31 ctest pass** (was 28/31 with 3 stale "Not Run" failures).

### Sample corpus (`samples/` — 74 files, ~128 KB)

One rich exemplar per supported lexer, all synthetic (no PII, uses `alice@example.com` / RFC-5737 doc IPs / Alice/Bob/Carol placeholders). Acts as eyeball-verification corpus for future palette work, and as a regression fixture if we add automated palette tests.

## DuckDB note

Per the **SQL dialect priority** memory, DuckDB is now a first-class SQL dialect in the keyword union — DuckDB-specific reserved words (SUMMARIZE, EXCLUDE, ASOF, POSITIONAL, etc.), extended integer types (HUGEINT family), and table-function macros (read_csv, read_parquet, read_json) all paint as keywords in `.sql` files even when the user is writing DuckDB queries rather than T-SQL / PostgreSQL.

## Out of scope (future work)

* **HTML / XML colour density** — markup-family palettes already use distinct hues for tag / attribute / value / comment / entity / CDATA. Per user directive "markup should be most colorful," there's room to push further (e.g. distinct colours per attribute type, semantic vs structural tag colours), but the v0.1.84 changes prioritised the Markdown / YAML / TXT / SQL deficiencies the user explicitly named.
* **JSONL / NDJSON** — currently route through QsciLexerJSON which works line-by-line. A dedicated stream-aware lexer is a v0.1.85 candidate if it turns out to matter.
* **SVG-specific colouring** — currently routed through QsciLexerXML. SVG-specific elements (rect, circle, path) and attributes (d, viewBox, fill, stroke) might warrant a brand override in a future release.
* **TSV separator switch in lexerutils.cpp** — `LexerCsv` ships with a `setSeparator(QChar)` setter; the dispatch to call it for `.tsv` files is deferred to v0.1.85 to avoid one more cross-file touch in this already-substantial release.
* **Heading detection in `LexerPlainText` for mid-document re-styles** — the regex anchors to slice newlines, which means partial restyle of an isolated chunk in a long `.txt` may miss the line boundary. Acceptable trade-off: full-document restyle (the common case) works correctly.
