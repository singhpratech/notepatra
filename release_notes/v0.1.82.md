# Notepatra v0.1.82

**Security hardening + tab-numbering fix.** Outcome of a deep
post-v0.1.81 security audit (6 attack surfaces — install scripts,
release pipeline, supply chain, binary network, website, repo settings)
plus a long-standing tab-numbering quirk that caused new tabs to
"rename themselves" lower after a sibling close.

No new features. Every user-visible UI behaviour is identical to
v0.1.81 except the tab-name fix and the AI Base URL warn-confirm dialog.
Safe drop-in upgrade.

## Tab-numbering fix — names no longer "go back" when you close a tab

### The bug

Two interacting paths in `src/mainwindow.cpp` made untitled tab names
inconsistent:

1. **`updateTabTitle()`** re-derived the displayed name from the tab's
   *current* index (`QString("new %1").arg(index + 1)`) every time the
   editor's modified state changed. Close "new 1" → existing "new 2"
   shifts to index 0 → next keystroke renames it to "new 1". Effectively
   tabs renamed themselves lower whenever a lower-indexed sibling was
   closed.
2. **`m_newCount`** was a plain `int = 0` in the header, reset on every
   launch. Session restore brought back saved tab names (e.g. "new 5")
   but the counter started fresh at 1, so the next `Ctrl+N` created a
   tab named "new 2" — lower than the visible saved "new 5".

### The fix

- `newFile()` now scans the visible tab labels (stripping the `*` /
  `[recovered]` markers) and picks `max(existing N) + 1`, defaulting to
  1 when no `new N` tabs are visible. Monotonic over what's on screen,
  self-heals after close / restore / rename.
- `updateTabTitle()` for untitled tabs preserves whatever label is
  already on the tab (minus the modification marker), instead of
  re-deriving from the current index. The label assigned by `newFile()`
  or `restoreSession()` is now the source of truth.

### Behaviour matrix

| Scenario | Before v0.1.82 | After |
|---|---|---|
| Create 3 tabs, close "new 1", type in the leftmost remaining tab | renames to "new 1" | stays "new 2" |
| Session restore brings back "new 5", then Ctrl+N | "new 2" (lower than visible) | "new 6" |
| Create 3 tabs, close all, then Ctrl+N | "new 4" (monotonic) | "new 1" (resets — no untitled tabs visible) |
| Mix of "new 1" + "new 5" visible, then Ctrl+N | "new 6" | "new 6" |

Tab content / cursor persistence across app-close is unchanged — that
was already implemented by `saveSession()` (auto-save every 10s + on
close) and continues to work.

## Security hardening sweep

Outcome of a structured audit covering 6 attack surfaces. Full details
in `SECURITY.md`. Every change is back-compatible for users.

### Install path — `docs/install.sh` and `docs/install.ps1`

- **SHA-256 verification is now hard-fail.** Previously the script
  silently skipped verification if it could not fetch `SHA256SUMS`
  (network error, 404 from a stale fallback URL). An attacker who
  could MITM a single fetch could swap the binary and pass through.
  Both scripts now refuse to install when sums are unreachable or the
  artifact is not listed in them.
- **Cosign signature verification is now run automatically** when
  `cosign` is on `PATH`, with the cert-identity pinned to the release
  workflow file + tag (was: a regex matching any workflow in the
  repo). On user machines without cosign the SHA check is the gate.
- **`curl --proto '=https' --tlsv1.2`** on every fetch, `umask 077`
  before `mktemp -d`.

### In-app auto-updater — `src/updater.cpp`

The auto-updater (Help → Check for Updates) was previously SHA-only.
It now also runs `cosign verify-blob` when `cosign` is on `PATH`,
with the same literal cert-identity pin. Hard-fails on mismatch.
Releases pre-v0.1.60 that don't ship the `.sig`/`.pem` assets
gracefully fall back to SHA-only (warn-skip, no install fail).

### GitHub Actions supply chain

- **All 38 of 38 `uses:` lines in workflow YAML are now SHA-pinned.**
  Was 0/38 — every action floated on tag/branch refs, including
  `dtolnay/rust-toolchain@stable` (six uses, on a *branch* ref that
  the action owner could fast-forward at any time). Highest-risk
  three (`actions/attest-build-provenance`, `softprops/action-gh-release`,
  `sigstore/cosign-installer`) were pinned first.
- **New `install-canary.yml` workflow** — daily + on-release diff of
  the served `notepatra.org/install.sh`/`.ps1` against the repo's
  `docs/` copies. Opens an issue on drift (catches GitHub Pages /
  DNS / registrar compromise).

### Repo settings (`gh api`)

- **Dependabot security updates** are now enabled (was disabled).
- **Tag protection ruleset** added for `refs/tags/v*` — no deletion,
  no force-push, signed-tag required.

### AI Base URL — `src/preferences.cpp`

The `Preferences → AI → Base URL` field used to accept any string and
forward your API key there. v0.1.82 validates it on save:

- Reject malformed / non-http(s) URLs (warn dialog, stays in edit mode).
- Reject plain `http://` to public hosts (API key in plaintext over
  the network = leak waiting to happen).
- For non-vendor hosts (anything outside an allowlist of OpenAI,
  OpenRouter, Anthropic, Google AI, Ollama Cloud, Mistral, Groq,
  Cohere, Azure OpenAI), pop a confirm dialog. Cancelling keeps the
  preferences dialog open.

This closes a known phishing pattern: a blog post or chat message
recommending "use this faster mirror" URL → unsuspecting user pastes
it → API key sent to attacker on next chat.

### Credential scrubber — `src/credscrub.cpp`

Seven new patterns redacted before any prompt body leaves the app:

- Cloudflare API tokens (`CFPAT-…`)
- DigitalOcean PATs (`dop_v1_…`)
- npm authentication tokens (`npm_…`)
- Twilio SIDs (`SK…`, `AC…` 32-hex)
- Azure Storage `AccountKey=`
- GCP service-account JSON (`"type":"service_account"`)
- HTTP `X-API-Key:` / `Authorization:` header values

### `SECURITY.md`

Reconciled with live ruleset reality. The previous text claimed
"required reviews on `main`" — the actual ruleset had
`required_approving_review_count: 0` (solo-maintainer pattern). The
cosign verify recipe is also corrected from a regex matching any
workflow in the repo to a literal workflow + tag pin.

### `scripts/release-check.sh`

Three new release-gate checks:

- `cargo clippy --all-targets --all-features -- -D warnings` (matches
  the CI `rust-quality` job — previously this would only fail in CI)
- `cargo fmt --check` (matches the same job)
- `cargo audit --deny warnings` (auto-installs `cargo-audit` if not
  present; flags CVEs in resolved transitive deps)

### Font-pack — `src/fontpack.h` / `.cpp`

Added `expectedSha256` to `NotepatraFontPack::Entry`. When set, the
installer verifies the downloaded TTF and refuses on mismatch.
Groundwork for upstream-org-compromise protection (e.g. JetBrains
repo takeover serving a malicious `JetBrainsMono.ttf`). The SHAs
themselves will be populated incrementally per font in follow-up
commits — the verification path is wired and tested.

### `docs/index.html`

Removed the stale `YOUR_BING_VERIFICATION_TOKEN_HERE` placeholder
meta tag.

## What still needs you (external actions)

Five things can't be done from CI — they need the maintainer at a
keyboard:

1. **Hardware-key 2FA** (FIDO2/WebAuthn, not TOTP) on the
   `singhpratech` GitHub account.
2. **CAA DNS record** on `notepatra.org`: `0 issue "letsencrypt.org"`.
3. **DNSSEC** at the registrar.
4. **Registrar lock** on the domain.
5. **CT-log monitoring** for unauthorized cert issuance (`crt.sh` RSS).

The roadmap for these is tracked in `SECURITY.md`.
