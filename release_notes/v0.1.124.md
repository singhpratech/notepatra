# Notepatra v0.1.124

**Invisible characters are now visible — 527 of them, where Notepad++ draws 113. And two Find/Replace bugs that were quietly destroying text are fixed.**

## The invisible-character problem

A file containing a zero-width space looked exactly like a file without one. Notepatra's entire symbol support was Scintilla's whitespace dots and EOL markers, so every zero-width, bidirectional, exotic-space and control character was literally undrawable. That is the class of bug where a build fails, you read the source, and the source looks perfect.

**View → Show Symbol** is rebuilt to Notepad++'s structure, with its eight items in its order:

| Menu item | What it reveals |
|---|---|
| Show Space and Tab | spaces as `·`, tabs as `⟶` |
| Show End of Line | `LF` / `CR` markers |
| Show Non-Printing Characters | Notepad++'s 49-entry table — `ZWSP`, `NBSP`, `RLO`, `ZWNBSP` … |
| Show Control Characters & Unicode EOL | its 64-entry table — C0, C1, `NEL`, `LS`, `PS` |
| **Show Every Other Invisible Character** | the 414 codepoints Notepad++ does not list |
| Show All Characters | all five at once |
| Show Indent Guide · Show Wrap Symbol | unchanged behaviour, now persisted |

The first two tables are transcribed from Notepad++'s source byte-for-byte, abbreviations included — `ZWNBSP` for U+FEFF rather than the colloquial "BOM", `OSPM` for U+1680, `SGCI` for U+0099. Someone comparing the two editors reads the same four letters.

### Going past Notepad++

Its tables are a fixed 113 codepoints, so anything outside them is invisible in Notepad++ too. That gap is not academic:

- **Variation selectors** — U+FE0F and the 240 in plane 14. Routine in emoji, and a common source of "these two lines look identical but the diff disagrees".
- **The TAG block**, U+E0020–E007F — a complete invisible ASCII alphabet. Text encoded here is unreadable in any editor that does not draw it, which is exactly why it is worth drawing.
- **Hangul fillers** (U+3164, U+115F, U+1160) — look like a plain space, are not one.
- The combining grapheme joiner, the Braille blank, and the rest of Unicode's format category.

The parity tables are untouched; the extra coverage is a separate toggle, and range expansion skips anything Notepad++ already claims, so U+FEFF keeps its `ZWNBSP` spelling while U+FE0F becomes ours.

You can also switch the blobs from abbreviations to codepoints — `U+200B` instead of `ZWSP` — matching Notepad++'s NPC display mode.

All Show Symbol settings now **persist across restarts** and apply to every tab. Previously none of them were saved.

Defaults match Notepad++: everything off except the control-character display. Non-printing characters are therefore **off out of the box** — turn them on from View → Show Symbol.

## Two bugs that destroyed text

Found by an adversarial audit against Notepad++, both live in every previous build, both with no test coverage at all.

**Replace All deleted any replacement containing `$`.** The replacement string was handed to the regex engine, which reads it as a *substitution template* — so `$100` parsed as capture group 100 and expanded to nothing. `$var`, `${HOME}` and `a$b` lost text the same way, and the status bar reported success. Match case defaults to off, so this was the out-of-the-box path, and Replace All in All Opened Documents repeated it across every tab.

**Replace claimed work it had not done, and overwrote what it was not asked to.** On a freshly opened tab it reported "Replaced 1 occurrence" over an untouched buffer *and* skipped that match permanently, so walking a file with Replace left one survivor and a wrong count. Once armed, it overwrote whatever happened to be selected, whether or not it matched. It now verifies the selection really is a match before touching it, and otherwise degrades to Find Next — Notepad++'s own contract.

## Also fixed

- **Find in Files reported "0 hits" for files it never opened.** The default `*.*` filter went straight to Qt, whose wildcards are literal, so it demanded a dot in the name and silently skipped `Makefile`, `Dockerfile`, `LICENSE` and `.gitignore`. `*.*` now means any file, as it does in Notepad++.
- **Mark All highlighted the wrong spans.** Offsets were computed into a lowercased *copy* of the document, and lowercasing is not length-preserving in UTF-8 — one such character shifted every later highlight, and the error accumulated. It also assumed each match was as long as the search pattern, which is wrong for every regex.
- **Indent guides were a white-on-black barber pole in Dark and Monokai.** Scintilla's reserved indent-guide style was never themed, so it kept its default black-on-white and the guide's own background became the brightest thing on a dark screen. Guides are on by default, so this shipped to every dark-theme user.
- Compare panes and the formatter output panels now draw symbols too. Comparing two files that differ only by an invisible character used to show two identical-looking lines while the diff insisted they differed.

## Verification

Every fix was verified by reverting it and confirming the new tests fail — and that only the expected assertions fail. The symbol tests measure real laid-out pixel width rather than asking Scintilla what it stored, because a representation round-trips perfectly while drawing nothing. The Replace tests click the actual dialog buttons: the whole bug class here was the gap between what the engine could do and what the dialog did, and the engine-level tests passed on code that ate text once the dialog was in the loop.

Rendering cost is not measurable — a 20,000-line document lays out in the same time with all 527 representations installed as with none.

Full suite: 75 C++ test suites on the Full build (72 on Lite, which omits the two DuckDB suites and the WebEngine-gated Noter-export suite), plus 158 Rust tests.
