# Notepatra v0.1.65 — Hotfix for the full-flavor build (QJsonDocument crash)

**Date:** 2026-05-10
**Tag:** `v0.1.65`
**Build:** Linux x64 / Linux ARM64 / macOS Apple Silicon / Windows x64 (lite + Linux full flavors)

A surgical hotfix for a `QJsonDocument` constructor mismatch in the WebEngine code path of `VegaChartRenderer`. Hidden in v0.1.63 (CI Linux + Windows builds silently failed; no v0.1.63 GitHub Release ever published). v0.1.64 inherited it; the new full-flavor build pass would have crashed CI the same way. This release fixes the call and re-cuts the full-flavor build.

---

## What changed

### `src/charts/vega_chart_renderer.cpp` — JS string-literal encoding

Replaced:

```cpp
QString jsArg = QString::fromUtf8(
    QJsonDocument(QJsonValue(QString::fromUtf8(specJson))).toJson(QJsonDocument::Compact));
```

Qt5's `QJsonDocument` has no `QJsonValue` constructor — only `QJsonObject` / `QJsonArray`. The broken line built locally on minimal-Qt dev machines (because the WebEngine code path is `#ifdef`'d out without `libqt5webengine5-dev`) but hit a hard `error: no matching function` on every CI runner that had WebEngine installed (Ubuntu 24.04, Windows install-qt-action).

New encoding:

```cpp
// Wrap in a 1-element array, serialize, slice off the surrounding [ ]
// — yields a valid JS string literal regardless of what control chars /
// quotes / backslashes the spec contains.
QJsonArray wrap;
wrap.append(QString::fromUtf8(specJson));
const QByteArray wrapped = QJsonDocument(wrap).toJson(QJsonDocument::Compact);
const QString jsArg = QString::fromUtf8(wrapped.mid(1, wrapped.size() - 2));
```

Plus `#include <QJsonArray>` at the top.

### Why this matters

- v0.1.63 silently never published a GitHub Release (Linux + Windows CI failed; macOS happened to compile under brew qt@5 because of a different Qt patchset).
- The v0.1.64 lite binary works fine because the broken line lives in the `#ifdef NOTEPATRA_WITH_WEBENGINE` branch which lite never compiles.
- The new v0.1.64 `-full` flavor build pass would have failed identically — meaning the [Install charts pack] prompt would have linked users to a Releases page where no full asset existed.

## What this release ships

- All v0.1.64 features (lite default, Charts Pack required card, plugin_loader scaffolding, install-handler)
- Plus the `QJsonDocument` fix so the full-flavor build actually compiles in CI
- Plus the v0.1.65 GitHub Release with both lite + Linux-full artifacts

Everything else is identical to v0.1.64.
