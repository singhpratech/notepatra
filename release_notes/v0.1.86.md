# Notepatra v0.1.86

**Factual-audit gate, BGR-bug sweep, download-size truth-up.** A correctness patch — no new features, no UI changes. Three classes of inaccuracy that had silently rotted across releases are now either fixed or impossible to recur.

## What changed

Three problems caught in the post-v0.1.85 audit, fixed in this release:

1. **Scintilla BGR byte-order sweep.** v0.1.85 introduced a memory rule about Win32 `COLORREF` byte-order in `SendScintilla` calls. Two more sites were found that pass raw `0x00RRGGBB` hex where Scintilla expects `0x00BBGGRR`. Symptoms: Find→Mark All rendered hits in red instead of the intended blue, and merge-conflict annotations rendered in olive-brown instead of the intended dark blue.
2. **Download-size claims drifted across the website.** The marketing copy on `docs/index.html`, `docs/docs.html`, and the README narrative was inflated by ~1.5 MB across every platform — 3.6 MB instead of the actual 3.45 MB, 28.7 MB instead of 26.86 MB, 42.5 MB instead of 40.56 MB, and so on. The README install-table at lines 262-267 was the only place that had been reconciled to actual artifact bytes. v0.1.86 brings every claim into ±0.05 MB agreement with `gh release view` output.
3. **The word "stripped" appeared in live marketing copy, but the Linux x64 binary isn't actually stripped.** Every release-note row going back to v0.1.55 has claimed "X MB stripped" but CI has no `strip` step — the shipped artifact carries 2.65 MB of DWARF debug info. Live marketing now drops the misleading word. The CI strip step is queued for a future release; when added, the binary drops from 9.71 MB → 7.06 MB and the word comes back.

## The audit miss — and the new gate

`feedback_release_factual_audit.md` had been in memory since v0.1.80. It explicitly said "run a full fact-check pass over docs/index.html + docs/docs.html + README every release; `stale-text-check.sh` does NOT catch download sizes". The v0.1.85 release nevertheless shipped with 6 wrong sizes and the wrong "stripped" claim.

Root cause: the audit was a memory entry, not a script. The operator (me) skipped it under release-time cognitive load and ran only the gated `stale-text-check.sh` — which by design only validates the gated canonical counts (file types, lexer count, test count). The factual-audit memory was load-bearing for catching this class of bug, and load-bearing memories that ask the operator to run a mechanical comparison are weak. Same lesson as `feedback_memory_must_be_a_gate_not_a_post_it` (promoted website stale-version sweep from memory to `stale-text-check.sh` in v0.1.83) — this is round two of the same pattern.

The fix is a new gate, `scripts/verify-download-sizes.sh`, wired into `scripts/release-check.sh`:

| Check | How |
|---|---|
| Each release artifact's actual bytes vs. site claim | `gh release view "v$VERSION" --json assets` → for each artifact, find the closest "X.Y MB" claim across the three docs → assert drift ≤ ±0.15 MB |
| The "stripped" claim is honest | If any binary-context "stripped" phrase appears in docs, download the Linux tarball and run `file ... \| grep ", stripped$"` — fail if not actually stripped |

The gate runs in `release-check.sh` between `stale-text-check.sh` and the working-tree-clean check. Memory `feedback_factual_audit_must_be_a_gate.md` documents the post-mortem.

| Source       | Before v0.1.86                     | After v0.1.86                                 | Reference                  |
|--------------|------------------------------------|-----------------------------------------------|----------------------------|
| Linux x64 tar.gz size | "3.6 MB" everywhere              | "3.5 MB" everywhere (actual: 3.45 MB)        | `gh release view v0.1.85`  |
| macOS DMG size        | "28.7 MB" everywhere             | "26.9 MB" everywhere (actual: 26.86 MB)      | `gh release view v0.1.85`  |
| Windows MSI size      | "42.5 MB" everywhere             | "40.6 MB" everywhere (actual: 40.56 MB)      | `gh release view v0.1.85`  |
| Bare binary size      | "~9 MB stripped" (misleading × 2)| "under 10 MB (~9.7 MB on Linux x64)"          | `file notepatra; ls -la`   |
| Mark All highlight    | red (BGR byte-swap of `0x0000FF`)| Tailwind blue-500 `#3B82F6` (BGR-packed)     | `src/findreplace.cpp:770`  |
| Merge annotation text | olive-brown (BGR-swap of `#204050`) | dark blue `#204050` (BGR-packed `0x00504020`) | `src/merge_helper_widget.cpp:185` |

## Out of scope

- **CI strip step.** Adding `strip --strip-all build/notepatra` to `.github/workflows/build.yml` would drop the bare Linux binary from 9.71 MB to 7.06 MB — smaller than the v0.1.59 "7.73 MB stripped" claim. Queued for a future release where the CI change can be verified end-to-end (need to confirm macOS/Windows behavior, then update docs to "~7 MB stripped" and let `verify-download-sizes.sh` validate the new claim against the new artifact bytes).
- **Other factual-audit categories.** The memory lists 7 audit categories; this release only addresses download sizes + the "stripped" word. Architecture claims, install one-liners, and example model names were spot-checked manually and remain accurate.
- **No editor / lexer / UI / AI changes.** All v0.1.84 + v0.1.85 features carry forward unchanged.
