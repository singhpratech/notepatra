# Notepatra v0.1.36 — Multi-word phrase search + Compare ignore-spaces by default

**Released:** 2026-04-26

Two UX improvements driven by user feedback:

1. **Project Search**: multi-word phrases like `import os` (with space) now obvious + safe.
2. **Compare**: "Ignore spaces" defaults to ON.

---

## 1. Project Search — multi-word phrases

User asked: *"what if I have a string like not 'import' but 'import os' — what do you think? How are we planning to implement that?"*

The honest answer: **it already worked.** The literal-mode search path uses `QString::indexOf` for substring matching, which handles spaces natively. The rust-core fast path uses aho-corasick, which also handles multi-character literal patterns including spaces. Searching for `import os` already returned the right matches.

But the placeholder text said *"Search for a string, word, or regex pattern…"* — which sounded like single-token search. So users assumed they had to use regex (`\s` for spaces) or wholeWord mode (which would treat the space as a word boundary). Fix is purely discoverability.

### Changes

**Placeholder text:**
```diff
- "Search for a string, word, or regex pattern…"
+ "Search any text — words, phrases like \"import os\", or regex patterns…"
```

**Query trim** at `startSearch()` so `" import os "` (accidental leading/trailing whitespace) matches the same lines as `"import os"`. Internal whitespace preserved — multi-word phrase support intact.

### Test coverage

Two new cases in `test_projectsearch.cpp`:

**Case 7** — multi-word phrase against a known fixture:

```python
# src/main.py
import os                    # line 1: matches
import sys                   # line 2: doesn't (no "import os" substring)
from os import path          # line 3: doesn't (words present but not contiguous)
import os.path               # line 4: matches (substring)
    import os  # indented    # line 5: matches
x = 'import os'              # line 6: matches (in string)

# src/other.py
import os                    # matches
```

Asserts:
- 5 matches total
- NOT matching `import sys` (different word after import)
- NOT matching `from os import path` (words present but `os` first, `import` second)
- Phrase narrows result set vs single-word `import` baseline

**Case 8** — query trim invariant:

`runQuery("  import os  ".trimmed())` produces identical 5 matches as `runQuery("import os")`. Locks in the trim behaviour so future refactors don't accidentally split queries on whitespace.

`test_projectsearch`: 26 → 31 assertions.

## 2. Compare — "Ignore spaces" defaults to ON

The Compare tab's most common use case is *"did this code change?"* — where re-indentation, alignment changes, or trailing-whitespace fixes shouldn't count as diffs. The "Ignore spaces" checkbox already existed; flipping the default to ON is a one-line change with high user impact.

```cpp
m_ignoreWhitespace->setChecked(true);   // v0.1.36 — was unchecked
```

For users who DO want byte-exact compares (YAML / Python where indentation IS meaning), just untick the checkbox — single click, persists per-tab.

### Test update

`test_compare_widget` Test 1 now first verifies the new default is ON, then toggles OFF (to test byte-exact diff path), then back ON (to test ignore-whitespace path). Same coverage, inverted setup order so the test reflects the new default.

## Try it

1. **Project Search:** open `Ctrl+Shift+G`, type a phrase like `import os` directly — no quotes needed. Multi-word literals just work as substrings. The placeholder text now nudges users toward this pattern.
2. **Compare:** open the Compare tab — the diff defaults to ignoring whitespace. Untick `Ignore spaces` for byte-exact mode (useful for YAML / Python indentation).
