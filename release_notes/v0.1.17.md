# Notepatra v0.1.17 — Safe in-app updater + Project Search rewrite

**Released:** 2026-04-24

v0.1.17 is a quality-and-correctness pass on the two most-used features: **Project Search** (which had a latent bug that prevented it from running at all on certain code paths) and **updates** (which previously dumped you at the GitHub release page — now it's a genuine Notepad++-style one-click download with SHA-256 verification and native-installer handoff).

---

## Highlights

### 🔄 Safe in-app updater — Notepad++-style, never breaks your install

When the **"Update Available"** dialog pops up on launch (or via `Help → Check for Updates`), **Download** now actually downloads. The new `Updater` module:

1. **Picks the right artifact** for your OS + architecture — Linux x64 / ARM64 AppImage, macOS DMG, Windows MSI (with NSIS / portable-zip fallbacks).
2. **Stream-downloads to `~/Downloads/<name>.part`** with a cancellable progress dialog showing MB received / total.
3. **Fetches `SHA256SUMS` and verifies** the hash of what you just downloaded. **Mismatch → file deleted, critical dialog shown, current install untouched.**
4. **POSIX-atomic rename** `.part` → final name (either the final file exists or the part does, never a torn state).
5. **Hands off to the native installer:**
   - **Windows:** `msiexec /i <file>` — MSI `MajorUpgrade` rolls back on failure, UAC-prompted.
   - **macOS:** `open <dmg>` — Finder drag to `/Applications`.
   - **Linux:** opens the Downloads folder so you drop the new AppImage in yourself.

**Safety contract:** the running Notepatra binary is **never** rewritten by the updater. Only the OS installer you explicitly click through may do that, and those installers all have their own transactional guarantees. Any failure anywhere — network drop, cancel, checksum mismatch, disk full, installer cancelled — leaves your current install 100 % intact.

18 assertions in `test_updater.cpp` cover the two pure, safety-critical functions (asset picker + SHA256SUMS parser), including "never picks a .sig / SHA256SUMS / attestation file", "rejects malformed hashes", and "no false-positive substring matches".

### 🔎 Project Search — fixed, honest, streaming, page-scrollable

The single biggest bug of the session: `QMetaObject::invokeMethod(m_worker, "search", Q_ARG(ProjectSearchWorker::Params, p))` was **silently failing** because the type-name string `"ProjectSearchWorker::Params"` didn't match the slot's registered unqualified `"Params"`. Qt logged the mismatch to stderr; the search simply **never ran**. Switched to the lambda overload of `invokeMethod` which bypasses string-based meta lookup.

Everything else in Project Search is now a rewrite of the UX:

- **Honest 0 → 100 % progress bar** — no bouncing indeterminate animation, no fake "walk takes 25 %" share. Fills linearly from `scanned / total`.
- **Live-ticking elapsed time** — a 10 Hz UI timer refreshes the status line between worker events so `elapsed ms` scrolls up visibly even when the worker is between per-file ticks.
- **Full counter line during scan:**
  ```
  Searching — 48 / 212 files (22%) · 28,340 lines · 3 matches · 180 ms elapsed
  ```
- **Total-files-scanned + lines-scanned + elapsed in final status:**
  ```
  ✓ 42 matches across 12 file(s) · scanned 212 files, 28,340 lines in 180 ms.
  ```
- **Instant-responsive Cancel** — click = immediate "Cancelling… (stopping worker threads)" feedback, live ticker freezes, worker bails at its next `m_cancel.load()` checkpoint. Post-cancel worker signals are ignored via an `m_phase == Idle` guard so a tail event can't resume the UI.
- **Per-file batched match emit** — matches arrive in one queued event per file instead of one per match. Query that hits 10 k times no longer spends 10 ms of UI-thread time on event dispatch.
- **Smart folder default** — when you open Project Search with no file open, it falls back to the file-explorer's workspace root, not `$HOME` (walking `$HOME` is the single biggest "why is this so slow" footgun).
- **Match tree shows full absolute path** on the parent row — copyable directly. Right-click any match: **Copy location (path:line:col)**, **Copy full path**, **Copy match line text**.
- **Page-level scroll** — the whole Project Search tab lives inside a `QScrollArea`. The match tree has no internal scrollbar; it grows to fit every visible row, and the **page scrollbar** takes over when content overflows the viewport. One scroll, not two — matches the VS Code / Sublime pattern.
- **Finer walk progress** — `walkProgress` emits on every file for the first 20, then every 50, plus once per subdirectory so even small trees and slow filesystems show a live count during the walk phase.

27-case deep test (`test_projectsearch.cpp`) covers coordinate correctness (including UTF-8 character columns, not bytes), heavy-dir pruning, binary-file skipping, whole-word regex, cancel mid-search, and batched-emit invariants. New 5-case headless UI test (`test_projectsearch_ui.cpp`) proves the status label cycles through the walk → scan → finish states and that the progress bar reaches 100 on a real 2 000-file / 800 k-line fixture.

### 🧩 Help menu — direct GitHub links

Three new entries under `Help`: **Notepatra on GitHub**, **Latest Release...**, **Report an Issue...** — each opens the right GitHub page in your browser. Saves a Google trip when you want to check a recent release, open a bug, or link someone to the source.

### 🐛 Ctrl+Shift+F — Find in Files wired correctly

The menu label said "Find in Files…" but the action was calling `showFind()` (the plain Find tab) instead of `showFindInFiles()`. One-char copy-paste bug in the Search menu. Pressed for over a month. Fixed.

### 🎨 Website — vertical-timeline release cards

Every release before the latest one is now collapsed into a one-line summary row on the website's Version History section (`notepatra.org/#versions`). Click any row to expand its full notes inline. A vertical rail with a colored dot per release runs down the left edge; the latest release is the accent-green dot, older ones outlined. Keyboard accessible (Enter / Space).

### 🧹 CI housekeeping

- The daily `Download stats snapshot` workflow that had been red for weeks (`E2BIG` — `$RELEASES_JSON` was crossing `ARG_MAX` when passed via argv to `python3`) was removed entirely. The website's download counter reads from the GitHub API at page-load time — nothing was consuming `docs/stats.json` anyway.
- `test_updater` + `test_projectsearch` + `test_projectsearch_ui` all registered with CTest. Full `ctest -j`: 11/11 pass.

## Installation

### Linux (AppImage)

```bash
wget https://github.com/singhpratech/notepatra/releases/download/v0.1.17/Notepatra-0.1.17-linux-x86_64.AppImage
chmod +x Notepatra-0.1.17-linux-x86_64.AppImage
./Notepatra-0.1.17-linux-x86_64.AppImage
```

### macOS

```bash
curl -fsSL https://github.com/singhpratech/notepatra/releases/download/v0.1.17/Notepatra-0.1.17.dmg -o ~/Downloads/Notepatra-0.1.17.dmg
open ~/Downloads/Notepatra-0.1.17.dmg
```

### Windows

Same binary, three packagings:

- **MSI** (Windows Installer) — `Notepatra-0.1.17.msi`
- **NSIS installer** — `Notepatra-Setup-0.1.17.exe`
- **Portable ZIP** — `Notepatra-0.1.17-windows-x64.zip`

All artifacts attached to this release page and cryptographically signed.

### One-command installer scripts (Linux / macOS / Windows)

```bash
# Linux, macOS
curl -fsSL https://notepatra.org/install.sh | sh

# Windows PowerShell
irm https://notepatra.org/install.ps1 | iex
```

## Upgrade notes

- If you're already on v0.1.16 running Project Search, the fix is critical — the worker was never being invoked due to the string-lookup mismatch. v0.1.17 is the first version where Project Search actually works end-to-end from the UI.
- The new updater UI replaces the previous "Download" button that just opened the release page. Existing bookmarks and release-page flows still work; nothing was removed.
- Project Search's results view is now a single-page scroll — if you had muscle memory for scrolling inside the tree widget, that scrollbar is gone; use the page scroll instead.
