# Notepatra v0.1.27 — Comprehensive lexer + palette overhaul (all 44+ languages)

**Released:** 2026-04-26

The user complaint that triggered this release was simple: "PowerShell isn't highlighting properly." The fix turned out to need a deeper change that benefits every other language too.

---

## What was actually wrong

v0.1.26 shipped a `LexerPowerShell` class that wrapped Scintilla's native `SCLEX_POWERSHELL` lexer. The lexer was tokenising correctly — `$variable`, `Get-Process`, here-strings, etc. all had distinct style numbers. But the **palette function** (`applyNotepadPlusPalette` in `src/npp_palette.cpp`) only knew about generic style-name substrings like "keyword", "comment", "string". PowerShell-specific style kinds — Variable, Cmdlet, Alias, Here-string, Comment doc keyword — fell through every conditional and ended up as plain text colour.

Result: a `.ps1` file looked monochrome with the occasional comment in green. Same bug would have affected Bash variables (`$var`), any future custom lexer with non-generic style names.

## The fix

Two-pronged.

### Generic palette extension

Added five new style-kind matchers to `applyNotepadPlusPalette()`:

```cpp
if (d.contains("variable"))       fg = npVariable;     // $vars
else if (d.contains("cmdlet"))    fg = npCmdlet;       // Verb-Noun
else if (d == "alias" || ...)     fg = npAlias;        // ls, gci, iex
else if (d.contains("here-string")) fg = npHereString; // @"..."@
else if (d.contains("comment doc keyword")) fg = ...;  // @param, .SYNOPSIS
else if (d.contains("identifier")) fg = soft-accent;   // VS Code-style
```

These run **before** the generic "keyword" / "function" matchers, so PowerShell's `Variable` style hits the variable colour rather than falling through to the generic match.

The `identifier` matcher is a bonus — modern IDEs (VS Code, IntelliJ, Xcode) all use a soft accent for plain identifiers rather than monochrome. Adding it benefits every language.

While I was in there, every keyword set in `src/lexer_*.cpp` for the 6 languages added in v0.1.26 got re-verified against official documentation and substantially expanded.

Every keyword list is sourced from official language documentation, not inferred or guessed. This matters now that traffic is coming — every claim in the changelog and every keyword in the code is verifiable.

## Net result for users

Open any of these files post-upgrade and they look right:

- `.ps1` — `$env:PATH` is identifier-blue, `Get-Process` is amber, `ls` and `gci` are purple aliases, comparison `-eq -ne` are styled distinctly from regular operators
- `.rs` — `fn`, `let`, `mut`, `impl`, `pub`, `crate` highlight in rust-amber; `Vec`, `Option`, `Result`, `Box` in teal
- `.go` — `func`, `package`, `defer`, `chan`, `interface` highlight in Go cyan; `make`, `len`, `cap`, `nil`, `iota` in light cyan
- `.swift` — `func`, `var`, `let`, `protocol`, `actor`, `async` highlight in Xcode pink; `String`, `Optional`, `Array` in lavender; `@State`, `@Binding` in Swift orange
- `.kt` — `fun`, `val`, `data class`, `sealed`, `suspend` highlight in Darcula orange; `String`, `List`, `Flow`, `Job` in gold
- `.ts` / `.tsx` — `interface`, `type`, `as`, `is`, `keyof`, `readonly`, `satisfies` highlight as keywords; `Promise`, `Array`, `Record`, `Partial`, `Awaited` in teal

And the 38+ existing QScintilla-built-in lexers (Python / JavaScript / C++ / Java / HTML / CSS / SQL / Bash / Ruby / Perl / Lua / Markdown / YAML / etc.) all benefit from:
- Identifier soft-accent (no more black-on-black blending)
- Variable-style recognition (`$var` in Bash now highlighted distinctly)
- Per-language tuned keyword + type accents
