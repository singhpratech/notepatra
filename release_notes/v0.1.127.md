# Notepatra v0.1.127

**Five doors refused a private key. The sixth handed it over in chunks.**

`select_range` accepted any range inside a credential file and `get_selection` returned it as text — so a key that `open_file`, `read_tab`, `find_in_tab`, `search_project` and `resources/read` all correctly refused was readable a selection at a time.

That is the third consecutive release with the same defect shape, and the interesting part of this one is not the sixth door. It is why there kept being another.

## Why enumerating callers was never going to work

- **v0.1.125** — the credential deny-list existed in two hand-maintained copies that had drifted apart. Fixed by unifying the *list*.
- **v0.1.126** — the unified list ran in only one of four read paths. Fixed by adding the check to the other three.
- **v0.1.127** — a fifth and sixth path nobody had enumerated.

Each fix was correct. None of them converged, because the thing going stale was never the list — it was the **enumeration**. Every new verb had to remember to ask, and the whole point of a security guard is that it does not depend on remembering.

So the check moved to where buffer text is *fetched* rather than where it is returned. There is now exactly one accessor:

```cpp
bool McpBridge::tabTextFor(int idx, QString *out, QString *refusal) const;
```

Every verb that needs buffer contents calls it. None calls `m_host.tabText` directly. And a test lints `mcp_bridge.cpp` for that invariant and fails the build on a raw call site — so a verb added next year cannot reintroduce the class without turning a test red.

A source-reading test is unusual, and it is here for a specific reason: the per-verb tests can only prove the verbs that exist today, and this defect has now twice arrived through a verb that was not on anyone's list.

## The two quieter leaks in the same family

**`select_range` refuses to stage the read at all**, not merely to return it. Leaving it open would still let a client move your cursor and highlight a private key inside your own editor window — and any future verb that reports selection state would inherit a leak that was already set up for it.

**`apply_edit` was a match oracle.** It reads the buffer to pre-check for a match, so "no match" versus an approval card naming the match tells a caller what a file contains, one probe at a time, without ever returning a byte of text. It goes through the same accessor now.

## The marker was lying about the cap

`read_tab` gained `max_bytes` in v0.1.126. Ask for 100 bytes and the returned text still ended:

```
[truncated at 5 MB]
```

The 5 MB ceiling had not been reached — `max_bytes` had. The string was a constant from before the argument existed.

Worse, the v0.1.126 notes claimed `read_tab` "always reports `truncated` and `total_chars`". That is true of the editor↔sidecar wire and **not** of the MCP tool result, which is plain text with no side channel — so those counts never reached a caller at all. The marker is the only place they can live, and it now reads:

```
[truncated: showing 100 of 2688894 characters — re-read with a larger max_bytes, or from an offset]
```

The v0.1.126 changelog entry is left as it shipped rather than quietly rewritten; the correction is recorded in this one.

## A schema that lied

`select_range`'s `inputSchema` advertised `tab_id`. Its argument allow-list did not include it, so a client generating calls from the published schema got `-32602 unexpected argument "tab_id"`.

The v0.1.126 sweep that added `tab_id` everywhere matched only the single-line `reject_extras` form, and `select_range` is the one written across multiple lines. One verb out of thirteen.

Rather than fix that one and move on, there is now a test that walks the **entire** tool list, finds every tool advertising `tab_id`, calls each one with it, and fails if any rejects the argument it publishes. A schema that lies is worse than a missing feature: it makes correct clients fail.

Also: `list_open_tabs` published the field as `id` while every verb takes `tab_id`. Both names are emitted for one release so v0.1.126 clients keep working.

## Verification

98 C++ suites, 66 sidecar protocol tests, both Cargo feature sets.

Every fix red-state verified by restoring the pre-fix code. The two NP-14 tests were confirmed to fail **independently** — the lint flags a raw call site even when nobody has thought to test the verb it appears in, which is the property that makes it worth having.

Still uncovered, carried forward: the approval card's explicit **Deny** button by real click (deny-by-timeout is proven), and the remote gateway, which stays behind a non-default Cargo feature.
