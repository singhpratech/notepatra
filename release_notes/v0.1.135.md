# Notepatra v0.1.135

**Unsaved diagrams survive quit, and clearer errors from the MCP diagram and chart tools.**

A fix release. The diagram and session fixes apply on every platform; the chart message fix matters most on macOS.

## Fixed: unsaved Diagram tabs are kept

- **Unsaved Diagram tabs are saved in the session and come back on the next start.** Before, the session saved editor tabs only, so a modified Diagram tab was silently dropped on quit, by the autosave tick and by a normal close, on every platform, while unsaved editor tabs came back. A modified diagram now restores with its source, title and modified state. An unmodified diagram that came from a `.npd` file is read again from disk; if that file is gone, or can no longer be read, the startup notice says so. An older Notepatra opening the same session restores the diagram as an editor tab holding the same text.
- **Closing a modified Diagram tab asks Save / Discard / Cancel**, like an editor tab. This covers the tab's close button, Close All, unchecking **Tools > Diagram**, and closing a window that keeps no session (`--new`). Before, those closed the tab and lost the edits without asking. A `close_tab` you approve through MCP closes without a second prompt.
- **The session is saved when Notepatra is ended by a signal.** On Linux and macOS, SIGTERM and SIGINT (`kill`, Ctrl+C in the terminal that started it) quit the app without closing the window, so the session was not saved and anything edited after the last autosave tick (every 5 s by default) was lost, editor tabs included. The session is now also saved when the app quits.
- **A close prompt interrupted by a quit keeps the tab.** If the app was told to quit while a Save / Discard / Cancel prompt was open, the prompt closed with no answer, the tab was treated as discarded and left out of the session. Only an explicit Discard discards now; anything else keeps the tab. This applies to editor and Diagram tabs.
- **A failed diagram save says so and keeps the old file.** Saving a diagram ignored write errors and reported success, so a full disk could leave a truncated `.npd`, clear the modified mark, and let the close prompt's Save close the tab. Diagrams are now written to a temporary file that replaces the old one only when every byte is written; on failure the old file is untouched, the tab stays modified, and a message gives the reason.

## Fixed: MCP

- **The Welcome tab keeps its `tab_id` across theme changes.** `set_theme` rebuilt the Welcome page and gave it a new id, so an id read before the change no longer found the tab.
- **The chart tools say why charts are unavailable.** `render_chart` and `export_chart` answered "charts require the Full edition (WebEngine)" on macOS Full, which `app_info` reports as edition Full. Charts need WebEngine, which no macOS build has. The error now gives the reason for the build you run: Lite on Linux or Windows is told charts need the Full edition; every macOS build is told chart rendering is not available in the macOS build and that `run_sql` and `run_query` still return the data. `get_capabilities` now reports `features.charts` and, when it is false, `charts_unavailable_reason`. The in-app chart card and the AI tool-call summary on macOS no longer tell you to get the Full build.

## Fixed: diagram validation and Mermaid import

- **`.npd` validation reports unclosed brackets and unterminated quotes, with line and column.** `validate_npd` answered `valid: true` for `(a) -> [b`, because the open `[b` was read as a node name. A node shape, node id or edge endpoint left open, and a quoted value with no closing quote, now give an error such as `line 2, column 8: unclosed '[': add the matching ']'`. `validate_npd`, `create_diagram` and `set_diagram_source` return a `column` field (0 when no column applies). These checks only add errors: what is drawn is unchanged.
- **At most 100 errors are listed**, followed by one "…and N more errors (only the first 100 are listed)" entry, so the result stays invalid. Validation of a long single line with many open brackets is also no longer slow: 1 MB took over 20 seconds per keystroke in the Diagram tab and per `validate_npd` call.
- **Mermaid import refuses diagram types it cannot import, with a clear message.** A `sequenceDiagram` (or class, state, ER, Gantt, pie and other non-flowchart types) came back as success with an empty diagram, and **Import Mermaid** in the Diagram tab replaced your diagram with it. The import now returns an error naming the Mermaid type and saying that only flowcharts (text starting with `flowchart` or `graph`) are supported. `mermaid_to_npd` returns it as an error; the in-app dialog shows it, stays open, and leaves your diagram as it was.
- **`::` in an imported label becomes "∷"** (U+2237). In `.npd`, `::` starts a node's hover text and cannot be escaped, so a Mermaid label like `std::vector` or `IPv6 ::1` produced a diagram that failed validation. Also fixed in the importer: edge labels that start with a quote or `:` are quoted, a node id that is an `.npd` keyword keeps its edge, an edge with an unnamed end no longer leaves an empty group member, and a flowchart with no header whose first line is a word like `Diagram` imports again. Every import in the test table now validates with zero errors.

## Known limits

- macOS builds are still not notarized; the first launch needs the steps in the docs.
- Charts (`render_chart`, `export_chart` and inline charts in the Data analyst) are not available on macOS in either edition. This release changes only the message.
- These changes were tested on Linux. None of them has been run on a real Mac for this release.

## Tests

Four new suites: 118 registered on the Full build, 115 on Lite (which leaves out the two DuckDB suites and the WebEngine-gated Noter export suite).

- `test_diagram_session` (new): a real window and MCP bridge under an isolated home directory. Diagrams made with `create_diagram` survive an autosave tick followed by a quit with no close event, and a normal close; an unmodified `.npd` is read again from disk; a window with no session prompts for a modified Diagram tab; a quit while the close prompt is open keeps the tab; the Welcome tab keeps its `tab_id` across `set_theme`.
- `test_npd_validation` (new): 42 valid and 32 invalid cases, plus the three starter templates, the shipped sample, the docs example and Mermaid-import output.
- `test_mermaid_import_dialog` (new): the Import Mermaid dialog shows the error, stays open, and leaves the diagram untouched.
- `test_mcp_chart_gate` (new): the real bridge built as Full without WebEngine, on every OS, gives the right chart message and capability flags.
- `test_mcp_bridge`, `test_mcp_host_tools`, `test_mermaid_import`: the column field, the error cap, the chart reasons, the Mermaid errors through the real host, and the label and edge fixes.
