# Notepatra v0.1.100 — window opens centred on Windows (title bar always reachable)

**Release date:** 2026-05-25

A Windows window-placement fix: on a cold start (and when opening a file by double-click) the window could open with its **title bar pushed above the top of the screen**, hiding the minimize / maximize / close buttons. v0.1.100 centres the window on open so the title bar is always fully visible.

---

## What was wrong

On Windows, each launch nudged the window up a little until — after a few cold starts — the title bar (and its window controls) climbed off the top edge of the screen, leaving no visible maximize/close button. Linux and macOS were unaffected.

## Root cause

The window position was **saved** with `QWidget::x()` / `y()` — Qt **frame** coordinates that *include* the title bar — but **restored** with `setGeometry()`, which takes **client** coordinates (the area *below* the title bar). So each restore set the client top to the previous frame top, and on Windows the title bar — which sits above the client rect — moved up by its own height every launch. The existing on-screen clamp only checked for a ≥100 px overlap, so a window whose body was on-screen but whose title bar was above the top slipped through unchanged.

## The fix

`src/mainwindow.cpp` — both window-restore sites (initial config restore + session restore) now centre the window on the primary screen using the **saved size**, via a new `centeredWindowRect()` helper, instead of restoring the saved x/y:

- The client top is kept a generous margin below the work-area top, so the frame's title bar can never be clipped — even at large sizes or 150 % display scaling.
- **Maximized state is preserved** (a maximized window still reopens maximized).
- **Window size is preserved** (the window remembers how big you made it).
- Only the on-screen *position* is no longer restored — it always opens centred, which is what keeps the controls reachable.

| Open path | Before v0.1.100 (Windows) | After v0.1.100 |
|---|---|---|
| Cold start | title bar crept above the top edge over successive launches | centred, title bar fully visible |
| Double-click a file | window shifted up, controls hidden | centred, controls visible |
| Was maximized last time | — | reopens maximized (unchanged) |

## AI Interaction Log — confirmed persistent (no change needed)

A user asked whether the **AI Interaction Log** survives version upgrades. It does — and this release documents why. The log is a SQLite file at `%APPDATA%\Notepatra\ai-logs\interactions.db` (Roaming) on Windows. The installers only manage the program files (Program Files for the MSI, `%LOCALAPPDATA%` for the portable build) and the Start-Menu shortcut; **neither the upgrade nor the uninstall touches `%APPDATA%`**, so the log persists across upgrades and even remains after uninstall. (Individual entries still auto-prune after 7 days by design — a privacy feature — and you can **Export JSON** from the viewer at any time.)

## Out of scope
