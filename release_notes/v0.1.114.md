# Notepatra v0.1.114

**Opening files is now bulletproof.** This release closes the long-standing Windows "double-click does nothing" ghost-open class and hardens the whole open pipeline on every platform: 13 deep-dive findings plus 30 follow-ups confirmed by two adversarial re-verify fleets (the second one auditing the fixes themselves), all fixed and pinned by tests. Same bare binary, no new dependencies.

## Opening files always works — and always shows something

- **The ghost open is dead.** Double-clicking a file while Notepatra was starting, busy, or hung could end in *nothing visible happening* — the request was silently swallowed by an unpumped window or a dead pipe. The single-instance forward now uses a greeting-gated protocol: the running instance proves it is alive **before** the payload is sent, every byte is confirmed drained, and if the primary is genuinely stuck you get a **visible temporary window** with your files instead of silence.
- **No more double opens.** The old protocol could leave a forwarded request in the pipe after falling back — a slow-but-alive primary opened the same files *again* later. Structurally impossible now: nothing is sent until the primary greets.
- **Non-ASCII paths open on Windows.** Paths with accents, Cyrillic, CJK and emoji were mangled by the ANSI codepage decode and silently dropped. Arguments now arrive as true UTF-16.
- **Missing files tell you.** A stale recent-files entry, a deleted session file, a typo'd path on the command line — all used to vanish silently. Every one now surfaces a non-modal notice (on the app's real status surface — the phantom second status strip is gone too).
- `--line N` jumps in the **first** file as `--help` promises — including forwarded opens — and never jumps an unrelated tab when that file fails to open. `--line` followed by a filename no longer eats the file.
- Double-clicking a file that is already open focuses its tab without reloading — your unsaved edits in that tab survive.

## Your session can't be silently lost

- **Every window that can't write the session now prompts on close.** Temporary windows (`--new`, hung-primary fallback) and the rare "another instance is restoring" window are session-passive by design — closing one used to silently discard every unsaved buffer. All of them now route modified tabs through Save / Discard / Cancel, and they never delete the main instance's crash evidence.
- **session.json writes are atomic on Windows** — the old remove-then-rename had a window with *no* session file on disk, and a failure deleted the only surviving copy.
- Two instances racing at login can no longer end up **both writing the session** (one clobbering the other's tabs): the race loser re-probes and hands its files to the winner instead of stealing its socket.
- Cold-start restore is deferred until the window has painted, protected by a PID-stamped marker so a hung restore can't brick the next launch — and a session tab whose file vanished is reported, not silently dropped.

## No more freezes

- **File → Close All froze the app — always.** The close loop fought the "always keep one tab" backfill forever at 100% CPU (and Cancel re-prompted infinitely). Pre-existing for many releases; found by the fleet enumerating callers. Fixed with a bounded sweep where Cancel aborts. "Close Others" also closed the wrong tab in some arrangements — fixed.
- **Modal prompts can't stack or fire invisibly.** Pre-show load failures queue into one combined notice; the file-watcher's "File Changed / Deleted" prompts are strictly one-at-a-time across *all* paths — including while a tab-close Save prompt is open (that collision could previously crash the app via a freed editor).
- The status-bar word count is cached and debounced — typing in multi-megabyte files no longer stutters; giant pastes are guarded the same way.
- A crash now leaves an async-signal-safe flag, so the next launch can tell you about it (and your recovery data survives temporary windows).

## Notes

- **No regressions: full ctest 67/67 green** (13 new test binaries cover the open pipeline: single-instance protocol, remote opens, cold-start ordering, CLI args, standalone windows, session autosave guard, watcher prompts, crash flag and more). A 6-scenario real-binary multi-process smoke passes 16/16: cold start, forward+ACK, `--new`, graceful quit, crash-flag cycle, kill -9 recovery.
- The headline regression test was verified **red** against the unfixed code before trusting it.
- Two adversarial fleets ran before this ship: one over the original diagnosis (16 finders, 3 refuters per finding) and one over the fixes themselves (85 agents) — the second caught 3 serious bugs *introduced by* the first wave, all fixed here.
- Known trade-off: if the running instance is busy for more than ~3 seconds (e.g. restoring a huge session), a double-click opens a temporary window rather than queueing — visible, data-safe, and noted in-app.
