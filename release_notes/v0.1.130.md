# Notepatra v0.1.130

**A Preview pane beside the editor: Markdown and HTML rendered live, Jupyter notebooks shown as notebooks, and plain `.sql` files that run cell by cell.**

Open it with `View → Preview Pane`, `Ctrl+Shift+V`, or the new **Preview** button (eye icon, showing ON or OFF) at the end of the built-in tools icon row. The pane sits to the right of the editor tabs, inside the editor area, in a draggable splitter (55/45 by default). It follows the current tab; on a tab it cannot preview it shows a one-line placeholder. Toggle it off and the editor gets the full width back. It is not saved in the session, so it is closed on the next launch.

Everything below ships in every build including the default Lite binary, with no new dependency and no network use. The Chromium HTML renderer and the DuckDB scratch database are Full-only. The release also fixes several layout problems on the website.

## Preview pane: Markdown and HTML

**Markdown (`.md`)** is rendered with Qt's GitHub-dialect Markdown parser: headings, emphasis, lists, task lists, pipe tables, fenced code (monospace, tinted), block quotes and links. It is live: the pane re-renders 250 ms after you stop typing. Relative images (`![](img.png)`) resolve against the file's folder. It is theme-aware: Light, Dark and Monokai each get matching text, code and table colours. `http`, `https` and `mailto` links open in the system browser; `#anchor` links scroll.

**HTML (`.html`, `.htm`, `.xhtml`)** renders two ways:

- **Lite** uses Qt's built-in rich-text engine, a CSS subset: headings, paragraphs, lists, tables, images and basic inline styles.
- **Full** bundles WebEngine and renders the page with the real Chromium engine: full CSS, and relative images and stylesheets beside the file load.

The previewed page is locked down. **JavaScript is disabled, no remote resources load, and the page cannot navigate the pane** (meta-refresh, forms and iframes are blocked). `http`, `https` and `mailto` link clicks open in the system browser. Nothing is fetched from the network by the preview. HTML over about 1.5 MB falls back to the built-in engine even in Full.

## Jupyter notebooks (`.ipynb`)

The file still opens as JSON text in the editor, unchanged. The pane shows a read-only notebook view:

- Markdown cells are rendered.
- Code cells appear in monospace with `In [n]:` counts and the kernel language.
- Outputs: `stdout` and `stderr` streams; `execute_result` and `display_data` as text, HTML tables, or embedded PNG images; and error tracebacks with ANSI colour codes stripped.
- `<script>` tags inside HTML outputs are removed.

Only nbformat 4 is supported. An nbformat 3 file shows a clear "unsupported" message, and malformed JSON shows the parse error. This is a viewer: cells are not executed and the notebook is not edited from the pane.

## SQL cells (`.sql`)

A plain `.sql` file becomes a notebook when it contains `-- %%` separator lines, the VS Code / Jupytext convention. The file stays a normal SQL file for every other tool.

```sql
-- %% [markdown]
-- # Orders check
-- Create a scratch table, then query it.

-- %%
CREATE TABLE orders (id INTEGER, total REAL);
-- %%
SELECT COUNT(*) AS n FROM orders;
```

`-- %% [markdown]` (or `-- %% md`) starts a notes cell whose `--` comment lines are rendered as Markdown. Each SQL cell is a card with a **Run** button, a status line ("3 row(s) in 2 ms", "Done in 4 ms", or the error) and a result table. **Run All** runs the cells top to bottom and stops at the first error; **Stop** cancels. `Ctrl+Return` in the editor runs the cell under the cursor, only while the pane shows a SQL notebook; otherwise the key is untouched.

**Connection chooser:**

- **Scratch (SQLite, temporary)** is a throw-away database in a temp folder. State persists across cells for the session (CREATE in one cell, SELECT in the next), and writes are always allowed.
- **Scratch (DuckDB, temporary)** is the same idea, in Full builds.
- Every saved connection from Settings: PostgreSQL, MySQL/MariaDB, SQL Server via ODBC, SQLite files, and DuckDB files in Full.

**On a saved connection, cells are read-only by default.** A statement that changes data is refused with a message until you tick **Allow writes**. Results are capped at 500 rows, and the status says when a result was truncated. Queries run off the GUI thread. The AI assistant's and the MCP server's SQL paths and their read-only gates are untouched.

## Limits

- **Stop** interrupts DuckDB queries immediately. For SQLite and the Qt SQL drivers it only flags the request, and the cell stays busy until the server returns.
- There is a 120-second ceiling on a query.
- With the Qt SQLite driver, a cell containing several statements runs only the first.
- Results are capped at 500 rows.
- The notebook viewer is nbformat 4 only, and read-only.
- HTML over about 1.5 MB uses the built-in renderer even in Full.
- The pane is not remembered across launches.

Not changed: session save and restore, tab handling, the existing Markdown Converter, the AI tools and the MCP bridge.
