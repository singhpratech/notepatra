# Notepatra v0.1.122

**Save & Open dialogs now remember your last folder — on every platform.**

## What changed

Saving or opening a file in Notepatra always started at your home folder. Save into a project directory, create the next file, hit Save As — and you were back at home, navigating from scratch every time. The complaint surfaced on Windows, but the cause was cross-platform: every Save/Open dialog hardcoded `QDir::homePath()` as its start directory, on Windows, Linux, and macOS alike. Only "Save As" on an already-saved file was smart (it starts in that file's own folder).

## The fix

Notepatra now remembers the last directory a Save/Open dialog used and starts there next time.

1. **Every dialog remembers.** A brand-new untitled buffer's Save As, "Save a Copy As", "Open", and "Open Folder as Workspace" now open in the directory you last used instead of home. The remembered folder is persisted in the app config and survives a quit/relaunch.
2. **No regression to existing behaviour.** "Save As" on a file that already has a path still prefers *that file's own folder* — the remembered directory is only the fallback for untitled buffers and secondary dialogs.
3. **Self-healing.** If the remembered folder was deleted, or lived on a removable drive that's since been unplugged, the dialog quietly falls back to your home folder instead of failing. Empty or nonexistent paths can never poison the next dialog.

| Flow | Before v0.1.122 | After v0.1.122 |
|---|---|---|
| Save As on a new/untitled file | Always home folder | Last-used folder |
| Save a Copy As | Always home folder | Last-used folder |
| Open / Open Folder | Always home folder | Last-used folder |
| Save As on an existing file | The file's own folder | The file's own folder (unchanged) |

## Test coverage

`test_last_dir.cpp` ships a new regression suite (72 suites total) covering the directory-extraction, deleted-folder guard, and home-fallback logic:

```
empty lastDir → home                 file path → parent directory remembered
directory path → itself remembered   deleted-folder guard ignores bad input
self-heal when remembered dir vanishes
```

The fix was **red-state verified** (reverting it makes the test fail) and confirmed against the compiled Linux binary — including driving the real Save As dialog and screenshotting it open in the remembered folder.
