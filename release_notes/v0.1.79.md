# Notepatra v0.1.79

**Double-click-from-file-manager focus handoff fix — Linux X11 and Windows.**

## The bug

Notepatra is single-instance: when you double-click a `.sql` (or any
text file) in Nemo / Files / Windows Explorer with Notepatra already
running, the new process forwards the path to the running instance
over a local IPC socket and exits without ever mapping a window.

Before v0.1.79, this looked broken in two ways:

| Platform                  | Symptom                                                                                                                                                  | What you saw                                                                                       |
|---------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------|----------------------------------------------------------------------------------------------------|
| Linux X11 (Cinnamon, GNOME, KDE) | Tab opens in the background, focus stays on the file manager, busy-cursor spinner ticks until the WM's 15 s timeout.                              | Alt-tab away from Nemo to find the just-opened file. Spinner still spinning when you switch back. |
| Windows                   | Tab opens, taskbar button flashes orange instead of activating.                                                                                          | Click the flashing icon manually to bring Notepatra forward.                                       |

## Root cause

Two different OS-level reasons, same user-visible symptom.

### Linux X11 — Cinnamon/Muffin focus-stealing prevention

Cinnamon's window manager (Muffin, a Mutter fork) implements focus-
stealing prevention (FSP). When a background process sends a plain
`_NET_ACTIVE_WINDOW` ClientMessage asking the WM to raise a window,
Muffin compares timestamps and the requesting client's foreground
state. If the request looks "unsolicited" — and ours did, because
the running Notepatra wasn't focused at the time — Muffin silently
demotes the activate to `_NET_WM_STATE_DEMANDS_ATTENTION` and leaves
the window in the background.

The `org.cinnamon prevent-focus-stealing` gsetting being false
doesn't help; Muffin has its own FSP layer that gsetting doesn't
control.

The infinite spinner is a separate problem: the desktop environment
starts a launch-feedback animation when it sees `DESKTOP_STARTUP_ID`
in our env, and waits for a window with that ID to map. Since we
never map a new window (we just IPC and exit), the spinner ticks
until the WM's 15 s timeout.

### Windows — Explorer foreground-rights handover

`SetForegroundWindow()` is blocked when the requesting process
doesn't currently own the foreground. Explorer hands foreground
rights to the *newly spawned* notepatra process (the second one,
which immediately exits after forwarding the IPC payload), not to
the running instance. By the time the running instance tries to
activate, it has no foreground rights, so Windows demotes the
request to a taskbar flash.

## The fix

### Linux X11 — wmctrl-faithful activate sequence

`src/mainwindow.cpp::handleRemoteOpen` now reproduces wmctrl's
`activate_window` sequence exactly. Three parts, all required:

```
(a) _NET_ACTIVE_WINDOW ClientMessage
       source = 2 (pager / user-blessed)
       timestamp from DESKTOP_STARTUP_ID's _TIME<N> suffix (or 0)

(b) xcb_map_window(window)
    xcb_configure_window(window, STACK_MODE_ABOVE)

(c) Round-trip fence:
       xcb_get_input_focus_reply(...)  ← forces server to process (a)+(b)
                                          before xcb_disconnect
```

Part **(b)** is the critical insight that took the longest to find.
`xcb_map_window` + `xcb_configure_window(STACK_MODE_ABOVE)` is what
`XMapRaised` decomposes into. It goes to the WM as a
`ConfigureRequest`, which is a **different code path** from
activation ClientMessages and is **not gated by FSP**. Adding (a)
alone gets demoted to DEMANDS_ATTENTION. Adding (b) alone doesn't
give input focus. Adding both, in order, with a round-trip fence,
wins consistently against Cinnamon, GNOME, and KDE.

Verified by reading the wmctrl source and `ltrace -l 'libX11*'`-ing
a `wmctrl -i -a 0x...` call against the running Notepatra. The new
code matches the trace step-for-step.

### Linux — kill the spinner

`StartupNotify=false` in the generated `.desktop` file
(`install.sh` + `docs/install.sh`). Notepatra spawn-and-IPC is fast
(<150 ms in practice), so the loss of launch feedback is invisible.

A spec-compliant `remove: ID="<id>"` startup-notify ClientMessage
sequence is also wired into `src/main.cpp::sendStartupNotifyComplete`
(quoted format per the freedesktop startup-notification spec, with
a round-trip fence before disconnect) as a belt-and-braces measure
for other DEs that respect the protocol. Cinnamon's launch tracker
ignores REMOVE messages in practice, so the `StartupNotify=false`
in the .desktop is what actually stops the spinner there.

### Windows — surrender foreground rights, then activate

`src/main.cpp` (second-instance code path) calls
`AllowSetForegroundWindow(ASFW_ANY)` right before exiting. This
explicitly hands foreground-activation rights from this process to
any other process, so the running Notepatra can `SetForegroundWindow`
without Windows blocking it.

`src/mainwindow.cpp::handleRemoteOpen` then does the documented
TOPMOST flip belt-and-braces (`HWND_TOPMOST` → `HWND_NOTOPMOST` with
`SWP_NOACTIVATE`) for z-order, followed by `SetForegroundWindow`.

## Files touched

```
src/main.cpp                 sendStartupNotifyComplete (Linux) +
                             DESKTOP_STARTUP_ID capture before
                             QApplication ctor strips it +
                             AllowSetForegroundWindow on Windows
src/mainwindow.cpp           handleRemoteOpen — X11 activate sequence,
                             _NET_STARTUP_ID property handoff,
                             Windows TOPMOST flip
src/mainwindow.h             handleRemoteOpen now takes startupId
                             QByteArray (default empty)
install.sh, docs/install.sh  StartupNotify=false in generated .desktop
CMakeLists.txt               link libxcb explicitly on Linux (was
                             transitive through Qt5 GUI)
```

## Out of scope

- **Wayland focus handoff.** The X11 atom-based sequence is X11-only.
  Wayland-native compositors expose `xdg-activation-v1` which is a
  separate protocol; wiring Notepatra to it is a future change.
- **GNOME (Mutter) without Cinnamon.** Same FSP design, same fix
  works — tested only Cinnamon/Muffin in practice but the wmctrl
  sequence is the reference implementation across X11 WMs.
- **macOS.** Has its own single-instance + activation model that
  doesn't suffer from this class of bug (NSApplication handles it).
