# Notepatra v0.1.31 — Notepad++ canonical palette + persistent stream stats + privacy hotfix

**Released:** 2026-04-26

Three user-reported issues addressed in one ship:

1. *"keywords + actual syntax are all just shades of blue"* — palette overhauled to the Notepad++ canonical 9-hue scheme (verified against the official `stylers.model.xml` and `DarkModeDefault.xml`).
2. *"the token-rate gets hidden after the full response — keep it visible"* — streaming stats now persist on the assistant bubble forever.
3. *"the GIF on the website has my folder structure"* — three website screenshots that leaked filesystem paths replaced with clean re-captures.

## 1. Palette: Notepad++ canonical 9-hue scheme

### The bug

In v0.1.30 the syntax palette painted identifiers in an accent blue (`#001080` light, `#9CDCFE` dark). Combined with bold-blue keywords and teal type names, the result on light theme looked like "shades of blue" — keyword text, identifier text, and type names all sat near the blue end of the spectrum. Operators stayed at default text colour with no bold weight, so `+ - = ( ) { } ;` blended into identifier text instead of standing out as syntax.

### The fix

Three changes that together restore clear visual hierarchy:

1. **Identifiers paint as default text colour** (black on light, sand-grey on dark). They read as "names", not as keywords. This single change kills the "all blue" effect on every C-family language.
2. **Operators paint navy bold** (`#000080` light) / **olive bold** (`#9F9D6D` dark) — distinct hue *and* distinct font weight.
3. **Secondary keywords (types) paint vivid violet `#8000FF`** (light) / **sage `#CEDF99`** (dark) — Notepad++ canonical hues, clearly NOT blue.

### The new palette

**Light theme** (paper `#FFFFFF`, text `#000000`) — direct from Notepad++ master `stylers.model.xml`:

| Token kind | Hex | Style |
|---|---|---|
| Keywords (`if`/`for`/`return`/`def`/`class`) | `#0000FF` | bold |
| Types / secondary keywords (`int`/`char`/`std::*`) | `#8000FF` | plain |
| Comments | `#008000` | italic |
| Numbers / decorators | `#FF8000` | plain / italic |
| Strings / characters | `#808080` | plain |
| Operators (`+ - = ( ) { } ;`) | `#000080` | **bold** |
| Preprocessor (`#include`/`#define`) | `#804000` | plain |
| Class / function names | `#7F0000` | plain |
| Regex literals | `#800080` | plain |
| Identifiers / default text | `#000000` | plain |

**Dark theme** (paper `#1E1E1E`, text `#DCDCCC`) — Zenburn-derived from Notepad++ master `DarkModeDefault.xml`:

| Token kind | Hex | Style |
|---|---|---|
| Keywords | `#DFC47D` warm sand | **bold** |
| Types | `#CEDF99` sage | plain |
| Comments | `#7F9F7F` sage-green | italic |
| Numbers | `#8CD0D3` cyan | plain |
| Strings | `#CC9393` rose | plain |
| Characters | `#DCA3A3` dusty rose | plain |
| Operators | `#9F9D6D` olive | **bold** |
| Preprocessor | `#FFCFAF` peach | plain |
| Class / function | `#DCDCAA` sandy yellow | plain |
| Decorators / attributes | `#93E0E3` light cyan | italic |
| Regex | `#D16969` brick | plain |
| Identifiers / default | `#DCDCCC` default | plain |

Each token kind sits on a distinct hue arc — no more "all blue shades" effect on either theme. **Bold + italic provide a second differentiation axis** on top of hue, useful for users with reduced colour perception.

### Per-language brand overrides

Pruned 14 redundant per-language overrides that just re-stated the old blue/teal pattern (TypeScript, JavaScript, Python, C/C++, C#, SQL, Bash, Batch, Perl, Lua, Pascal, Makefile, YAML, CoffeeScript). The new generic palette covers them with clearer differentiation than the old per-language teal-types overrides did.

Kept for visual identity (matches each language's home IDE / brand): Rust (rust-amber), Go (Go-cyan `#00ADD8`), Swift (Xcode-pink), Kotlin (Darcula-orange `#CC7832`), Java (IntelliJ navy / Darcula), D (red brick / coral), HTML/PHP, CSS, XML, JSON, Markdown, CMake, Ruby.

### PowerShell

Cmdlets, variables, and aliases retuned to Notepad++ canonical:
- Variables: default text colour (was identifier-blue)
- Cmdlets: violet `#8000FF` light / peach `#FFCFAF` dark
- Aliases: cyan `#0080FF` light / sage `#CEDF99` dark

## 2. Streaming stats persist after the response completes

### The bug

v0.1.30 added the live `⏱ N tok · X tok/s · Y s` label during generation, but it disappeared the moment the stream ended. The user wanted: *"keep it visible after the full response too"*.

### The fix

`AIPanel::endAssistantBubble` now captures the final streaming counts (`finalTokens`, `finalElapsedMs`) before tearing down the live label, then seeds them onto the new `ChatMessage` that gets pushed into chat history. `aiAddAssistantCard` (the function that builds every assistant bubble) renders the same `⏱ N tok · X tok/s · Y s` line below the model-name header on every assistant card — so the stats stay visible forever, through chat history, theme switches, transcript re-renders.

When `responseStats` arrives moments later with canonical Ollama-reported `eval_count` / `prompt_eval_count` / wall-clock, those numbers overwrite the seeded estimates and the card re-renders with the canonical values. The visual is identical, but the numbers are exact.

### Display modes

Same as the live label:
- Tokens reported, elapsed > 200 ms: `⏱ 145 tok · 23.4 tok/s · 6.3 s` (full triple)
- Tokens reported, elapsed ≤ 200 ms: `⏱ 12 tok · 0.18 s` (no tok/s — too noisy with small numbers)
- No tokens but elapsed: `⏱ 0.3 s`
- No stats at all: hidden

## 3. Privacy: website screenshot leak (HOTFIX)

### The bug

User flagged the GIF on `notepatra.org` showed their folder structure. Audit confirmed three image files leaked private filesystem paths:

| File | What leaked |
|---|---|
| `docs/screenshots/tour.gif` | `/home/<user>/Documents/notepad-linux-native` in Project Search Folder field across 13 of 15 frames; internal launch-prep filenames from the (now-untracked) `outreach/` directory; reference to `release_notes/v0.1.7.md` |
| `docs/screenshots/ai-assistant.png` | Same exact Project Search exposure |
| `docs/screenshots/editor-dark.png` | Recent Files panel exposed paths to a separate personal project's `.env.local` file |

These had been live on `notepatra.org` for several days. The `outreach/` directory had been untracked weeks ago for privacy, but those filenames remained burned into the GIF.

### The fix

- All three leaky files removed from the repo (`git rm`).
- Replaced with two clean re-captures: `welcome-clean.png` (Welcome tab without recent files visible) and `editor-code.png` (pure C++ source with no path chrome).
- Removed the "See it in action" GIF section from `index.html` until a clean re-capture is ready.
- Updated captions on the showcase stills to match the new images.

Once v0.1.31 lands on `main`, GitHub Pages rebuilds and the leaky URLs return 404.

## Installation

### Linux (tar.gz)

```bash
wget https://github.com/singhpratech/notepatra/releases/download/v0.1.31/notepatra-linux-x64.tar.gz
tar xzf notepatra-linux-x64.tar.gz
./notepatra
```

### macOS (DMG)

```bash
curl -fsSL https://github.com/singhpratech/notepatra/releases/download/v0.1.31/notepatra-macos-arm64.dmg -o ~/Downloads/notepatra-0.1.31.dmg
```

- **MSI** — `notepatra-0.1.31.msi`
