Project Search (Ctrl+Shift+G) NEW

Rust-Powered Core

Safe auto-update NEW

Click Download in the in-app "update available" dialog and the right artifact for your OS + architecture is fetched, SHA-256 verified against the release's SHA256SUMS, and handed to the native installer (MSI on Windows, DMG in Finder on macOS, file manager on Linux). Your current install is never touched by the updater — the OS installer does the swap under its own transactional rollback. Checksum mismatch, cancelled download, network drop, disk full — any failure leaves the running app exactly as it was.

🧨 Tool-call JSON parse-error surfacing
  • When the model emits malformed JSON in tool-call arguments (very common when the args contain unescaped quotes from the broken JSON the user is asking it to fix), both the Ollama path and the OpenAI-compat SSE path now surface a structured error_kind: malformed_args tool result back to the model — instead of silently passing empty args (which used to surface as confusing errors like "hunks array is empty").
  • The model receives "Tool-call arguments JSON failed to parse: <error>. Re-emit the call with valid JSON." plus a 240-char raw-args preview, so it self-corrects on the next turn. The 25-call hard cap still ticks, so a model stuck in a malformed loop eventually halts.

2026-04-27 · Coding Mode write tools + persistent chat history + visible close button · Linux · macOS · Windows
🤖 Coding Mode can finally write code (3 new agentic tools)
  • write_file(path, content, mode?) — creates or overwrites text files; modes overwrite (default) / create (fails if exists) / append. Auto-creates parent directories inside the workspace; refuses to write outside it; refuses paths matching the credential deny-list (.ssh, *.pem, /etc/passwd, etc.). After writing, the file auto-opens in a tab — or the buffer reloads silently if it's already open.
  • search(pattern, path?, regex?, glob?, case_sensitive?, max_matches?) — pattern hunt across the workspace. Literal substring or regex. Glob filter (e.g. *.py). Capped at 200 matches. Same heavy-dir skip-list as the file explorer.
  • apply_diff(path, hunks) — surgical line-level edits. Each hunk has old_start_line + old_lines (expected current text) + new_lines. Atomic two-phase apply: validates ALL hunks against the live file first → if any drifted, return error_kind: conflict and nothing is written. Otherwise hunks apply in reverse-line-order so earlier indices stay stable. Write goes through .tmp + std::rename so a kill-9 mid-write leaves either old or new — never half-baked.
  • The user reported they expected "create me a Python file" to actually create a .py file — and it did nothing. v0.1.35 shipped agentic tool-calling but only with the read side (read_file, list_dir); v0.1.39 closes that gap.
💾 Persistent chat history (per-workspace)
  • Conversations now survive app restart. Stored at ~/.config/notepatra/chat-history/<sha1-of-workspace>.json. One file per workspace; switching workspaces swaps in the right history.
  • Saves debounced 2 s, capped at 1 MB per workspace (oldest messages roll off the front when full). Reset deletes the on-disk file. Atomic write via .tmp + rename.
🎨 AI dock close button now visibly red
  • The X close button on the AI Assistant header was tone-on-tone against the chrome on every theme — invisible at rest, only showing on hover. Replaced with theme-independent red: #E81123 (Windows-canonical close-button red, UWP/Fluent) at rest, red bg + white X on hover.

🛡 Path safety extended for writes (resolveSafeWritePath)
  • The three-layer safety from v0.1.35 (workspace anchor + canonicalize + hardcoded deny-list) still holds. New helper for write-side: target may not exist yet, but the lowest existing ancestor's canonical path must be inside the workspace; only THEN is mkpath called for the rest. Hardcoded deny-list applies to the candidate target, so creating ~/.ssh/foo via a mkpath chain is still refused.

🪟 Windows: After upgrading from v0.1.23 → v0.1.24, my "Open with" menu still shows the old garbled name Notepatra â€" native code editor. How do I fix it?

This is a Windows shell-cache issue, not a Notepatra bug. Windows MuiCache permanently stores the FileDescription string the first time it reads an executable's VERSIONINFO resource — and never re-reads it on upgrade. The new v0.1.24 binary embeds clean ASCII (Notepatra native code editor for the AI era), but Windows keeps showing the cached mojibake from your previous v0.1.23 install. The fix is a one-time cache wipe that takes about 5 seconds. Tested and confirmed working on Windows 11.

Open PowerShell (no admin needed — HKCU only) and paste this whole block:

# 1. Wipe Notepatra's stale entries from MuiCache (the cache that has the â€" text)
$mui = "HKCU:\Software\Classes\Local Settings\Software\Microsoft\Windows\Shell\MuiCache"
Get-Item $mui | Select-Object -ExpandProperty Property | Where-Object { $_ -match "notepatra" } | ForEach-Object {
    Remove-ItemProperty -Path $mui -Name $_ -Force
    Write-Host "Cleared MuiCache: $_" -ForegroundColor Green
}

# 2. Wipe stale "Open with" associations pointing to old notepatra.exe paths
Remove-Item "HKCU:\Software\Classes\Applications\notepatra.exe" -Recurse -Force -ErrorAction SilentlyContinue
$exts = @(".txt",".log",".md",".json",".py",".cpp",".js",".html",".css",".xml",".sql",".sh",".yml",".yaml",".ini",".conf",".csv",".rs",".go",".java",".rb",".php",".c",".h",".hpp",".tsx",".ts",".jsx")
foreach ($ext in $exts) {
    Remove-Item "HKCU:\Software\Microsoft\Windows\CurrentVersion\Explorer\FileExts\$ext\OpenWithList" -Recurse -Force -ErrorAction SilentlyContinue
    Remove-Item "HKCU:\Software\Microsoft\Windows\CurrentVersion\Explorer\FileExts\$ext\OpenWithProgids" -Recurse -Force -ErrorAction SilentlyContinue
}
Write-Host "Cleared OpenWithList for $($exts.Count) extensions" -ForegroundColor Green

# 3. Force shell to rebuild association cache
ie4uinit.exe -show
ie4uinit.exe -ClearIconCache
Write-Host "Rebuilt shell cache" -ForegroundColor Green

# 4. Restart Explorer (drops in-memory cache)
Stop-Process -Name explorer -Force
Start-Process explorer
Write-Host "Restarted Explorer — right-click any file now to verify" -ForegroundColor Cyan

What it does — line by line:

  1. MuiCache wipe — clears the per-user cache where Windows stores FileDescription strings shown in "Open with" / File Properties → Details. This is the cache holding the â€" mojibake.
  2. Per-extension cache wipe — removes the OpenWithList + OpenWithProgids entries Windows keeps for 28 common file types. Forces Windows to re-query the .exe's actual VERSIONINFO next time you open the menu.
  3. ie4uinit.exe -show + -ClearIconCache — built-in Windows tool that rebuilds the shell association + icon caches. The red ❌ overlay on the Notepatra icon disappears here.
  4. Restart Explorer — drops the in-memory copy of the cache (the fourth and final layer). Without this, the menu can stay stale until you log out / reboot.

Verify it worked: right-click any .txt or .json file → Open with → the Notepatra entry should now read Notepatra native code editor for the AI era with a clean icon. If you still see the old text, log out and back in (forces every cache layer to flush). New v0.1.24 installs on a clean machine never see this — it only affects upgrades from v0.1.23 or earlier.

How is Notepatra different from Notepad++ or VS Code?

Notepatra is its own native code editor — written from scratch in C++ and Rust, not a port or a clone. Runs on Linux, macOS Apple Silicon, and Windows from one codebase. Compared to Notepad++: truly cross-platform, local-first AI is built in, Rust-powered search and formatters. Compared to VS Code: a much smaller install footprint (5–85 MB depending on platform vs 300+ MB for VS Code), no Electron runtime, no telemetry, no account required. Credit to Don Ho for proving a code editor can be small, fast, and free.

Is it really free? What's the catch?

No catch. GPL-3.0, no telemetry, no analytics, no API key, no enterprise tier, no subscription. Source on GitHub. The "catch" is that it's a one-person open-source project — no SLA, no warranty, no support contract. See the disclaimer in the footer.

How big is it compared to VS Code?

The bare executable is ~4 MB stripped across every platform. Latest download sizes: 2.8 MB Linux x64 tar.gz · 2.6 MB Linux ARM64 tar.gz · 25.5 MB macOS DMG · 43.5 MB Windows MSI / 36.3 MB NSIS / 41.7 MB portable zip. Installed on Windows the on-disk footprint grows to ~75-85 MB because the MSI extracts bundled Qt5 + QScintilla DLLs out of the compressed payload — normal for every Qt-based installer. Linux is small because Qt is a system package; macOS and Windows bundle Qt + QScintilla DLLs for portability. VS Code is 300+ MB regardless. Notepatra installs at 5–85 MB depending on platform.

Does my code go to the cloud?

No. Notepatra is local-first. The AI runs on your machine via Ollama (which you install separately). The only outbound connections are: localhost Ollama, git push/pull when you click them, and the REST client when you send a request. Verifiable with strace.

What languages does it highlight?

100+ file types via 48 language lexers — Python, JavaScript, TypeScript, C, C++, C#, Java, Rust, Go, HTML, CSS, SQL (T-SQL/PL/SQL/MySQL/PostgreSQL/SQLite), JSON, YAML, Markdown, Bash, Ruby, Perl, Lua, Fortran, Verilog, VHDL, MATLAB, LaTeX, Pascal, CMake, Makefile, and more.

How do I verify a download is genuine?

Every release ships with SHA-256 checksums, cosign signatures (Sigstore + Rekor), and SLSA build provenance. The install scripts verify SHA-256 automatically and refuse to install on mismatch. Full guide in SECURITY.md.

Will it open big files?

Yes — up to 2 GB. The Rust core uses memory-mapped I/O (mmap2), so opening a 2 GB log file doesn't load the whole file into RAM (pages are faulted in lazily as you scroll). Files larger than 50 MB automatically disable syntax highlighting and auto-complete to keep things snappy.

Can I write plugins?

Yes. Drop a .so/.dylib/.dll in ~/.config/notepatra/plugins/. The plugin C API is two functions: notepatra_plugin_name() and notepatra_plugin_run(text, len). Example in the README.
