Notepatra for Enterprise

A short, plain-English brief for the IT, legal, or procurement reviewer evaluating whether a developer in your organization can install Notepatra. Bookmark this page, paste it into a software-acceptance request, or forward it to your OSS-license review board. Nothing on this page is legal advice — your legal team is.

The 30-second answer

Notepatra is a standalone end-user code editor — like Notepad++, GIMP, vim, or VS Code from a license-review perspective. It is licensed under the GNU General Public License v3.0 (GPL-3.0-or-later). Running, installing, and using Notepatra inside your organization does not require you to release any of your source code, does not "infect" the files your developers edit with it, does not phone home, and does not require an account or commercial contract. Notepad++ — same license family — is installed on millions of corporate workstations worldwide. Notepatra is no different.

What GPL-3.0 actually means for your organization

The corporate fear of GPL is real but is almost always about a different scenario than yours. The fear is about linking GPL code into a closed-source product your company ships to customers. That's not what's happening when an employee installs Notepatra to edit files.

Common concernDoes it apply when using Notepatra?
"If we install GPL software, we'll have to release our source code." No. The GPL is triggered only when you distribute the GPL software or a derivative of it. Running it doesn't trigger anything. Same as running gcc, vim, or Linux itself.
"If our developers edit our proprietary source code in Notepatra, will that code become GPL?" No. The editor and the file you edit are separate works. Editing a file in a GPL editor does not create a derivative work of the editor. Same principle as: writing a document in LibreOffice doesn't make the document fall under LibreOffice's license.
"What if a developer accidentally pastes Notepatra source into our codebase?" That would be a normal copyright concern, the same as if they pasted code from Stack Overflow or any other source. The license discipline you apply to all third-party code applies here too.
"What if we want to modify Notepatra for internal use?" Allowed. The GPL only requires source disclosure if you distribute your modified version (e.g. ship binaries to customers or a wider audience). Internal use, even modified, does not require disclosure.
"What about AGPL? Some of our software policies block AGPL." Notepatra is not AGPL. It's GPL-3.0. The AGPL network clause does not apply.
"Patent retaliation clause?" GPL-3.0 includes a clause that ends your patent rights from contributors if you sue someone for patent infringement based on the software. It applies to contributors — the people writing the code — not to end-users.
"Anti-tivoization clause?" GPL-3.0 prevents distributing hardware that runs the GPL software but blocks the user from modifying it. Doesn't apply when a developer installs Notepatra on their own workstation.
Bottom line: the GPL "copyleft" obligations attach to whoever distributes the software. As an end-user organization that installs and runs Notepatra, you have no source-disclosure obligation, no license-grant obligation, and no patent-grant obligation.

Supply chain & provenance

Every Notepatra release ships with cryptographic provenance suitable for an internal SBOM or software-acceptance package.

SHA-256 checksums

Every release page contains a SHA256SUMS file listing every binary artifact. Your IT team can verify the bytes match what was published:

curl -sL https://github.com/singhpratech/notepatra/releases/latest/download/SHA256SUMS \
  | sha256sum --check --ignore-missing

cosign signatures (Sigstore + Rekor)

Every artifact is keylessly signed via Sigstore cosign. The signature is recorded in the public Rekor transparency log, so any tampering with the release page is detectable from outside. Verify a download:

cosign verify-blob \
  --certificate notepatra-linux-x64.tar.gz.pem \
  --certificate-identity-regexp "^https://github.com/singhpratech/notepatra" \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  --signature notepatra-linux-x64.tar.gz.sig \
  notepatra-linux-x64.tar.gz

SLSA build provenance

GitHub Actions emits SLSA Level 3 provenance attestations alongside each release. The attestation cryptographically ties each binary back to a specific commit SHA and workflow run, so your security team can independently confirm that a release was built from the exact public source in github.com/singhpratech/notepatra and not from an attacker-controlled fork.

Reproducible from source

Every commit is public. Tags are immutable. There is no closed-source binary blob anywhere in the build pipeline. A determined security team can clone the repo at a given tag, run the documented build, and reproduce a functionally equivalent binary.

FAQ — questions procurement actually asks

Will GPL-3.0 obligate us to release our internal tools or our code?

No. GPL obligations attach to distribution of the GPL software or its derivatives. Running, installing, and using Notepatra does not distribute anything and does not create a derivative work.

What if our developer modifies Notepatra to add a feature we use internally?

Allowed. As long as the modified version is not distributed outside your organization, no source-disclosure obligation arises. (If you do distribute it — e.g. to customers, contractors outside your org, or the public — you must offer the source under GPL-3.0.)

Does Notepatra connect to any external service by default?

No. The editor boots offline. Update-check is manual. AI features default to a local backend; cloud backends are opt-in and require the user to enter credentials.

Is there a commercial / paid version that drops the copyleft requirement?

Not today. Notepatra is GPL-3.0 across the board. If your situation requires a permissive-license version — e.g. you want to embed Notepatra into a closed-source product you ship to customers — open an issue or reach out via @singhpratech on GitHub and we can discuss.

Will Notepatra add telemetry or "phone home" in a future version?

No. "No telemetry, no analytics, no mandatory account" is part of the project's stated commitment. The website's FAQ and every release page repeats it. If that ever changed it would be a major version event documented in the changelog — not a silent flip.

Where do I report a security issue?

See SECURITY.md in the repo for the disclosure policy.

Who is responsible for support / liability?

Notepatra is provided as-is under the GPL-3.0 disclaimer of warranty (sections 15 and 16). There is no SLA, no support contract, and no warranty. Your organization assumes risk the same way it does for every other GPL tool it uses (gcc, gdb, git, vim, Linux kernel).

Is the binary I download the same as what's in the source repo?

Yes, and you can cryptographically verify it. Every release is built by GitHub Actions from a tagged commit in the public repo. The SLSA provenance attestation and cosign signature both bind the binary to that commit. A reproducible build pass is on the roadmap and is partially in place today.

Can we host an internal mirror of Notepatra binaries?

Yes — GPL-3.0 explicitly allows this. You may redistribute the binaries inside your organization (or publicly) as long as you also offer the source code under GPL-3.0. Pointing users at github.com/singhpratech/notepatra satisfies the source-availability requirement.

Can we run Notepatra in an air-gapped environment?

Yes. The Lite flavor is fully self-contained (~10 MB on disk). The Full flavor bundles the chart-rendering JS as a Qt resource and works offline. AI features can be configured for a local Ollama or llama.cpp running on the air-gapped machine — no external network required.
